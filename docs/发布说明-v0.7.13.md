# v0.7.13 —— 多路径连接（内网 / 公网 / DDNS）与失败自诊断

> 发布日期：2026-10-27
> 上一版：[v0.7.12](发布说明-v0.7.12.md)（「网络断开」误判修复与日志轮转）
>
> **新功能版**：一条 NAS 连接现在可以带**多条访问路径** —— 家里内网、公网 DDNS、
> 备用域名都写进去，客户端按顺序自动挑可达的那条；一条挂了自动切下一条，
> **不用重启 daemon、不丢会话**；回到内网后自动切回。连不上时
> `qxync routes --probe` 逐条告诉你每条路径的 DNS、内网/公网分类、延迟和失败原因。
>
> 无数据格式变更：老 link 文件、老 `sync.db` 原样可用；不配 `endpoints` 时行为与
> v0.7.12 一字不差；IPC 只加字段/方法，不 bump 版本。

## 一句话

```text
升级 + 重启 daemon 后：
  → 一条连接可配多条访问路径：在家自动走 LAN、出门自动走 DDNS，按顺序选第一条可达的
  → 当前路径失败立刻切下一条（冷却 30s 起、5 分钟封顶）；优先路径恢复后连续 2 次
    探测成功才切回，LAN/WAN 不来回抖
  → 连不上时 qxync routes --probe 逐条列出 DNS（A/AAAA）、内网/公网/运营商 NAT、
    延迟、冷却与最近错误；daemon 没在跑也能用（自动直连探测）
  → DDNS 换 IP 后自动重建连接池重新解析；路径指到另一台 NAS 会被 UID 指纹拦下
  → 旧配置零迁移：endpoints 留空 = 和以前一样只走主地址
```

## 一、起因：一个地址，坏了就只能手动改

原来的 `LinkConfig` 只有一组 `host` / `port` / `https`。现实中同一台 NAS 的访问入口
经常不止一个：

| 场景 | 原来的问题 |
|---|---|
| 家里内网 `192.168.1.10` + 公网 DDNS 域名 | 在家想走 LAN（快、不绕公网），出门只能手动改成 DDNS，回来再改回去 |
| DDNS 域名 | 解析出的 IP 会变；连接池里通往旧 IP 的死连接会被一直复用 |
| 一条路径暂时不通（NAT 没打洞、路由器重启、运营商封锁） | 界面只说「网络错误」，看不出是哪条路径、为什么不通 |
| 想加一条备用域名 | 只能换主地址，而主地址同时是凭据锚点和本地缓存目录名 —— 一改像换了台 NAS |

用户原话：

> 「做一下多路径，可能从内网或者公网访问过来，然后有些时候域名可能是 ddns 的，
> 这个也要考虑到，连接不到的时候都检测一下多路径的问题看着来。」

## 二、怎么配

### 2.1 GUI（推荐）

**设置 → 连接 → 额外访问路径**（textarea，每行一条）：

```text
家里 LAN   = http://192.168.1.10:9834
公网 DDNS  = https://qnap.example.com:9834
```

保存后 link 文件里的 `endpoints` 数组就是这两条。GUI 会提示：主地址是缓存 / 凭据的
锚点，日常不要改它；要换 NAS 请新建连接。

### 2.2 link 文件

`~/.config/qxync/links/<id>.json`：

```json
{
  "id": "default",
  "host": "qnap.example.com",
  "port": 9834,
  "https": true,
  "insecure": true,
  "user": "test1",
  "endpoints": [
    { "label": "家里 LAN", "host": "192.168.1.10", "port": 9834 },
    { "label": "备用 DDNS", "host": "nas2.example.com", "https": true, "port": 9834 }
  ],
  "local_namespace": "qnap.example.com"
}
```

规则：

* `endpoints` 是**额外路径**，按书写顺序**先于**主地址尝试；主地址自动追加到最后兜底；
* 列表为空 → 只有主地址，行为与 v0.7.12 完全一致（旧配置零迁移）；
* 显式把主地址写进列表 → 尊重它出现的位置（想「LAN 主、DDNS 备」就把它写第一行）；
* `port` / `https` 省略时**继承主地址**（不猜 8080/443，避免把 `http://` 悄悄指到错误端口）；
* 同 `(协议, 主机, 端口)` 去重，保留第一次出现；最多 **8 条**（含主地址）；
* `local_namespace`：第一次保存多路径时冻结的本地命名空间（`sync.db` / 缓存目录名）。
  之后即使主地址改了，本地状态目录也不跟着变。

### 2.3 文本行语法（GUI / CLI 共用）

```text
[标签 = ][http:// | https://] 主机 [:端口]
```

* 例：`家里 LAN = 192.168.1.10:9834`、`公网 DDNS = https://qnap.example.com:9834/`；
* 空行与 `#` 开头的行是注释；允许尾部 `/`，拒绝路径 / 查询串 / 片段；
* IPv6 带端口必须写 `[fe80::1]:9834`；裸 IPv6 视为无端口；
* 坏行**带行号报错**，不静默丢弃。

## 三、运行期怎么选路

`qxync-client::route::Router` 是进程内共享的路由表（daemon 的主客户端、引擎客户端、
每个挂载点共用同一个 `Arc`）。

| 规则 | 行为 |
|---|---|
| 顺序 | 配置顺序 = 优先级；额外路径在前、主地址兜底 |
| 初始选路 | 登录前并行探测一次，选顺序上第一条可达的 |
| 失败切路 | 当前路径失败 → 标记失败并**立即**切到顺序上下一条（不在冷却期的） |
| 并发失败 | 只有「失败的那条仍是 active」才切路；多线程同时失败不会一次跳两条 |
| 冷却 | `30s × 2^(连续失败-1)`，上限 5 分钟；成功即清零 |
| 全部冷却 | 选「冷却最早到期」的那条，不把自己锁死 |
| 切回优先路径 | 在线巡检发现更靠前的路径**连续 2 次**探测成功才切回（防 LAN/WAN 抖动） |
| 巡检间隔 | 默认 60s（`QXNYC_ROUTE_PROBE_SECS` 可调，`0` 关闭） |
| 探测超时 | 单条路径 3s 上限（探测专用 client 连接 2s / 总 3s） |
| 业务连接超时 | 多路径时 8s（旧单路径仍是 20s）—— 一条被黑洞的路径不该拖 20 秒 |

## 四、跨路径重试与 DDNS

所有请求的 URL 都来自当前 active 路径。不同操作的重试策略：

| 操作 | 跨路径重试 | 说明 |
|---|---|---|
| 登录（含 2SV） | 是，每路径一次 | 只对 `Transport` 重试；`Auth` / 业务 status 立即停（换路也没用） |
| 幂等 GET（列目录 / stat / max_log / settime / probe） | 是，每路径一次 | 保留原有「对端提前关连接 / 反代 502」的同路径抖动重试 |
| 区间下载 / 整文件下载 | 是 | 整文件下载失败删 `.qxync-part` 从头来（不拼接残留分片） |
| `upload_bytes` / `upload_file` | 是 | 每次重开文件 / 克隆字节；服务端 `overwrite=1`，重放安全 |
| `upload_stream_sized` | 否 | 调用方给的 reader 不能重放；失败交给上传队列下一次尝试（届时已在新路径） |
| mkdir / rename / move / delete | 仅 `is_connect()` | 请求确定没发出去才重试，避免重复建目录 / 重复删除 |
| logout | 否 | 尽力而为 |

**DDNS 连接池刷新**：所有路径都失败后，如果目标是域名（不是 IP 字面量），重建一次
`reqwest::Client`（丢弃旧 DNS / 连接池）再试一次。原因：连接池按 `host:port` 复用，
DDNS 换 IP 后池里通往旧 IP 的死连接会被一直取出 —— 不换 client 就永远解析不到新地址。
每次操作最多刷新一次。

## 五、连不上时怎么查

### 5.1 CLI

```bash
qxync routes                 # 只读路由表（零网络、离线也能看）
qxync routes --probe         # 立即并行探测全部路径（DNS + HTTP，≤3s）
qxync routes --json          # 脚本/验收用
qxync status                 # 多一行「路径：N 条（当前 …；x/y 可用）」
qxync login                  # 成功时报告所用路径；失败时自动打印每条路径的现场
```

输出示例（脱敏）：

```text
多路径    : 2 条（按顺序尝试；✓ = 当前，本次已探测）
   1     家里 LAN      http://192.168.1.10:9834      192.168.1.10〔内网〕         - ms  冷却中
        └ 冷却中：27 秒后可再试
        └ 最近错误：请求超时：deadline has elapsed
   2  ✓  主地址        https://qnap.example.com:9834  203.0.113.7〔公网〕      53 ms  正常
最近切换  : 12 秒前 从 192.168.1.10:9834 到 qnap.example.com:9834（原因 failure）
```

**daemon 没在跑 / 老 daemon 不认识 `routes`** → 自动回落**直连探测**（不需要登录）。
这是「连不上时先查多路径」在没有 daemon 的机器上仍然可用的原因。

错误文案仍遵守 M30：不含完整 URL / sid / 远端路径；路径诊断里只出现 `host:port`
与 DNS 结果。

### 5.2 GUI

* 设置 → 连接：新增「额外访问路径」textarea；
* 诊断 → 新增「多路径」子页：路径表 + 刷新 + 「检测全部路径」+ 上次切换原因；
* `QXNYC_GUI_TAB=diag:routes` 可直达。

### 5.3 IPC

* `Request::Routes { probe }` → `RoutesData`（`active` / `endpoints[]` / `switches` /
  `last_switch` / `probed`）；
* `StatusData.routes: Option<RouteSummary>`（`active` / `healthy` / `total` / `last_switch`）；
  老 daemon 没有该字段 → 界面不显示路径行；
* `LinkInfo.endpoints: Vec<EndpointInfo>`：GUI 用它判断「路径改了要不要重启 daemon」；
* **不 bump `IPC_VERSION`**：只加字段/方法，老客户端忽略新字段。

## 六、数据安全：身份守卫与命名空间

多路径的前提是「所有路径指向同一台 NAS」。如果另一台 NAS 的地址被误加进路径列表，
客户端会正常登录、正常同步 —— 然后把 A 的改动写进 B。所以：

* 第一次成功登录时把 `qbox_get_nas_uid` 的 `UID`（拿不到则 `MAC0`）记到
  `<state>/link-identity/<id>.json`（**运行期事实**，不进配置目录）；
* 之后每次登录（含切路后的重登）比对；不一致 → 该路径标记 `blocked` 并换下一条重登；
  全部不一致才报错（错误信息里给出期望/实际 UID，并提示「换 NAS 请新建连接」）；
* `subject`（主地址 `host:port`）变了 = 用户确实换了 NAS → 视为新设备覆盖；
* 接口拿不到 UID / MAC（老固件、字段缺失）→ 跳过校验并 WARN，**不误杀**；
* 指纹文件读写失败只告警，不阻塞登录；`blocked` 的路径不会被探测「复活」。

`local_namespace` 则保证「改主地址 ≠ 换一份同步状态」：缓存/状态目录由它派生，
不再随 `host` 变化而拆散。

## 八、升级

```bash
# 1) 换二进制（qxync / qxyncd / qxync-gui 都要换：GUI 的路径表单与诊断页在新版里）
sudo install -m755 target/release/qxync target/release/qxyncd target/release/qxync-gui /usr/bin/

# 2) 重启 daemon（正在跑的进程不会自己变）
systemctl --user restart qxyncd
# 没有 systemd 时：qxync daemon stop && qxync daemon start

# 3) 想试多路径：GUI 设置→连接填「额外访问路径」，或直接编辑 link 文件的 endpoints
# 4) 连不上时先查多路径（不需要 daemon）
qxync routes --probe
```

不需要迁移任何文件：老 link 文件没有 `endpoints` 就走单地址；新字段空值不落盘。

## 已知限制（如实记）

* **改路径配置仍需重启 daemon 才生效**（与现在改 host 一致）；GUI「保存并登录」会自动
  重启。运行期切路径不需要重启。
* **代理仍作用于全部路径（含 LAN）**：手动代理可能让内网探测失真，建议 `Auto` +
  `NO_PROXY`。每路径独立代理 / 独立 TLS 校验**有意不做**（见 M40 文档 §7）。
* **系统 DNS 缓存**（systemd-resolved / nscd）按 TTL 缓存，我们只能做到「失败后重建
  连接重新解析」，无法绕过缓存。
* **DDNS 指向内网 / 运营商 NAT** 只在诊断里标出并提示，不自动禁用该路径。
* **不做**：链路聚合 / 负载均衡 / 同时多路传一个文件（始终单活路径）；自动发现局域网
  地址；公网 IP 查询 / DDNS 服务商 API 更新。
* 真机「登录 + 主路径死掉自动切下一条」**没有用真实账号演练**（本次没有把口令带进
  会话记录）；同一代码路径由假 NAS 的隔离 e2e 覆盖，真机只验证了无需登录的探测面。
* `cargo clippy` 在发版环境未安装，未运行（与 v0.7.12 相同）。
* `xtask/tests/gui-matrix.sh` 的 TABS 已加 `diag:routes`，但**整套矩阵未重跑**；
  本版只跑了单窗口 GUI 验证。

## 一、修复：同步错误红字常驻 + 每轮重登（M44）

用户原话：

> 「老是显示报错，我也不知道错哪，显示了也解决不了，显示他干啥。。。咋处理一下，烦死了」

### 根因

NAS 上一棵目录树被移走后（`2026/29-四川赛/.lo` 整体搬进 `.build-tmp`），同步状态库里
留下 **80 行旧路径**（30 个目录 + 50 个文件）。此后每轮对账：

```text
远端列举 → status=5（路径不存在）
stat 再确认 → 还是 status=5
→ 数据安全规则：存在性未知 → 本轮不判定该目录及其内容
→ 这批目录永远不会回来 → 每轮都判不掉
→ 每轮 3 条样本进 errors → GUI 首页红字常驻
同时 status=5 被当成「会话失效」→ 每轮「立即重登」（实测一天 163 次）
```

红字本身只是症状，真正的问题是**程序把「目录没了」和「会话坏了」混为一谈**，既不
处理也不放过。

### 修法（三条）

| # | 修法 | 边界 |
|---|---|---|
| ① | **幽灵目录自动清理**：远端列不出来 + 本地这棵子树没有任何节点 + 父目录清单里也没有它 → 清掉 baseline 子树与清单快照（**只清状态记录，不动任何文件**） | 本地还有内容 / 父清单里看得见它（= 权限问题）一律**不清**；挂载视图整体为空（本地状态没接上）时**一律不清**（安全闸） |
| ② | 清不掉的目录降级为**说明行**：带路径样例 + 总数，黄色显示，不再进 `errors` / `last_error` / journal 错误列表 | 日志从每轮 3 条 WARN 压到「首次 + 每 10 分钟一条」 |
| ③ | `status=4/5` 只有**本轮一个目录都没列成**时才算会话失效（延迟到轮末判定） | 真会话失效照旧重登，不再每轮误判 |

### 升级后怎么确认

```bash
# 首轮对账日志应出现（1~3 分钟内）：
grep "清理失效目录" ~/.local/state/qxync/log/qxyncd.log.$(date +%F)
# 对账：清理失效目录 …/2026/29-四川赛/.lo（远端列不出来、本地也没有内容）→ 清掉 80 条同步状态记录，不动任何文件

qxync sync --json   # last_error 应为 null；note 里最多一条「清理了 80 条失效的同步记录」
```

之后 GUI 首页红字消失，`轮询遇会话失效` 不再刷。

## 二、修复：直连挂载的改名/删除与 NAS 分叉（M46 §6.5，产品 bug）

**症状**：用 CLI `qxync mount`（不经 daemon）直连挂载后，在挂载点里 `mv` / `rm`，
NAS 上**旧名字原样留着、新名字从未出现**——本地与远端从此分叉。

**根因**：上传成功的回调（success hook）只在 daemon 挂载时接线；直连模式下
`remote_known` 永远停在 `false`，改名被判成「远端没有老副本」走纯本地分支。

**修法**：`with_upload_queue` 装默认 success hook（清单条目刷签名 +
`remote_known=true` + 清脏标记）；daemon 挂载时用完整 hook 覆盖，daemon 行为
**一字不变**。

**升级须知**：此前用直连挂载做过改名/删除的，NAS 上可能留着旧名字的幽灵文件
（内容没丢，只是名字对不上）。升级后**新操作**不会再分叉；旧分叉不会自动修，
发现后手动对一下即可。daemon 挂载（GUI / `qxync daemon start` 后的挂载）从来
不受此 bug 影响。

## 三、修复：GUI 搜索结果路径看不清（M43.1）

用户原话：

> 「搜索出来的路径会追加好长一段……把文件名和路径分两行……路径过长的话默认显示后面，前面隐藏」

结果表路径列由单行尾省略改成**两行**：第一行文件名（尾省略），第二行父目录
（11px 暗色）；目录过长时默认**显示尾部、隐藏开头**（按真实像素宽度从左侧裁
字符，前面补「…」），完整路径仍在 `title` 悬浮提示里；窗口变宽/变窄后按新列宽
重裁。列头同步改成「文件 / 路径」。只动 GUI 排版，其余零改动。

## 四、变更：端到端验收合并成一个入口（M45/M46，开发者向）

用户原话：

> 「看看所有的 e2e 能不能化简一下或者合并一下，现在发布前的测试提交太久了」

审计发现单跑都不慢（隔离套件 1～16s），慢在「怎么跑」：19 个脚本 + 3 个 node
套件靠人肉串行，`gui-matrix` 内部还重复跑 4 个子套件。更糟的是其中 8 处
`pkill -x qxyncd`——**跑一次验收会把桌面上正在同步的守护和托盘一起杀掉**
（2026-10-29 真事故，本轮验证时复现过两次）。

```bash
bash xtask/tests/e2e.sh                 # gate（默认）：单测 + fmt + 隔离 e2e，38s
bash xtask/tests/e2e.sh --tier fast     # 并行隔离套件，18s
bash xtask/tests/e2e.sh --tier gui      # 改了 ui/ 再跑
bash xtask/tests/e2e.sh --tier fuse     # 改了 FUSE/水合再跑（需 /dev/fuse）
bash xtask/tests/e2e.sh --tier nas      # 改了同步/schema/任务再跑（写真机 NAS）
bash xtask/tests/e2e.sh --tier all      # 全部；缺环境自动 SKIP 并说明缺什么
bash xtask/tests/e2e.sh --list          # 套件注册表
```

- 24 个套件注册表 + 五档 + 能力探测 + fast 档并行 + 去重 + 汇总表 + 失败贴日志尾部；
- **守护保护**：套件只停自己 socket 上的 daemon、只收自己窗口；跑完发现你的
  daemon 被带走 → 退出码 3 并点名疑似加害者；
- 超时杀整棵进程树（不再留孤儿脚本继续动状态）；
- 真机套件默认只挂夹具目录（`QXNYC_REMOTE_ROOT` 可覆盖），`m83` 619s → 16s、
  `m84` 30 分钟超时 → 198s；
- CI 的 7 个 e2e/node step 合并成 1 个。

修完后的全档实跑：**gate 11/0、gui-matrix 160/0、m82 40/0、m83 27/0、m84 99/0、
m5 30/0、m7 60/0、fuse 78/0**，全程维护者桌面 daemon pid 不变。

## 六、升级

```bash
# 1) 换二进制（qxync / qxyncd / qxync-gui 一起换，保持版本一致）
sudo install -m755 target/release/qxync target/release/qxyncd target/release/qxync-gui /usr/bin/

# 2) 重启 daemon（本版有同步引擎行为变化，daemon 需要重启才生效）
qxync daemon stop && qxync daemon start
# 或：systemctl --user restart qxyncd

# 3) GUI 退出重开（托盘右键退出再启动）
```

升级须知：

* **不需要迁移任何文件**：无数据格式变更、无 IPC 变更、无配置变更；`sync.db` /
  缓存 / link 文件原样可用。
* **首轮日志会出现「清理失效目录」**：这是 M44 在清幽灵目录（只清状态记录，
  不动任何文件），属预期行为。
* **直连挂载的旧分叉不会自动修**：见第二节「升级须知」。
* **AUR 包**：`packaging/arch/` 的 `sha256sums` 仍需 `updpkgsums` 后再推 AUR
  （既定流程，与历版相同）。

## 已知限制（如实记）

* **M44 只清「远端列不出来」的幽灵**：远端列得出来但 stat 失败（权限边界）的目录
  仍不判定、只进说明行——这是数据安全规则，不是缺陷。
* **`cargo clippy` 未运行**：发版环境未安装 `cargo-clippy`（与 v0.7.12 起相同）。
* **e2e `nas` 档的 `m20/m21/m40-real-nas`**：需要 `QXNYC_REAL_HOST/USER/PASSWORD`
  环境变量，本机未配，入口如实 SKIP。
* **`qs_fixture.py` 不支持 2SV**：真机夹具用 TOTP 包装脚本绕过（M46 文档 §7 待办）。
* **测试连接是主账号**：`.local-run/config` 里的测试连接当前指向主账号
  （非文档中的 test1），真机档会拿它登录（M46 文档 §7 已记，建议换测试账号）。

# M19 删除相关数据：任务 / 连接 / 本机全部

> 起因：用户反馈「**再添加一个删除所有相关数据的功能**」。
>
> 结论：新增「删除相关数据（purge）」功能，三个作用域 —— **任务**、**连接**、**本机全部**。
> 任何作用域都**不动 NAS 数据、不动挂载点里的文件**；默认先给计划（会删什么、多大），
> GUI 用弹窗摊开、CLI 默认只预览，真正删除才执行。

---

## 1. 旧边界为什么需要一个出口

旧版只有两个删除动作，而且都刻意不碰数据：

| 动作 | 实现 | 留下的东西 |
|---|---|---|
| 删除任务登记 | `Task::delete()` 只删 `tasks/<id>.json` | 水合缓存、`sync/<ns>/sync.db` 里的 baseline / 日志 / 待裁决 |
| 移除连接 | `LinkConfig::delete()` 只删 link / 凭据 / peers | `sync/<ns>` / `cache/<ns>` / `upload-queue/<ns>` / 挂载记录 / 日志 / socket / pid |

「删登记 ≠ 删数据」这个边界本身是**对的**（`link_delete` 的注释里写死过「不删本地文件、
不删 NAS 数据、不动 cache/state」），但它没有**出口**：

* 缓存会一直占着磁盘，用户只能自己 `rm`；
* 重加同名任务时读到旧 baseline，第一次对账的行为「像被删过又回来」；
* 移除连接后 `~/.local/share/qxync/` 里永远留着它的一整套目录，界面里却已经看不到。

M19 就是把出口补上，并且**只补出口，不放松默认值**：不勾选时行为与旧版一字不差。

## 2. 三个作用域

| 作用域 | 删什么 | 明确不删 |
|---|---|---|
| **任务** | 任务登记；该任务的水合缓存（`<cache_dir>/<连接命名空间>`）；`baseline` / `journal` / `decisions` 里落在该 NAS 文件夹子树的**行**；该挂载点的挂载记录 | 挂载点目录与其中文件；NAS 数据；按连接共享的上传 / 删除队列；`pins`；`nodes` 身份索引 |
| **连接** | 该连接的任务登记；link / 凭据 / peers；`sync/<ns>`（含 sync.db）；`cache/<ns>`；`upload-queue/<ns>`；挂载记录；该连接的日志（`qxyncd-<id>.log*`）；socket / pid | 挂载点目录与其中文件；NAS 数据 |
| **全部** | 本机 qxync 的**配置目录 / 数据目录 / 状态目录**（连接、凭据、任务、缓存、状态库、挂载记录、日志），以及各连接的 socket / pid | 挂载点目录与其中文件；NAS 数据；系统 autostart 项（要关请到「设置 → 高级」） |

`<ns>` 是 M16 的连接命名空间：`default` → NAS 主机名，其它 → `#<id>@<主机名>`。

### 任务级为什么删 baseline 行、而不是整个 sync.db

状态库是**按连接**一份（`sync/<ns>/sync.db`），同一连接的多条任务共用它。
把整个库删掉会连别的任务的 baseline / 日志一起丢。所以任务级 purge 用
`path = root OR path LIKE 'root/%'` 精确删行（`%`/`_`/`\` 都转义：

`Store::delete_path_rows_under`），并且：

* **NAS 文件夹被本连接的另一条任务共用时不删**（`/home` 两条任务共用时，删行等于替另一条任务
  做决定）—— 计划里给警告并跳过；
* **水合缓存目录被共用时同样跳过**（老任务 / 手动改过 `cache_dir` 的才可能发生；M18 起新建任务
  默认独占一条路径）。

## 3. 五条安全设计

### 3.1 先计划、再执行

`PurgePlan` 把「要删哪些路径、各多大、多少状态库行、有哪些警告」全部先算出来，
GUI 展示给用户确认，CLI 默认只打印计划（`--yes` 才执行）。
每个条目带一个**允许根**（`PurgeItem::base`，不序列化给前端）：执行时逐项校验目标仍在
允许根内，越界项**拒绝删除并记警告**，而不是照单全收。

### 3.2 不跟随符号链接

`measure()` / `remove_path()` 都用 `symlink_metadata` 判类型：符号链接只算 1 项、0 字节，
删除时**只删链接本身**；`remove_dir_all` 也不会穿过子目录里的符号链接。
单测 `execute_does_not_follow_symlinks` 钉住了「缓存目录里有一条指向外部文件的链接，
外部文件必须还在」。

### 3.3 共享数据不猜

见 §2 末尾：NAS 文件夹 / 缓存目录被别的任务共用时，对应项不进计划（并给警告）。
宁可少删，也不替另一条任务做决定。

### 3.4 内存副本与库必须一起清

M5 起 daemon 的 `SyncState.baseline` 是**工作副本**：只删库不删内存，下一轮 `persist`
会把旧条目原样写回来。任务级 purge 由 **daemon 执行**（daemon 在跑时 CLI/GUI 一律走
`tasks{action:"purge"}` IPC）：

1. 先卸载该挂载点（`umount` 会排空上传 / 删除队列）；
2. 删文件（缓存、任务登记）+ 删库行；
3. 把内存 `baseline` 里落在该根下的条目摘掉，再 `save_all()`。

daemon 不在时（GUI 离线 / CLI 直用）由本地进程用读写句柄删库行 —— 这时也不存在
「另一个进程正在写内存副本」的问题。

### 3.5 全局必须停 daemon

`--all` / 「危险区」会先停止**所有** daemon（连接级则停目标连接），等 socket 真的消失后再删目录。
脚本 `m19-purge.sh` 专门断言「purge 之后 daemon 没有被打挂」。

## 5. 用法

### 5.1 CLI

```bash
# 预览（默认行为：不删任何东西）
qxync purge --task home

# 真的删：任务登记 + 缓存 + baseline/日志/待裁决
qxync purge --task home --yes

# 连接级：--link 选中哪条连接，就删哪条
qxync --link nas2 purge --connection --yes

# 全局（恢复出厂）：会先停掉所有 daemon
qxync purge --all --yes

# 脚本：--json 输出计划（预览）或结果（--yes）
qxync purge --task home --json
```

注意：**不带 `--yes` 一律只预览**（与 `--dry-run` 等价）。这是有意的 —— purge 不可逆，
CLI 不应该因为少打一个参数就删数据。

### 5.2 GUI

| 入口 | 弹窗 | 不勾选（默认） | 勾选 |
|---|---|---|---|
| 任务卡「**删除…**」 | 删除任务「home」？ | 只删任务登记（旧行为） | 同时删水合缓存 / 同步状态 / 日志 |
| 连接行「**移除**」 | 移除连接「nas2」？ | 停 daemon、卸载挂载点、删任务登记与连接配置 | 再加：该连接全部本地数据 |
| 设置 → 高级 → **危险区** | 删除本机所有 qxync 数据？ | ——（确认按钮禁用，必须勾选「我了解…」） | 删除全部连接 / 任务 / 缓存 / 状态 / 日志 |

三个弹窗都支持 Esc / 点遮罩取消；焦点陷阱与焦点归还原与既有弹窗一致；
计划请求失败时**中止删除**（不回落旧路径）——「不知道会删什么就不删」。

## 7. 取舍与边界

1. **不删挂载点目录、不删 NAS 数据**：挂载点是 FUSE 视图 / 用户的目录；NAS 数据从来不在本功能
   的删除范围里。弹窗与 CLI 输出都明说这一点。
2. **空父目录保留**：删完 `cache/tasks/default/home/<ns>` 后，`home/` 这类空父目录会留着
   （它们可能被别的任务共用，也不影响功能）。`--all` 则会清掉整个数据根。
3. **按连接共享的上传 / 删除队列、`pins`、`nodes` 不按任务删**：
   * 队列 / `pins` 没有任务归属（路径是远端路径），删除可能影响同连接的其他任务；
   * `nodes` 是文件身份索引（rename 识别用），是可重建的缓存，删了只是退化成「按路径识别」。
   任务级 purge 的 notes 里写明了「上传 / 删除队列按连接共享，未删除」。
4. **共用数据不猜**：NAS 文件夹或缓存目录被本连接另一条任务共用时，对应项跳过并警告
   （见 §2 / §3.3）。
5. **全局 purge 不删系统 autostart 项**：那是 `~/.config/autostart/qxync.desktop`，
   属于「开机行为」而不是 qxync 数据；要关请用「设置 → 高级」的开关。
6. **不可逆**：purge 就是真删，没有回收站 / 备份。GUI 默认不勾选、危险区必须勾选、
   CLI 默认只预览，是三层防误触；但删了就是删了。
7. **回退旧版本不受影响**：任务文件格式、状态库 schema、连接文件格式**都没有改**
   （本功能只加读/删能力）。旧版本读不到已删数据（本来也读不到），不会因此报错。
8. **未做**：
   * GUI 里逐项勾选（现在只有「全部相关数据」一个开关）；
   * 任务级单独删日志（journal 行按子树删，日志文件是按连接滚动的）；
   * 删除后自动 `ensure_dirs()` 重建空目录（交给下次启动 / 用户决定更诚实）；
   * Windows / macOS（整个项目目前只支持 Linux）。

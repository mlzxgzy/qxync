## 一、新增：删除熔断能「先看清单再决定」（M2c §5.3）

用户原话：

> 「删除被熔断挡住（kami@qnap.kdajv.com:9834）：本轮有 99 项删除被保护挡住
> （这轮没有真的删除任何文件；确认这些删除确实需要，再放行）……加个能够看到啥
> （文件）被批量删除的窗口，然后看到后可以决定是否删除」

### 以前的问题

删除熔断（一轮对账判定要删的条目超过阈值时挡下整批、等人工确认）的告警只有一句
「本轮有 N 项删除被保护挡住」+ 一个「放行删除」按钮 —— **被挡的到底是哪些路径，
任何地方都看不到**。那句「确认这些删除确实需要，再放行」只能盲猜：真机上 526 项
挡下的那次，用户同样只能盲放行。

### 现在

| 层 | 行为 |
|---|---|
| 引擎 | 对账判熔断那一刻，把整批 `deletes` 路径快照进内存（升序、最多 200 条 + 全量计数；多视图同轮熔断**合并**而不是覆盖；与熔断签名同一套生命周期：签名变化时替换、解除/放行后清空、提前返回的轮次不清） |
| IPC | 新方法 `blocked_deletes`（零网络，只读内存快照）返回清单 + 原因 + 视图短名 + 首次挡下时间 + 截断标记 |
| GUI | 新弹窗 `#blocked-modal`（42vh 滚动清单、mono 字体路径、「将删除」徽标）；四个告警位（首页 / 状态页 / 诊断页 / 任务卡）都加「查看清单」按钮；弹窗开着时随状态轮询自动刷新；弹窗里的「放行」走原有 `doForceDeletes` 二次确认链，**不是绕过确认的后门** |
| CLI | `qxync sync --blocked-list`（`--json` 可用）；`qxync status` 的熔断行同步提示这个参数 |

### 升级后怎么确认

```bash
# 熔断出现时：
qxync sync --blocked-list          # 终端直接列出被挡路径
qxync sync --blocked-list --json   # 机器可读：blocked/count/paths/label/first_seen/truncated
# 或 GUI：告警条上点「查看清单」→ 弹窗 → 看完再「放行这一轮的删除」或「取消」
```

清单截断到 200 条时弹窗会说明「共 N 项，只列前 200 项」（count 始终是全量数）。

### 边界（如实记）

- **FUSE 侧本地 `rm -rf` 熔断（`DeleteGuard`）不在本次范围**：它逐项回 `EACCES`，
  没有「一批待删清单」可看。
- 清单是**内存快照**，daemon 重启后清空（熔断状态本身也是内存态，行为一致）。

## 三、升级

```bash
# 1) 换二进制（qxync / qxyncd / qxync-gui 一起换，保持版本一致）
sudo install -m755 target/release/qxync target/release/qxyncd target/release/qxync-gui /usr/bin/

# 2) 重启 daemon（IPC 新增方法，daemon 需要重启才提供）
qxync daemon stop && qxync daemon start
# 或：systemctl --user restart qxyncd

# 3) GUI 退出重开（托盘右键退出再启动）
```

升级须知：

* **不需要迁移任何文件**：无数据格式变更、无配置变更；`sync.db` / 缓存 / link
  文件原样可用。IPC 只加方法（`blocked_deletes`）不加字段，老 GUI 配新 daemon
  或新 GUI 配老 daemon 都不会坏（新方法不可用时 GUI 弹窗报「清单不可用」）。
* **AUR 包**：`packaging/arch/` 的 `sha256sums` 仍需 `updpkgsums` 后再推 AUR
  （既定流程，与历版相同）。

## 已知限制（如实记）

* **清单只覆盖对账侧的批量删除熔断**（`DeleteProtection`）：FUSE 侧本地 `rm -rf`
  熔断（`DeleteGuard`）逐项回 `EACCES`，没有「一批待删清单」可看，不在本次范围。
* **`cargo clippy` 未运行**：发版环境未安装 `cargo-clippy`（与 v0.7.12 起相同）。
* **真机验证待部署**：熔断触发路径（熔断轮带清单 → 放行轮不带 → 放行后清空）的
  真机断言已写进 `m2c_engine_refresh_conflict_delete_protection`，下次真机跑生效；
  GUI 弹窗的实机截图待下次熔断出现时补。

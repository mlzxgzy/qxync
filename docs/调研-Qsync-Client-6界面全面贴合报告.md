# Qsync Client 6 界面调研与「全面贴合」方案

> 调研基线：本仓库 `5c4237b release: v0.8.3`（2026-11-01）。
> 官方基准：QNAP Qsync Client 6（Windows 6.1.0 build 0831；教程覆盖 6.0.0+，最后修订 2025-07-22）。
> 证据：官方教程正文与 44 张内嵌截图（本地留档 `.research/`，gitignore）；`qxync-gui` 源码与 2026-10-29 实机截图（`.local-run/gui-shots/`，DPR=1.6458）。
> 方法：官方侧逐屏识读 + 像素取样（PIL）；现状侧逐文件 `file:line` 审计；能力侧对 `ipc.rs` / `commands.rs` / daemon 做「有没有 IPC」判定。
> 说明：本报告只做调研与方案，**未改动任何源码**。所有「未证实」项都已显式标注，不拿推测当结论。

---

## 0. 一页结论

**一句话：qxync-gui 已经有 Qsync 的「骨架」，但还没有 Qsync 的「脸」和「呼吸方式」。**

- **骨架（信息架构）已对齐约 80%**：M8 系列把顶部 tab 改成左侧图标栏，补齐了主页 / 任务 / 文件更新中心 / 错误 / 设置 / 诊断，页面与数据源都在（`docs/M8-向Qsync-Client-6靠拢.md:3`、`crates/qxync-gui/ui/index.html:32-71`）。
- **脸（视觉语言）只对齐约 35%**：主色 `#2F6FD0` vs 官方 `#0C75FF`/`#036DE1`；页面标题 15px vs 官方 24–26px；正文 13px vs 官方 14px；卡片白底 vs `#FAFAFA`；左栏白底 + 文字标签 vs `#F8F9FB` + 纯图标；圆角 6/8 vs 8–10；无品牌 logo。
- **呼吸方式（信息密度）差距最大**：当前主界面常驻「daemon 药丸 + pid/v·uptime/socket + session + 启停 daemon + 当前连接下拉 + 底部 IPC 操作日志抽屉」。这些是**运维控制台**元素，官方一个都没有（`index.html:78-111`、`:1116-1127`、`app.js:1268-1284`）。
- **可落地性很好**：50 项官方界面能力里，**31 项（62%）无需动后端**（23 项已完成 + 8 项纯前端可做）；真正要新后端的只有选择性同步、1-way、Smart Delete 真语义、节省空间「关闭」、LAN 搜索 5 件（约 13–22 人日），而备份任务 / 版本还原 / 团队文件夹 / 分享链接 / 一任务多配对**已被明确决策否决**（`docs/M8…:33`、`:998-1003`）。
- **推荐路线**：先做 **P0 视觉地基 + 外壳净化**（≈4.6 人日），再做 **P1 任务模型 UI**（列表卡 / 详情页 / 新建向导，≈7.6 人日），然后 **P2 更新中心 / 错误列表 / 设置四分区收编**（≈6.3 人日），最后 **P3 分享中心占位 / 帮助关于 / 托盘通知 / 首次引导 / i18n**（≈2.9 人日，含英文 UI 则 ≈7.2）。**合计约 21–22 人日**（细化到工单见 [贴合Qsync6-工作项清单.md](贴合Qsync6-工作项清单.md)；不含新后端项）。

**贴合度评分（Lead 判断，权重与依据见 §4.2）**

| 维度 | 权重 | 现状 | 满分目标（P0–P3 后） |
|---|---:|---:|---:|
| 信息架构与导航 | 15% | 82 | 95 |
| 视觉语言（色/字/形/密度） | 20% | 35 | 88 |
| 首页 / 任务列表 | 15% | 55 | 92 |
| 任务详情 / 配对文件夹 / 新建向导 | 15% | 25 | 85 |
| 文件更新中心 / 错误列表 | 10% | 50 | 88 |
| 设置 | 10% | 45 | 85 |
| 系统集成（托盘/通知/自启/窗口） | 5% | 55 | 80 |
| 文案与 i18n | 10% | 55 | 90 |
| **加权总分** | 100% | **≈49** | **≈88** |

> 「贴合」不是 100 分也可以交付：**剩下 12 分是平台差异与诚实降级**（Linux 无 CfAPI/无挂载点、备份/还原/分享不做、多 NAS 是 qxync 自有能力）。这些必须**写进 UI 说明**，而不是假装有。

## 1. 调研范围与三个必须先纠正的前提

### 1.1 范围

- **官方**：Qsync Client 6 的主窗口、首次建任务、任务列表、同步/备份任务详情、文件夹对设置、频率设置、恢复文件、更新中心、错误列表、分享中心、设置四分区、连接管理、帮助/关于、托盘（未证实）。
- **现状**：`crates/qxync-gui/ui/` 全部前端 + `src/{lib,commands,ipc,tray}.rs` 的界面相关命令；以 7 个一级页面 × 9 个设置分区 × 4 个诊断子页为骨架。
- **不做**：Qsync Central 服务端、备份引擎、版本桶、分享 API 的协议实现（只判断界面能不能做、需不需要后端）。

### 1.2 三个必须先纠正的前提（会误导后续所有判断）

| # | 常见误判 | 事实 | 证据 |
|---|---|---|---|
| 1 | 「设置 10 个分区」 | **9 个**：连接 / 代理 / 同步与筛选 / 个人 / 高级 / 日志 / 释放空间 / LAN 加速 / 关于 | `app.js:52`、`index.html:464-473` |

- **左栏 61px、纯图标无文字**：`#F8F9FB`；logo 40×40；导航项间距 60px；选中态是 55×47 浅蓝胶囊 `#E1EEFF`；图标 24×24 主蓝 `#036DE1`；布局是**上 4（任务/更新/错误/分享）+ 下 2（设置/帮助）**，不是 6 等距（img/32）。
- **对话框**：自定义标题栏 30px `#F8F9FB`，左「Qsync 蓝标 + Qsync」，标题居中 14px，仅一个 ✕（img/01/03/05/27）。

## 7. 验收方案

1. **基线截图**：`Xft.dpi=96 GDK_SCALE=1` 下跑 `xtask/tests/gui-matrix.sh`，产出 9 个目的地 1× 图；作为后续所有视觉对比的基线（现有 `.local-run/gui-shots/` 是 DPR 1.6458，不可用）。
2. **并排比对**：官方 1× 图（img/15、img/32、img/03、img/01）vs qxync 新截图，检查 8 项：左栏宽/底色/选中态、页标题字号、卡片底色/描边/圆角、主按钮色/高/圆角、表格行高/表头、角标、间距。
3. **Token 断言**：扩展 `qxync-gui --self-test` 的 `ui_spec`：检查 `getComputedStyle` 的关键值（accent `#0C75FF`、页标题 24px、左栏 61px、卡片 `#FAFAFA`），防止回退。
4. **验收矩阵不退化**：`gui-matrix.sh` 全绿；`QXNYC_GUI_TAB` 旧值（status/mounts/sync/connect/files）落点不变；`settings:<sec>` 9 个分区仍可直达；页面窗口标题断言不变。
5. **文案对照**：用 §5.5 表逐条核对 zh 文案；`**`、`unspecified/pinned` 等 raw key、`pid/socket` 不得出现在普通页面。
6. **人工清单**：首次启动引导、添加任务 3 步、任务详情往返、暂停/继续、更新中心搜索/排序/清空、错误列表操作、设置四分区、分享占位、托盘菜单、关于弹窗。

## 9. 需要拍板的 6 个问题

1. **「全面贴合」的口径**：是「产品级对齐（IA + 视觉 + 术语 + 交互，允许平台差异）」，还是「像素级复刻 Windows 截图」？建议前者；像素级在 Linux 字体/DPI 下不可维护。
2. **左栏文字标签**：M8 当初保留标签是「有意的偏离」（可发现性）。建议**默认纯图标 + tooltip**，并在设置里提供「显示导航文字」开关（默认关），既贴合又不丢可发现性。
3. **是否加分享中心占位页 / 帮助关于弹窗 / 首次引导**（纯 UI，P3）。建议都加：它们决定「像不像一个完整产品」。
4. **一任务多配对**：官方是 1..N。是否推翻 2026-10-02 的「1:1」决策？若不推翻，任务详情页表格只能 1 行，需接受这个差异。
5. **备份任务灰卡**：官方首屏有 Backup 卡。建议保留**灰色不可点 + 原因说明**（比直接消失更贴合，也更诚实）；若不想引导用户点，可只在「添加任务」向导里出现。
6. **英文 UI**：en 只有 49 键。是补全（+3–5 人日）还是明确「本期仅中文」并移除语言下拉？建议先明确，避免半成品。

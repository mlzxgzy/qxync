# M1.5 设计：守护进程（qxyncd）+ 本地 IPC + CLI 完善

> 目标（规划 §2 M1.5）：把「FUSE + 引擎 + 服务端」收进一个常驻进程 `qxyncd`，
> `qsync`（CLI/GUI）退化成它的客户端；IPC 覆盖 `status/login/ls/mount/get/put/pin`；
> 日志走 `RUST_LOG` + 滚动文件。
>
> 本文件是**开工前的准备工作**：先把契约、生命周期、错误语义定死，再写代码。

---

## 0. 一句话架构

```
 qsync (CLI) ─┐
              ├─ unix socket + JSON(行) ─► qxyncd (常驻单进程)
 GUI (后续) ──┘                              ├─ QsyncSession（登录/保活/重登）
                                             ├─ MetadataCache（M1：内存表）
                                             ├─ HydrationMgr（M1 已有：single-flight + 超时 + EIO）
                                             ├─ MountRegistry（FUSE 线程 + 挂载点）
                                             └─ （M2 起）区间水合 / 轮询 / 上传队列 / 脱水
```

依据：报告 12 §6.1 —— FUSE 的 `read()` 是同步阻塞的，**跨进程 IPC 会拉长水合路径**，
所以 FUSE 与引擎必须同进程；CLI/GUI 才走 IPC。

## 1. 传输与帧格式

| 项 | 决定 | 理由 |
|---|---|---|
| 传输 | **Unix domain socket**（不用 TCP） | 无端口冲突、用文件权限做访问控制、不需要额外 token |
| 路径 | `$XDG_RUNTIME_DIR/qxync/qxyncd.sock`，无该变量时退到 `~/.local/state/qxync/qxyncd.sock` | 运行期文件按 XDG 约定放 `runtime`；退路保证 ssh/无 systemd 环境可用 |
| 权限 | 目录 `0700`、socket `0600` | 只有本人可连 |
| 帧格式 | **一行一个 JSON**（`\n` 分隔，UTF-8，无长度前缀） | `socat - UNIX-CONNECT:…` 就能手测；出问题一眼看清 |
| 并发 | 每连接一个 tokio task；请求可乱序完成（同连接内按序回复） | 长任务（get/put）不能阻塞 status |
| 版本 | 请求带 `"v":1`，响应回 `"v":1`；版本不符直接报 `bad_version` | 后续加字段不破坏旧 CLI |
| 超时 | CLI 侧每请求默认 30s（`get/put/mount` 用 600s） | 与 Qsync 的 60s 水合超时区分开 |

请求/响应示例（也是 `nc -U` 手测模板）：

```json
{"v":1,"method":"status"}
{"v":1,"ok":true,"data":{"user":"test1","host":"qnap...","logged_in":true,"max_log":37,...}}
{"v":1,"method":"ls","path":"/home/qxync-test"}
{"v":1,"method":"get","dir":"/home/qxync-test","name":"big.bin","dest":"/tmp/big.bin"}
```

## 2. IPC 方法表（M1.5 范围）

| method | 参数 | 响应 `data` | 备注 |
|---|---|---|---|
| `ping` | — | `{pong, daemon_version, pid, uptime_secs}` | 存活探测，不做 IO |
| `status` | — | `StatusData` | 见下；**不触发登录**（未登录就 `logged_in:false`） |
| `login` | `user?`, `password?`（省略则读 `credentials.json`） | `{sid_masked, user, uid}` | 成功时写回凭据（0600） |
| `logout` | — | `{}` | 清会话 |
| `ls` | `path` | `Vec<DirEntry>` | 自动翻页在 client 里做 |
| `stat` | `dir`,`name` | `DirEntry?` | 契约：`path`+`file_name`+`file_total=1` |
| `get` | `dir`,`name`,`dest` | `{bytes, mtime}` | 流式落盘 + 长度校验（铁则 1） |
| `put` | `local`,`dest`,`name?` | `{bytes, mtime}` | 上传后 `stat&settime=1` 对齐时间戳 |
| `mkdir` | `parent`,`name` | `{}` | |
| `pin` | `path`,`state?`（省略 = 查询；取值 `pinned`/`unpinned`/`unspecified`/`excluded`） | `{path,pin}` | M1.5 只登记 + xattr 可读；真正影响水合/脱水在 M2/M5 |
| `mount` | `mountpoint`,`remote?`,`cache_dir?`,`threads?`,`auto_unmount?`,`hydrate_timeout_secs?`,`read_write?`,`delete_limit?` | `MountInfo` | FUSE 在 daemon 内起线程；M2c 加 `delete_limit`（本地批量删除熔断） |
| `umount` | `mountpoint` | `{}` | 走 `fusermount3 -u` + join 线程 |
| `mounts` | — | `Vec<MountInfo>` | |
| `sync` | `once?`,`force_deletes?`,`max_deletes?`,`interval_secs?` | `SyncInfo` | **M2c**：三游标轮询 + baseline 对账；`once` 立刻跑一轮，`force_deletes` 放行批量删除 |
| `rm` | `dir`,`name` | `{deleted}` | **M2c**：删远端条目（脚本/测试用） |
| `shutdown` | — | `{unmounted: n}` | 干净退出（卸载所有挂载、删 socket/pid） |

> **M2c 起 `status` 的 `StatusData` 多一个 `sync: SyncInfo`**（三游标 / baseline 条目数 / 冲突 / 删除保护），
> 新增 `sync`、`rm` 两个方法，`mount` 多 `delete_limit`；细节见 [`M2c-变更发现.md`](M2c-变更发现.md)。

`StatusData`：

```jsonc
{
  "daemon": {"version":"0.1.0","pid":1234,"uptime_secs":42,"socket":"/run/user/1000/qxync/qxyncd.sock"},
  "link":   {"id":"default","host":"nas.example.com","port":9834,"https":true,"user":"test1","ipv4_only":true},
  "logged_in": true,
  "session": {"sid_masked":"abcd…","alive":true},          // 永不回传完整 sid
  "server": {"qsync_version":"5.1.1","qpkg_version":"5.0.0.7","build":"20260723",
             "qbox_cgi":true,"fcgi":true,"busy_reason":null},
  "cursors":{"max_log":37,"global_notify":177,"sync_signal":1},
  "hydro":  {"count":1,"bytes":134217728},                  // 本进程累计
  "mounts": [{"mountpoint":"/home/me/qsync-mnt","remote":"/home","readonly":true}]
}
```

**错误**：响应 `{"v":1,"ok":false,"error":{"kind":"...","message":"..."}}`，
`kind ∈ {bad_version, bad_request, not_logged_in, auth, transport, status, parse, io, unsupported, not_running}`。
CLI 直接把 `kind` 映射成退出码（0 成功 / 2 鉴权 / 3 网络 / 4 服务端 status / 5 IO / 1 其它），方便写脚本。

## 3. 进程生命周期

```
qsync daemon start            # 拉起 qxyncd（默认 daemon 化：fork+setsid；--foreground 便于调试）
qsync daemon status           # ping + status（未运行 → kind=not_running，退出码 1）
qsync daemon stop             # shutdown 请求；超时则 SIGTERM
```

* **启动顺序**：读 `links/<id>.json` → 建 socket（已存在且能 ping 通则直接报「已在运行」）→ 可选自动登录 → 进入 accept 循环。
* **pid 文件**：`~/.local/state/qxync/qxyncd.pid`（内容为 pid + socket 路径），用于 `stop` 与排障。
* **日志**：`RUST_LOG` 控制级别（默认 `info`），同时写滚动文件 `~/.local/state/qxync/log/qxyncd.log`
  （按天滚动、保留 7 份；用 `tracing-appender`）。CLI 只写 stderr，不写文件。
* **退出**：`shutdown` / SIGINT / SIGTERM → 依次 `fusermount3 -u` 所有挂载点（等线程 join）→ 删 socket + pid。
  **绝不留下残留挂载**（M1 的 `destroy()` 已保证单挂载干净卸载）。
* **崩溃恢复**：下次启动时若发现 pid 文件但进程不在、或 socket 连不上 → 清理陈旧文件后重建；
  挂载点若已不存在则忽略。

## 4. 会话与保活

* 登录信息（`host/user/password` 0600）与连接配置分离：daemon 启动不强制登录，**首次需要时才登**
  （`status` 不触发登录）。
* 任何请求收到 `ErrorKind::Auth`（服务端 `status:4/5`、`WFM_NEED_USER_NAME`）→ 自动重登一次再重试原请求；
  仍失败则返回 `auth`，由 CLI 提示 `qsync login`。
* sid 只在内存；`status` 里只回**掩码**（前 4 位 + `…`），避免日志/截图泄漏。
* M1.5 不做 `q_token`（真机 `status:-50`，只读/写路径都不需要它）。

## 5. pin 的语义（先定契约）

* `pin` 状态存 `StateStore`（M1.5：内存 + SQLite `pins` 表；表结构随 M2 的 baseline 表一起定）。
* 对外体现：`getfattr -n user.qsync.pin <mount>/<file>` 返回 `pinned|unpinned|unspecified`。
* M1.5 只登记，**不影响**水合/脱水决策；M2/M5 再让 Dehydrator/`read()` 读它
  （`pinned` 不脱水、`excluded` 不同步）。

## 6. 与现有代码的衔接（不破坏 M0/M1）

| 现有 | M1.5 后 |
|---|---|
| `qsync <cmd>` 直连 NAS | 默认**先找 daemon**（socket 可连就走 IPC），加 `--direct` 强制直连、`--via-daemon` 强制 IPC |
| `qsync mount` 在 CLI 前台挂载 | 改由 daemon 持有；CLI 只发 `mount` 请求并打印结果（`--foreground` 时仍可前台挂载便于调试） |
| `qxync-client` 直连 | 不变：daemon 内部就是调它 |
| `qxync-fuse` | 不变：daemon 用 std::thread 起 `mount`（**不能用 `spawn_blocking`**，见 M1 坑 #4） |
| 铁则 1/2 | 不变；daemon 只是把调用方从 CLI 换成 socket |

兼容期结束（M2）后再把 `--direct` 标记为 deprecated。

## 7. M1.5 验收标准

1. `qsync daemon start` → `qsync daemon status` 显示 pid/socket/uptime 与 NAS 信息（未登录时 `logged_in:false`）。
2. `qsync --via-daemon login` → `logged_in:true`；`--via-daemon ls /home/qxync-test` 与直连结果一致。
3. `qsync --via-daemon get`/`put` 往返字节一致（复用 M0 的 fixture）。
4. `qsync --via-daemon mount <mnt>` → `fuse-matrix.sh` 的检查项在 daemon 挂载下同样通过；
   `qsync --via-daemon umount` 后 `/proc/mounts` 无残留。
5. `pin` 设置后 `getfattr -n user.qsync.pin` 可读到对应值。
6. `qsync daemon stop` 后：socket/pid 文件消失、无残留挂载；再次 `start` 能正常拉起（幂等）。
7. 日志文件按天滚动、`RUST_LOG=debug` 能看到 IPC 请求轨迹。
8. `cargo test --workspace` 全绿（含 IPC 编解码单测 + 真机 IPC 端到端测试）。

```
qsync daemon stop     → socket/pid 删除、无残留挂载；停止后 CLI 自动回退直连
```

* IPC 无 token 鉴权（依赖 socket 0600）；GUI 化时再评估。
* `--direct` 在 M2 稳定后可标 deprecated。

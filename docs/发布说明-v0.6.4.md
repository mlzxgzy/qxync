# v0.6.4 —— 大目录对账：删除判定不再永久推迟

> 发布日期：2026-10-18
> 上一版：[v0.6.3](发布说明-v0.6.3.md)（任务默认路径 / 删除相关数据）
>
> **补丁版**：只修 v0.6.3 之后真机暴露的对账缺陷，没有新功能、没有配置/数据格式变更。

**升级就是换二进制 + 重启 daemon**（这次改的正是 daemon，已在跑的旧进程不会自动变）。

## 一句话

目录数超过单轮上限（默认 200）的任务，以前每轮都从排序开头只列前 200 个目录，排在后面的
目录**永远**轮不到；而「远端视图不完整就不按缺失删本地」这条安全阀因此永久生效 ——
这些目录里的**远端删除、上传、刷新判定永远不会执行**。本版改成**轮转扫描 + 按目录判定**：
删除恢复落地，且本轮没扫到的目录**一个都不误删**。

## 一、症状：目录一多，「删」这一半就停摆

真机上（228 个目录）每轮都打印同一条说明：

```text
目录数 228 超过单轮上限 200（后 28 个本轮没扫） → 本轮跳过删除判定
```

连续 **87 轮**重复。数据安全没有被破坏（没有误删），但删除判定永远不执行：远端已经删掉的
文件本地一直在，改名的旧名也一直留着，界面上「同步正常」的假象会让人以为删干净了。

根因是顺序固定 + 上限截断：每轮都从头取前 `max_dirs_per_poll` 个目录，排序靠后的目录
既不会被列出，也不会被「轮空」到，安全阀「远端视图不完整 → 暂缓删除判定」就一直挂着。

## 二、修了什么

1. **轮转扫描**：目录数超上限时，每轮从上一轮停下的目录之后接着列、到尾回绕；远端根
   恒定每轮都列（所以上限 200 的一轮 = 根 + 199 个其它目录）。游标落在 `sync.db` 的
   `meta` 表（`reconcile_scan_cursor:<mountpoint>`），`qxync sync --once` 跨进程也接得上。
   228 个目录、200 上限 → **2 轮覆盖全部目录**。
2. **视图完整性按目录判定**：只有本轮真正列过（列举成功，或 4/5/6 经 `stat` 确认
   `exist=0`）的目录里的候选才允许判定；没列到的目录里的条目一律暂不判定（不按缺失删
   本地），同一视图里其它已列全的目录**不陪绑**。
3. **改名配对**只用「父目录本轮列过」的已删侧候选 —— 不把「没看到」配成一次改名。
4. **`status 4/5` 不再直接当成「远端已删」**（顺带补掉的一个更危险的老洞）：4/5 同时是
   权限拒绝 / 会话失效的码（真机 `/Download` 回 5、`/homes` 回 4，但路径其实存在）。现在
   列举回 4/5/6 时先用 `stat` 正向确认，只有 `exist=0` 才按「远端已删」处理；stat 说仍
   存在 → 目录条目记进远端视图（防止「父目录列举漏掉它」时目录自身连整棵子树被删），
   内容本轮不判定；stat 也失败 → 存在性未知，目录自身与内容都不判定。stat 成功本身证明
   会话有效，所以**不**置 `auth_failed`（否则永久 ACL 隐藏的目录会每轮重登 + 刷 WARN）。
5. **HTTP 状态与响应形状**：`get_list` / `stat` 检查 HTTP 状态与「像不像列表 JSON」——
   反代 502 的 `{"error":…}`、HTTP 200 的非列表 JSON 不再被读成空目录；`list_limit` 不再
   把缺省 `total=0` 当总数在第一页就停止翻页。

## 三、升级须知

* **换二进制后重启 daemon**：`cargo build --release`（或装新包）后重启 `qxyncd`；
  已经在跑的旧进程不会自动变。
* **没有数据迁移**：`sync.db` schema 没改，只在 `meta` 里多一个游标键；回退旧版本不受影响
  （旧版本忽略这个键）。
* 目录越多、一轮扫不完是**正常**的：228 目录 / 上限 200 = 每轮轮转 199 个，2 轮一轮回。
  note 会从「后 N 个本轮没扫」变成「本轮按轮转列了 N 个」，远端删除会在 1～2 轮内落地。
* 单轮上限仍是 **200**（没有为了提高覆盖而调大，避免单轮耗时变长）。

## 五、已知边界（如实写）

* **真机上「路径存在但当前会话不可见」时 `stat` 是否稳定回 `exist=0` 没有实测**（仓库只有
  `get_list` 回 4/5 的真机证据）。若 QTS 对不可见路径的 `stat` 也回 `exist=0`，这条误删
  路径只是多了一跳，需要真机对 `/Download` 或 `/homes` 直接调一次 `func=stat` 确认，必要时
  再加「父目录列表也没有该条目」的交叉校验。
* 删除保护的粒度从「整个远端视图」变成「本轮轮到的目录窗口」：没轮到的目录里的删除会被
  **延后**（不是误删），最坏等一个轮转周期。
* 跨目录改名可能被拆到不同轮次判定（本地有未上传改动时可能重传旧名）。
* `cargo clippy` 本环境未安装组件，未跑；GUI 没有新增界面元素，不需要新的 GUI 矩阵。

# qxync v0.4.0 —— 缓存优先 + 会话自愈：`ls`/`cat` 的等待与「sid 一过期就 EIO」都收拾掉了

**中文** · [English](#english)

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](https://github.com/mlzxgzy/qxync/blob/master/LICENSE-MIT)

**这一版没有破坏性变更**：配置、任务文件、缓存目录布局、命令行参数都不需要改
（0.3.0 那次的 `roots` / `home_root` 删除仍然生效）。升级方式就是换二进制 + 重启 daemon，
建议顺手把挂载点卸了重挂一次（见文末「升级」）。

## 一句话

以前 `ls` 每次都要等一次网（0.3–1 秒），而**磁盘上明明已经缓存好的文件**，重启后再 `cat`
还要几十秒；sid 一过期，整个挂载点还有可能会一直 `EIO` 到重新挂载。这一版两处都根治了。

## 缓存优先：本地有的内容不再重新问 NAS（M9）

**根因**：记录「哪些区间已经取回本地」的位图只活在内存里。daemon 一重启、或者节点被重新
`lookup` 一遍，位图就被清成全「未取回」—— 于是磁盘上明明有内容，`read()` 还是逐区间重新
从 NAS 拉。同理，`readdir` / `lookup` 当时根本没有任何本地清单，每次访问都是一次 NAS 往返。

**现在**：

* **水合位图随内容落盘**（缓存文件旁边的 `<cache>.qxstate`，带 size/mtime 签名）。
  重建节点时按签名**认领**磁盘上已有的缓存 —— 缓存命中的 `cat` 零 NAS 往返；
  签名对不上（NAS 上那份变了）就整份作废，绝不拿旧内容冒充新版本。
* **「映射」本地化**：挂载点里有什么，吃的是 NAS 文件列表的本地快照；快照由后台变更轮询
  定时刷新，`ls` / `lookup` 不再每次等网。本地新建 / 删除 / 改名会立刻同步进快照。
* **远端内容变了**：本地**脱水**时只更元数据；本地**有水**时旧内容继续可读，
  后台把新版本整份拉下来后 **原子换上**（换上前 `cat` 拿到的是完整旧版本、`stat` 也是旧大小；
  换上后一次切成新版本 + 新大小）。不会读到半新半旧，也不会为了"顺手更新"卡住你的 `cat`。

真机实测（4 MiB 文件，隔离环境，同一台 NAS）：

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 同一会话第二次 `ls` | 0.50 s | **0.001 s** |
| 重启 daemon 后第二次 `ls` | 0.32 s | **0.001 s** |
| **重启 daemon 后 `cat`（内容已整份在磁盘上）** | **23.75 s** | **0.115 s** |
| 远端变更、后台刷新在飞时的 `cat` | — | 0.002 s（完整旧版本） |
| 刷新落地后的 `cat` | — | 0.002 s（新版本，`stat` 同步切到新大小） |

## 会话自愈：sid 过期不再等于挂载点废掉（M10）

**根因**：挂载点持有的是**挂载那一刻拷贝**的 sid，过期后没有任何路径更新它；
「遇鉴权失败自动重登」只写在 IPC 命令里，挂载点和同步引擎都不走那条路。

**现在**：

* sid **可热更新**：daemon 重登成功后，新 sid 会**推给所有同账号的挂载点**
  （读写挂载的上传队列共用同一个客户端，也一起吃）；
* 挂载点遇到鉴权失败会**让 daemon 重登一次、拿到新 sid 原地重试**（只重试一次），
  覆盖 `readdir` / `lookup` / 区间水合 / `mkdir` / `unlink` / `set_mtime` / `rename`；
* 另有**会话保活**兜底：默认每 120 秒探一次，失效就重登并推挂载点
  （`QXNYC_SESSION_KEEPALIVE=0` 可关）；
* 变更轮询遇到会话失效也会重登，不再每一轮都失败。

真机验收：`logout`（服务端 sid 作废 + 挂载点 sid 清掉）之后，挂载点冷 `ls` 0.50 秒成功、
`cat` 1024 字节成功；daemon 日志里能看到
`挂载点会话失效 → 会话已热更新到 1 个挂载点 → 登录成功`。
修好之前，同一场景挂载点的每个请求都是永久 `EIO`。

## 升级

1. 换二进制（tar.gz / AUR 包 / 自建），重启 daemon：
   ```bash
   qxync daemon restart     # 或 systemctl --user restart qxyncd
   ```
2. **建议把挂载点卸了重挂一次**（`qxync umount <挂载点>` 后重新 `qxync mount`）：
   正在跑的老进程里没有本版的新逻辑，重挂才能拿到「会话热更新」。
3. 兼容性说明：
   * 缓存目录里会多出 `<cache>.qxstate` 小文件（64 字节级），脱水 / 删除时会跟着清掉；
   * 升级前已经缓存的文件**第一次读**仍可能重新水合一次（那一份没有位图，认领不了），
     之后就快了 —— 这是刻意的：宁可重下一次，也不把稀疏文件里的空洞当成数据；
   * 远端文件列表的刷新节奏 = 变更轮询间隔（`QXNYC_POLL_INTERVAL`，默认 30 秒）。
     远端刚建的文件在下一轮轮询之前不在「映射」里，这是本版刻意的语义（映射来自 NAS 文件列表）。

* `qxync-fuse` 单测 27 → 35、`qxync-client` 23 → 24、`qxync-core` 105 → 106、`qxync-daemon` 2 → 6。
* 两个隔离环境（独立配置 / socket / 挂载点）对真机 NAS 跑的端到端对比见
  [`docs/M9-缓存优先与映射.md`](https://github.com/mlzxgzy/qxync/blob/master/docs/M9-缓存优先与映射.md)
  与 [`docs/M10-会话热更新.md`](https://github.com/mlzxgzy/qxync/blob/master/docs/M10-会话热更新.md)；
  逐条判据记在 [`docs/验收记录.md`](https://github.com/mlzxgzy/qxync/blob/master/docs/验收记录.md)。

## English

# qxync v0.4.0 — cache first + session self-healing

**No breaking changes**: configuration, task files, cache layout and CLI arguments are unchanged
(the `roots` / `home_root` removal from 0.3.0 still applies). Upgrading means swapping the binaries
and restarting the daemon; remounting the mount point once is recommended (see "Upgrade" below).

### Cache first (M9)

The bitmap that records *which ranges are already cached locally* used to live only in memory, so after
a daemon restart — or whenever a node was re-`lookup`ed — it was reset and `read()` re-fetched every
range from the NAS even though the bytes were already on disk. `readdir`/`lookup` had no local listing
at all, costing a NAS round trip per call.

Now the hydration bitmap is **persisted next to the content** (`<cache>.qxstate`, carrying a
size/mtime signature), so a cache-hit `cat` makes **zero NAS round trips**; `ls`/`lookup` are served
from a **local snapshot of the NAS file list** refreshed by the change poll; and when a remote file
changes, a **hydrated** local file keeps serving its old content while the new version is fetched in
the background and **atomically swapped in** (until the swap, `cat` returns the complete old version
and `stat` reports its size; after it, both switch to the new one at once).

Measured on a real NAS (4 MiB file, isolated environment):

| Scenario | Before | After |
|---|---|---|
| second `ls` in the same session | 0.50 s | **0.001 s** |
| second `ls` after a daemon restart | 0.32 s | **0.001 s** |
| **`cat` after a daemon restart (content fully on disk)** | **23.75 s** | **0.115 s** |
| `cat` while the background refresh is in flight | — | 0.002 s (complete old version) |
| `cat` after the refresh landed | — | 0.002 s (new version, size switches with it) |

### Session self-healing (M10)

A mount point used to hold the sid **copied at mount time**, with no path updating it; "re-login on
auth failure" existed only in the IPC macro. Now the sid is **hot-swappable**: after a re-login the
daemon **pushes the new sid to every mount of the same account** (read-write mounts' upload queue
shares the same client), a mount that hits an auth failure asks the daemon to log in again and
**retries in place exactly once** (`readdir` / `lookup` / range hydration / `mkdir` / `unlink` /
`set_mtime` / `rename`), and a periodic keepalive (120 s by default, `QXNYC_SESSION_KEEPALIVE=0`
disables it) re-logs in and pushes when the sid is gone. Change polling also re-logs in on session
expiry instead of failing every round.

On-device acceptance: after `logout` (server-side sid invalidated and the mount's sid cleared), a cold
`ls` on the mount succeeds in 0.50 s and `cat` returns 1024 bytes, with the log showing
"mount session expired → session hot-updated to 1 mount → login ok". Before the fix, every request on
that mount stayed `EIO` until it was remounted.

### Upgrade

1. Swap the binaries and restart the daemon (`qxync daemon restart`, or
   `systemctl --user restart qxyncd`).
2. **Remount once** (`qxync umount <mountpoint>` then `qxync mount …`) — the running old process has
   none of the new logic, so remounting is what picks up session hot-update.
3. Compatibility: the cache directory gains small `<cache>.qxstate` files (tens of bytes, cleaned up
   together with the content); files cached by an older version may be re-hydrated **once** on first
   read (they have no bitmap to adopt) and are fast afterwards; the mapping's freshness equals the
   change-poll interval (`QXNYC_POLL_INTERVAL`, 30 s by default).

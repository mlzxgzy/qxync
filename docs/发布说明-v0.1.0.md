# qxync v0.1.0 —— Qsync for Linux，带 on-demand 按需同步

**中文** · [English](#english)

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](https://github.com/mlzxgzy/qxync/blob/master/LICENSE-MIT)

首个公开版本。用 Rust + FUSE 实现的**第三方 QNAP Qsync Linux 客户端**：
NAS 上的文件在本地只是一个「占位符」，`ls -l` 显示真实大小却**零下载**，
读到哪一块才取哪一块；不想留的就**脱水**回占位符。

> ⚠️ 只用于**你自己拥有或已获明确授权**的 QNAP NAS。本项目不分发任何 QNAP 二进制、
> 不绕过任何授权或保护措施，与 QNAP Systems, Inc. **无任何关联**。
> 完整条款见 [`DISCLAIMER.md`](https://github.com/mlzxgzy/qxync/blob/master/DISCLAIMER.md)。

## 这个版本有什么

**三个二进制**

| 二进制 | 角色 |
|---|---|
| `qsync` | 命令行：登录 / 列举 / 上传下载 / 挂载 / 同步 / 脱水 / 任务 / 设置 / 日志 / LAN 对等 |
| `qxyncd` | 常驻守护：**唯一**持有 FUSE 与 NAS 会话 + 本地 unix socket JSON IPC |
| `qxync-gui` | Tauri 2 桌面应用（零依赖静态前端，无 npm；全部经 daemon 的 IPC） |

**能力一览**

- **按需水合**：**128 KiB 区间**粒度 —— `head -c 100 big.bin` 只下载 1 个区间，不整文件下载
- **读写挂载**：写前 **read-modify-write**，绝不把没取回的区间当 0 上传
- **变更发现**：三游标轮询 + baseline 三向对账；**冲突副本** + 远端批量删除**熔断**
- **脱水 / 释放空间**：完整安全检查链（pin、未上传改动、打开的 fd、被 mmap、正在水合、刚访问过）
- **本地状态库**：SQLite 承载游标 / baseline / pin / 上传队列，**同一事务**落盘
- **多根 / 共享文件夹**：家目录可读写，非家目录根在 FUSE 层直接 `EROFS`
- **选择性同步**：gitignore 风味的 `exclude` 规则 + 内置临时文件过滤
- **LAN 直连**：qxync↔qxync 自研对等协议（配对 / 事件快路径 / 本地区间直传），失败静默回落 NAS
- **桌面 GUI**：主页 / 任务 / 文件 / 更新 / 错误 / 设置 / 诊断 + 托盘 + 通知 + 开机自启

**可靠性不是「能跑起来」的程度** —— 每个里程碑都在真机上跑过完整验收：

| 矩阵 | 结果 |
|---|---|
| `fuse-matrix.sh`（真挂载） | ✅ 68/68 |
| `gui-matrix.sh` | ✅ 148/148 |
| `m5` / `m6` / `m7` | ✅ 30 / 29 / 60 |
| `m82` / `m83` / `m84` | ✅ 37 / 27 / 92 |
| **合计** | ✅ **491 项全过** |
| `cargo test --workspace` | ✅ 全绿 |

真机验证对象：**QNAP TS-464C / QTS 5.2.9 / Qsync QPKG 5.0.0.7（build 20260723）**。
明细见 [`docs/验收记录.md`](https://github.com/mlzxgzy/qxync/blob/master/docs/验收记录.md)。

**两条铁则**（整个项目不许违反）：

1. 每次 `read()` 必须返回真实数据或明确 `EIO`，**绝不短读**（短读 = 内核零填充 = 数据静默损坏）。
2. 每次脱水必须**先 `inval_inode` 让内核失效缓存，再清内容**（顺序反了 = 数据错乱）。

## 安装

**本 Release 直接带预编译产物**（Linux x86_64），下载即用：

| 资产 | 说明 |
|---|---|
| `qxync-0.1.0-x86_64-unknown-linux-gnu.tar.gz` | 三个二进制 + 许可证 / 免责声明 |
| `qsync` · `qxyncd` · `qxync-gui` | 三个裸二进制，同一份构建 |
| `SHA256SUMS` | 校验和（`sha256sum -c SHA256SUMS`） |

解包后三个二进制**放在同一个目录**即可：GUI 先找自己旁边的 `qxyncd`，找不到再退回 `PATH`。
运行 GUI 需要系统里有 WebKitGTK 4.1 / GTK 3 运行时（Debian/Ubuntu：
`libwebkit2gtk-4.1-0` + `libgtk-3-0`），FUSE 3 需要 `/dev/fuse` + `fusermount3`。

也可以从源码构建（可复现、可审计）：

```bash
git clone https://github.com/mlzxgzy/qxync.git
cd qxync
cargo build --workspace --release
```

需要 **Rust 1.90+** 与 **FUSE 3**（`/dev/fuse` + `fusermount3`）；
构建 GUI 还需要 WebKitGTK 4.1 / GTK 3 的开发包。详见 [README](https://github.com/mlzxgzy/qxync/blob/master/README.md#快速开始)。

```bash
qsync --host <你的NAS> --port 9834 --insecure --user <用户> --password '<口令>' login
qsync daemon start
qsync mount ~/qsync-mnt --remote /home
```

## 已知限制

- 托盘需要 SNI 宿主（Plasma / waybar / polybar / XFCE+statusnotifier / LXQt / Cinnamon /
  GNOME+AppIndicator）；**裸 GNOME 与只有 XEmbed 的老式托盘不会显示图标**
  （程序会探测并如实告知，不会把窗口藏进没人画的托盘）
- **不实现云账号 / QID / myQNAPcloud 登录**，只做「直连 NAS 的本地账号」
- **不与官方客户端的 WebSocket 二进制通道互通**（线格式未还原）
- 界面 i18n 目前只有 zh-CN（`en` 表已预留）
- 只在 QNAP TS-464C / QTS 5.2.9 上做过完整真机验证，其它型号可能有行为差异

完整列表见 [README 的「已知限制」](https://github.com/mlzxgzy/qxync/blob/master/README.md#已知限制)。

## English

# qxync v0.1.0 — Qsync for Linux with on-demand sync

First public release. A **third-party QNAP Qsync client for Linux** in Rust + FUSE:
files from your NAS appear locally as **placeholders** — `ls -l` shows the real size with
**zero download** — and only the ranges you actually read are fetched. What you no longer need can
be **dehydrated** back into a placeholder.

> ⚠️ For QNAP NAS devices **you own or are explicitly authorized to administer** only.
> This project distributes no QNAP binaries and circumvents no authorization or protection measure.
> It is **not affiliated with QNAP Systems, Inc.** See [`DISCLAIMER.md`](https://github.com/mlzxgzy/qxync/blob/master/DISCLAIMER.md).

### What's in it

- **On-demand hydration** at **128 KiB range** granularity — `head -c 100 big.bin` fetches one
  range, not the whole file
- **Read-write mounts** with mandatory **read-modify-write** before any upload, so ranges that were
  never fetched are never uploaded as zeros
- **Change discovery**: three-cursor polling + baseline three-way reconciliation,
  **conflicted copies**, and a **circuit breaker** for mass remote deletions
- **Dehydration / free up space** behind a full safety chain (pins, pending uploads, open fds,
  mmap via `/proc/*/maps`, in-flight hydration, recent access)
- **Local state store**: SQLite holding cursors / baseline / pins / upload queue, committed in a
  **single transaction**
- **Multi-root / shared folders**: the home root is writable; non-home roots return `EROFS` at the
  FUSE layer
- **Selective sync** with gitignore-flavoured `exclude` rules plus built-in temp-file filtering
- **LAN direct**: a qxync-to-qxync peer protocol (pairing, event fast path, local range transfer)
  that silently falls back to the NAS on any mismatch
- **Desktop GUI** (Tauri 2): Home / Tasks / Files / Updates / Errors / Settings / Diagnostics,
  plus tray, notifications and autostart

### Verified, not just "it runs"

Every milestone went through a full acceptance run against a real NAS:
**491 checks passing** across eight matrices (fuse 68 · gui 148 · m5 30 · m6 29 · m7 60 ·
m82 37 · m83 27 · m84 92), plus a green `cargo test --workspace`.
Verified on **QNAP TS-464C / QTS 5.2.9 / Qsync QPKG 5.0.0.7 (build 20260723)**.

**Two hard rules** the project never violates:

1. Every `read()` returns real data or an explicit `EIO` — **never a short read**
   (a short read means the kernel zero-fills, i.e. silent corruption).
2. Every dehydration calls **`inval_inode` before clearing content** (reversed order corrupts data).

### Install

**Prebuilt artifacts are attached to this release** (Linux x86_64) — download and run:

| Asset | What it is |
|---|---|
| `qxync-0.1.0-x86_64-unknown-linux-gnu.tar.gz` | all three binaries + licences / disclaimer |
| `qsync` · `qxyncd` · `qxync-gui` | the three binaries on their own, from the same build |
| `SHA256SUMS` | checksums (`sha256sum -c SHA256SUMS`) |

Keep the three binaries in the **same directory**: the GUI first looks for `qxyncd` next to itself
and only then falls back to `PATH`. Running the GUI needs the WebKitGTK 4.1 / GTK 3 runtime
(`libwebkit2gtk-4.1-0` + `libgtk-3-0` on Debian/Ubuntu); FUSE 3 needs `/dev/fuse` + `fusermount3`.

You can also build from source (reproducible and auditable):

```bash
git clone https://github.com/mlzxgzy/qxync.git
cd qxync
cargo build --workspace --release
```

Requires **Rust 1.90+** and **FUSE 3** (`/dev/fuse` + `fusermount3`); building the GUI additionally
needs the WebKitGTK 4.1 / GTK 3 dev packages. See the [README](https://github.com/mlzxgzy/qxync/blob/master/README.en.md#quick-start).

### Known limitations

- The tray needs an SNI host (Plasma / waybar / polybar / XFCE+statusnotifier / LXQt / Cinnamon /
  GNOME+AppIndicator); **bare GNOME and XEmbed-only legacy trays show no icon** — the app detects
  this and tells you, rather than hiding its window in a tray nobody draws
- **No cloud account / QID / myQNAPcloud login** — local NAS accounts only
- **No interoperability with the official client's WebSocket binary channel** (wire format not
  reverse-engineered)
- UI i18n is currently zh-CN only (the `en` table is reserved)
- Full acceptance was only done on QNAP TS-464C / QTS 5.2.9; other models may differ

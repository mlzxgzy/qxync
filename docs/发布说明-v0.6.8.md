# v0.6.8 —— 对账扫描：时间预算驱动，一轮能装下就全量

> 发布日期：2026-10-19
> 上一版：[v0.6.7](发布说明-v0.6.7.md)（daemon 停止前查占用）
>
> **重设计版**：对账「一轮列多少目录」从写死的 200 改为按轮询间隔推导的时间预算。
> 无配置/数据格式变更；旧游标兼容（列完全部时自动清掉）。

**升级就是换二进制 + 重启 daemon**（改的正是 daemon 的对账循环）。

## 一句话

目录多的任务，以前不管轮询间隔多长、一轮只列 200 个目录，剩下的排队轮转 ——
间隔 600s、1439 个目录时远端删除最坏要 **80 分钟**才落地。本版改成**时间预算驱动**：
预算 = 间隔 × 50%，装得下就每轮全量（删除延迟 = 一个间隔），装不下自动退化为轮转。

## 一、问题：上限跟间隔脱钩，「轮转」变成了常态而不是兜底

真机（2026-10-19）：

```text
qbox_get_sync_log lower=337725 没有新事件          ← 事件快路径是死的
对账：目录数 1439 超过单轮上限 200（本轮按轮转列了 200 个）
```

三个事实叠在一起：

1. **轮询间隔 600s**（journal 里 scan 记录间隔稳定在 607~615s），不是默认的 30s；
2. **全量列举只要 1~5 分钟**（1439 个目录 × 50~200ms/次），在 600s 里绰绰有余；
3. **该账号事件快路径是死的**：`qbox_get_syncing_folder_list` 返回 `total:0`、
   `qbox_get_sync_log` 无新事件 —— baseline 对账就是变更发现的**主路径**。

旧设计里 `max_dirs_per_poll = 200` 是为默认 30s 间隔准备的（30s 里装不下 1439 次列举），
但它跟实际间隔完全脱钩：600s 间隔的任务也被硬掰成 8 轮轮转，删除判定最坏延迟
8 × 600s = **80 分钟**。轮转本身没错（v0.6.4 修的就是「永远轮不到」），错的是
「该不该轮转」不问间隔。

## 二、改了什么

1. **时间预算**（`SyncConfig::scan_time_budget`）：
   * 后台轮询 → 间隔 × 50%（`SCAN_BUDGET_RATIO_OF_INTERVAL`），**每轮推导**
     （间隔运行时可调，`sync --interval`）；
   * `sync --once` / GUI「立即同步」→ 给足 600s（`SCAN_BUDGET_ONCE`）—— 手动场景
     就是要全量；
   * `QXNYC_SCAN_BUDGET_SECS` 显式覆盖（`0` = 不限时间）。
2. **预算没用完 → 一轮全量**：窗口列完即全量，删除判定延迟 = 一个间隔；预算耗尽 →
   到点即收，游标 = 最后一个列过的目录，下轮续扫（退化为轮转，每轮耗时可控）。
3. **进度保证**：每轮**至少列一个**轮转目录（预算检查从第二个开始）。否则「预算 <
   一次列举耗时」的极端配置（间隔 1s → 预算 0.5s，单次列举 600ms）会让根吃光预算、
   游标存不下 —— v0.6.4 修过的饿死换个马甲回来。至少推进一个 = 游标每轮前进，
   最慢也能转完一圈。
4. **游标语义升级**：
   * 游标存在就进轮转模式（不再要求「目录数 > 硬顶」）—— 时间预算耗尽留下的游标
     若被忽略，排序在后的目录在时间预算下永远轮不到；
   * 列完全部时**清游标**（`Store::delete_meta`，新增）—— 不清的话下轮带着游标
     进轮转模式，白转一圈；
   * 回绕补齐**不超过全集**：预算 ≥ 全集时窗口 = 全集的旋转序，不重复列目录
     （顺手修了 `pick_scan_window` 在「预算大于全集」时会重复塞目录的 bug）。
5. **`max_dirs_per_poll` 降级为硬顶兜底**（防目录数爆炸拖死单轮），默认 200 → 2000。
6. **note 口径升级**：预算耗尽会写明
   `对账时间预算 Xs 耗尽：本轮列了 Y/Z 个目录，下轮从游标续扫`。

## 三、对你意味着什么

| 场景 | 旧行为 | 新行为 |
|---|---|---|
| 1439 目录 × 600s 间隔 | 8 轮轮转，删除延迟最坏 80 分钟 | **每轮全量**（预算 300s > 实际 1~5 分钟），删除延迟 ≤ 10 分钟 |
| 1439 目录 × 30s 间隔 | 8 轮轮转 | 预算 15s 装不下 → 自动退化为轮转（游标续扫），每轮耗时可控 |
| 手动 `sync --once` | 只列 200 个 | 预算 600s，基本就是全量 |
| 目录数 > 2000 | 轮转 | 仍轮转（硬顶兜底），但时间预算先到就按时间走 |

```text
cargo test -p qxync-daemon -p qxync-core
  qxync-core    225 + 8 + 1 passed
  qxync-daemon  63 passed（含 2 个新测试）
cargo build --workspace   零警告
```

新测试：

- `generous_time_budget_scans_everything_in_one_round` —— 预算充足时 228 目录一轮
  列完、排序一头一尾的删除**当轮**都执行、游标清空；
- `tiny_time_budget_still_makes_progress` —— 1ns 预算下每轮固定推进一个目录、游标
  逐轮前进（d000 → d001 → d002）、未轮到的目录不误删。

既有轮转测试（`reconcile_rotates_scan_window_instead_of_starving_deletions` 等）
保留语义：显式把硬顶压回 200 复刻「目录数超硬顶」场景，两轮窗口合起来仍覆盖全部目录。

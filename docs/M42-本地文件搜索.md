# M42 · 本地文件搜索（`qxync find`）—— 用目录数据库直接搜同步树

> 状态：**已实现（未发版；`[Unreleased]`）**；§7 为验收结果
> 前置：[M5 SQLite 状态库](M5-SQLite与delta.md)（`baseline`）、
> [M36 远端副本证据](M36-回放顺序与远端副本证据.md)（`nodes.local_only`）

## 0. 结论先行

用户问：「**有目录数据库的话是不是可以快速搜索仓库内的文件啊**」。能 —— 但要先分清
「目录数据库」和「内容索引」：

* **能搜的**：路径、文件名、大小、mtime、文件/目录 —— 状态库里本来就有；
* **搜不了的**：文件内容（状态库只存签名，不存内容）；内容搜索要走缓存/另建 FTS，
  不在本里程碑（见 §8）。

`qxync find` 就是把这个「目录数据库」直接开放出来的最小 CLI：

```text
$ qxync find 防火墙 --limit 5
/home/.Qsync/0.1+X/5.课件/1+X防火墙安全配置-外发.pdf
/home/.Qsync/2024/06-台州实训室/…/三级.1.2.2.Windows防火墙和远程访问安全配置
…
…共 49 条，已显示 5 条（--limit 0 显示全部）
```

真实库（**28 136 个文件 + 5 891 个目录**）实测 **97 ms**（含进程启动），
**不挂载、不联网、daemon 不在跑**都成立。

## 1. 数据源：状态库里原本就有两份「目录清单」

| 表 | 内容 | 搜索里的角色 |
|---|---|---|
| `baseline(path, present, is_dir, size, mtime)` | 上次同步成功时的**远端**路径 + 签名（M5） | 主力：`present=1` 的行就是 NAS 同步树清单；`present=0` 是墓碑，不返回 |
| `nodes(file_id, path, …, local_only)` | 文件身份 → 路径（M15）；`local_only=1` = 本地新建、远端还没有副本（M36） | 补「刚建、还没上传成功」的文件，`origin=local_only` |

去重：同一个路径既在 baseline（`present=1`）又在 `nodes.local_only` 时，以远端签名为准。
搜索先用 [`qxync_core::search::run`](../crates/qxync-core/src/search.rs) 做纯函数匹配，
装载由 [`Store::search`](../crates/qxync-core/src/store.rs) 负责（`Store::baseline()` +
`Store::nodes_local_only()`）——**只读**，不建库、不写任何行。

### 新鲜度（写进 `--help` 的硬约束）

* `baseline`：每轮对账结束 `save_state` 事务落盘；上传成功 `note_uploaded → save_all`
  立即落盘（M38/M41 那套）；FUSE 新建 `node_upsert` 也是立即落盘；
* 所以**远端侧**的变化最多滞后一轮轮询（默认 30 s），本地新建/上传几乎实时；
* 要绝对新鲜：先 `qxync sync --once` 再搜。搜索本身**绝不**触发对账/联网。

## 2. 匹配与过滤语义

| 维度 | 规则 |
|---|---|
| 默认模式 | **子串**，大小写不敏感（Unicode 折叠；中文不受影响）；`--case-sensitive` 关闭折叠 |
| `--glob` | `*` 任意序列、`?` 单字符；**模式里没有 `/` 时只匹配文件名**（`*.pdf` 命中任意层级）；有 `/` 时按整条路径匹配，此时 `*` 可跨 `/`；无字符类（`[abc]` 按字面） |
| 空模式 | 匹配全部（`qxync find` = 列出前 100 条） |
| `--under` | 按**路径段**判子树：`/home/a` 不会吞 `/home/ab`；末尾 `/` 容忍；**可以给挂载点下的本地路径**（自动换算成远端） |
| `--type f\|d` | 只要文件 / 只要目录（也接受 `file`/`dir`） |
| `--min-size` / `--max-size` | 1024 进制，后缀 K/M/G/T，大小写不敏感 |
| `--sort path\|size\|mtime` | `path` 升序（默认）；`size` 大的在前、`mtime` 新的在前；`--reverse` 翻转 |
| `--limit N` | 默认 100；`0` = 全部；`total` 始终是**截断前**的命中数 |

为什么不用 SQL `LIKE`：LIKE 的大小写折叠只对 ASCII 生效，模式里的 `%`/`_`/`\` 还得
自己转义（漏一处就是「搜 `100%` 变成搜一切」）。3 万行在 Rust 侧过滤是毫秒级，
正确性更值钱（§7 有实测）。

## 3. CLI

```
qxync find [PATTERN] [--glob] [--case-sensitive]
           [--under <PATH>] [--task <ID>]
           [--type <f|d>] [--min-size <SIZE>] [--max-size <SIZE>]
           [--sort <path|size|mtime>] [--reverse]
           [--limit <N>] [--local] [--long] [--json]
```

别名 `qxync search`。`--link` 选连接；`--via-daemon` 会被明确拒绝（本命令纯本地）。

| 参数 | 默认 | 语义 |
|---|---|---|
| `PATTERN` | 全部 | 子串（默认）/ glob（`--glob`） |
| `--glob` | 关 | 通配符模式 |
| `--case-sensitive` | 关 | 大小写敏感 |
| `--under` | 全部 | 只搜这棵子树；远端路径或挂载点本地路径 |
| `--task` | 全部 | 只搜这个任务（root 前缀），并优先用它做 `--local` 映射 |
| `--type` | 全部 | `f` / `d` |
| `--min-size` / `--max-size` | 无 | 1024 进制 K/M/G/T |
| `--sort` / `--reverse` | `path` | `path` 升序；`size`/`mtime` 默认降序 |
| `--limit` | 100 | `0` = 全部 |
| `--local` | 关 | 输出挂载点里的本地路径（映射不到回退远端路径，stderr 提示一次） |
| `--long` | 关 | `类型 大小 时间 路径`（复用 `human_size` / `format_unix_secs`） |
| `--json` | 关 | 结构化输出（见下） |

输出（人读）：

```text
$ qxync find 防火墙 --limit 2 --local
/home/kami/qxync/default/qsync/0.1+X/5.课件/1+X防火墙安全配置-外发.pdf
/home/kami/qxync/default/qsync/2024/06-台州实训室/…/三级.1.2.2.Windows防火墙和远程访问安全配置

$ qxync find --under /home/.Qsync/2026/29-四川赛 --sort mtime --limit 3 --long
f   53.9 KiB  2026-10-28 14:53:24  /home/.Qsync/2026/29-四川赛/04-大数据/03-赛题/…zip
f  446.4 KiB  2026-10-28 14:53:24  /home/.Qsync/2026/29-四川赛/04-大数据/03-赛题/…zip
f      165 B  2026-10-28 11:03:27  /home/.Qsync/2026/29-四川赛/00-汇总资料/.~04-软件清单-2.xlsx
```

`--json`（字段名是稳定契约，脚本按它们判断）：

```json
{
  "pattern": "防火墙",
  "under": null,
  "total": 49,
  "truncated": true,
  "hits": [
    {
      "path": "/home/.Qsync/0.1+X/5.课件/1+X防火墙安全配置-外发.pdf",
      "local_path": "/home/kami/qxync/default/qsync/0.1+X/5.课件/1+X防火墙安全配置-外发.pdf",
      "task_id": "qsync",
      "size": 2031348,
      "mtime": 1718181584,

      "is_dir": false,
      "origin": "remote"
    }

```

退出码：`0` 正常（含 0 命中）；`1` 参数错误 / 状态库不存在或读不了。
截断提示与「本地路径映射不到」提示都写 **stderr**，stdout 保持可管道。

## 4. 边界与失败模式

* **状态库不存在** → 退出码 1，错误里带库路径与「先跑一轮 `qxync sync --once`」提示；
  绝不新建库；
* **状态库为空**（从未对账）→ stderr 说明 + 0 命中 + 退出码 0；
* **`present=0` 墓碑不返回**；本地已删但尚未对账的文件可能仍出现（状态库是缓存）；
* **`--task` 未知** → 退出码 1（错误里带任务 id）；`--task` 属于别的连接也拒绝；
* **`--under` 不是绝对路径** → 参数错误（不猜）；
* `--local` 但任务缺失/根对不上 → 回退远端路径，只提示一次；
* 只读打开 WAL 库：与 GUI/purge 预览同一条路径（`Store::open_readonly`，5s busy_timeout），
  失败给出可读错误而不是 panic；
* 大库扩展性：当前 O(n) 装载 + 过滤（3.4 万条端到端实测 **97 ms**，含进程启动与
  SQLite 读取）；20 万条以上可考虑按 `--under` 前缀先走 SQL 预筛（§8）。

## 6. 为什么不复用系统级「目录数据库」

| 候选 | 为什么不 |
|---|---|
| `plocate`（本机 1.9 GB 索引） | 实测**覆盖不到** `/home/kami`（`plocate /home/kami/.bashrc` 无结果），仓库/挂载点全不在索引里 |
| Baloo（KDE 内容索引） | 本机没装；而且 qxync 文档本来就要求把挂载点**排除**出 Baloo（M23：内容索引 = 读内容 = 全量水合），天生冲突 |
| 现扫挂载点（`find`/`rg`） | 需要挂载 + daemon；按需挂载下每次 `readdir`/`stat` 都可能打 NAS，断网直接不可用 |

状态库本来就在本地、且是同步逻辑的权威缓存 —— 用它最省事，也最符合「离线可用」的目标。

## 8. 后续（明确不做进 M42）

1. **GUI 搜索框**：`qxync-core::search` + `Store::search` 已是纯函数/只读入口，GUI 可直接
   复用（`qxync-gui` 本来就有 `open_readonly` 的用法）。
2. **内容搜索**：FTS5 trigram 或读缓存内容建立增量索引；复杂度、隐私、增量维护都远超
   本里程碑，单独立项。
3. **缓存状态列**（`--cached`）：读 `.qxstate` 位图判断「已水合、离线可读」，对
   「断网时哪些文件能打开」很有用。
4. **大库优化**：`--under` 前缀走 SQL 预筛（现在 3.4 万条没必要）。
5. **更多维度**：`--changed-within 7d`、按 owner/扩展名、按任务分组输出。

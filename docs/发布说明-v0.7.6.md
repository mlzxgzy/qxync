# v0.7.6 —— WPS 保存 + Dolphin 复制，两处 FUSE 兼容修复

> 发布日期：2026-10-21
> 上一版：[v0.7.5](发布说明-v0.7.5.md)（断网不再刷屏报错 + 托盘三色状态点）
>
> **双点修复版**：① WPS 表格保存不再报
> 「在替换目标文件时发生错误！(0x80000008)」—— FUSE 层补上 `O_TMPFILE` 与
> `link`（WPS / 新版 LibreOffice / Qt 5.14+ `QSaveFile` 的原子保存路径）；
> ② Dolphin 复制不再报「磁盘上没有足够的空间写入 …」—— 补上 `statfs`，
> 回缓存盘真实空间。另含两处顺手加固：`renameat2` 的 flags 不再静默忽略
> （`RENAME_EXCHANGE` 原先会被当普通 rename 执行 = 静默数据丢失，现明确回
> `EINVAL`），fuser 的诊断日志接进 daemon 日志（原先全部静默蒸发）。

**升级注意（本版与以往不同）**：两个修复都在 FUSE 挂载层，而挂载线程在
qxyncd 里 —— `systemctl --user reload qxyncd`（SIGHUP）只重载同步引擎，
**不够**；要完整 stop/start daemon（或退出托盘 GUI 再启动，它会一并重启
挂载）。重启期间挂载点闪断一下，Dolphin 按 F5 即可。设置文件零迁移。

## 一句话

两个报错都是「桌面程序用了 qxync 没实现的 FUSE 操作」：

```text
WPS 保存   ：open(O_TMPFILE) 写内容 → linkat 原子替换目标 —— 两步都没实现
             （errno 95 / errno 1），所以每次保存都报 0x80000008；
             LibreOffice 用「命名临时文件 + rename」，rename 一直好的，
             所以同一个文件 LibreOffice 能存、WPS 不能。
Dolphin 复制：复制前先查目标挂载剩多少空间（statfs）—— 没实现，回的全是 0，
             KIO 看到 0 直接判磁盘满；cp 不做这个检查，所以命令行一直好的。
```

## 〇、怎么用（什么都不用做）

```text
升级 + 完整重启 daemon 后：

WPS 里改表格 → Ctrl+S：
  之前 ：❌ 弹「WPS表格 在替换目标文件时发生错误！(0x80000008)」
  现在 ：✅ 正常保存（本地立即生效，NAS 异步上传）

Dolphin 往挂载点里复制文件：
  之前 ：❌ 弹「磁盘上没有足够的空间写入 file:///…」（df 显示 0 B 可用）
  现在 ：✅ 正常复制；df / Dolphin 状态栏显示缓存盘的真实剩余空间
```

## 一、WPS 保存报错：为什么、修了什么

### 根因（真机诊断实测）

WPS 的原子保存是两步：`open(目录, O_TMPFILE)` 写入新内容（临时文件**没有
名字**，崩溃不留垃圾），然后 `linkat(fd, "", 目录, 名字, AT_EMPTY_PATH)` 把
它原子地接到目标名上。qxync 两步都不支持：

| 操作 | 真机实测 | 原因 |
|---|---|---|
| `open(O_TMPFILE)` | **errno 95（EOPNOTSUPP）** | fuser 0.17 的 opcode 枚举只到 47；内核协议 7.37 发来 `FUSE_TMPFILE`(51) 时解析失败 → 回 ENOSYS → 内核转 `EOPNOTSUPP` |
| `link()` | **errno 1（EPERM）** | qxync 压根没实现 link，fuser 默认拒绝 |
| `rename()`（LibreOffice 的路径） | ✅ 一直正常 | 早就实现了 |

诊断脚本（`.local-run/wps_save_diag`）在真机上把三个 syscall 各测一遍，
 errno 与预期完全吻合 —— 这也是「LibreOffice 能存、WPS 不能」的直接解释。

### 修法（三层）

| 层 | 改动 | 说明 |
|---|---|---|
| **vendor/fuser**（`[patch.crates-io]` 本地补丁） | opcode 枚举补 `FUSE_TMPFILE = 51`，新增 `Operation::TmpFile` 解析（请求体 = `fuse_create_in`、无名字参数，与 FUSE_CREATE 同构）与 `Filesystem::tmpfile()` 回调 | 默认实现回 ENOSYS，内核据此回 `EOPNOTSUPP` —— 与上游未打补丁时行为一致，别的 fuser 用户不受影响；`FUSE_STATX = 52` 显式回 ENOSYS 保持原状。上游修复合入发布版后可移除此补丁 |
| **`tmpfile()` 实现** | 建「未命名」节点：`Node.unnamed` —— 空 remote、不进 `by_remote`、不进目录清单、`mark_dirty` 只置脏不入队 | 缓存文件用 `tmpfile-<ino>.cache`；`release()` 时仍未命名（写了但没 link）→ 整个丢弃（节点 + 缓存），不留垃圾 —— 正是 O_TMPFILE 的语义 |
| **`link()` 实现** | 对未命名节点 = **物化**：搬名字、迁缓存、进清单、标脏上传 | 这正是 `linkat(AT_EMPTY_PATH)` 的语义；对普通节点 = **复制语义**（NAS 协议没有硬链接，与 CIFS 等网络文件系统同例：新节点 + 拷贝缓存 + 上传）。目标已存在 → `EEXIST` |

## 二、Dolphin 复制报「磁盘没有足够空间」：为什么、修了什么

### 根因

挂载点从未实现 `statfs`，走 fuser 默认值（blocks / bfree / bavail 全 0），
于是 `df -h` 显示 0 B 可用。而 Dolphin/KIO 在复制**前**会按目标挂载的可用
空间做检查（`FileSystemFreeSpaceJob`），看到 0 直接判 `ERR_DISK_FULL` ——
「磁盘上没有足够的空间写入 file:///…」。写入实际落在本地缓存盘（空间充足），
`cp` / qxync put 不做 statvfs，所以「命令行可以、Dolphin 不行」。KDE bug
492108 里没回真实 statfs 的 davfs2 挂载是同一症状。

### 修法

`Filesystem::statfs` 对 cache_dir 跑 `statvfs(3)` 并映射到 FUSE 字段：

- 缓存目录尚未创建时沿祖先目录找第一个存在的（挂载早于建目录的竞态）；
- 块粒度优先 `f_frsize`（`df` 也按它算），为 0 时退回 `f_bsize`；
- `f_namemax` 为 0 时按惯例兜底 255，别回 0。

**报缓存盘而不是 NAS**：写入最终落进 cache_dir，「往这个挂载点写还剩多少」
就是缓存盘剩余；NAS 侧配额不在 statfs 语义里，由上传失败回报。量不到时
维持旧行为（全 0）并留一条 warn，不编造数字。

## 三、顺手加固的两处

- **`renameat2` 的 flags 不再静默忽略**：原先 `RENAME_EXCHANGE` 被当普通
  rename 执行 —— 源名字的内容被覆盖而不是交换，等于**静默数据丢失**。NAS
  协议做不了原子交换（3 步换名有中间态），按网络文件系统惯例（sshfs/CIFS
  同样不支持）明确回 `EINVAL`；`RENAME_NOREPLACE` 目标已存在时回 `EEXIST`
  （内核通常已挡，兜底）。
- **fuser 的诊断日志不再蒸发**：fuser 用 `log` crate 输出（「[Not Implemented]
  link(...)」「Unknown FUSE opcode」等），而 daemon 只初始化 `tracing` ——
  两者之间没有桥，**所有 fuser 层错误全部静默丢弃**（本次故障查了整轮日志
  零线索的直接原因）。daemon 启动时装 `log` → `tracing` 桥（target=`fuser`），
  以后这类问题日志里直接可见。

## 五、已知边界

* **生效需要完整重启 daemon**（stop/start 或重启 GUI，`reload` 不够）——
  挂载线程在 qxyncd 里，SIGHUP 只重载同步引擎；
* 普通文件的 `link()` 是**复制语义**（新 inode、各自独立），不是真硬链接 ——
  NAS 协议没有硬链接，与 CIFS 等网络文件系统同例；`ln` 会成功，但改一份
  不会同步另一份；
* `O_TMPFILE` 写了不 link 就关闭的内容**不保留**（这正是该 syscall 的语义，
  WPS 自己也依赖它来避免留垃圾）；
* statfs 报的是**缓存盘**空间：缓存盘满了写入会失败，即使 NAS 还有空间 ——
  这是缓存优先架构的固有语义（v0.7.6 只是让数字变真实了）；
* vendor/fuser 补丁在上游发布修复后可移除（`Cargo.toml` 的
  `[patch.crates-io]` 段有注释标记）。

# qxync v0.3.0 —— 一对多删除，只剩一对一；NAS 文件夹改成下拉选

**中文** · [English](#english)

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](https://github.com/mlzxgzy/qxync/blob/master/LICENSE-MIT)

**⚠️ 破坏性版本：`roots` / `home_root` 两个配置字段与多根挂载都已删除。**
NAS 上的数据、缓存、baseline、凭据都不受影响，但挂在旧配置上的用法要按下面改一遍
（三行表格，见 [README §2.6](https://github.com/mlzxgzy/qxync/blob/master/README.md#26-从-02x-升级一对多删了)）。

## 为什么要删

「一个本地文件夹 ⇄ 多个 NAS 目录」在概念上就不成立：多根时挂载点会被当成虚拟根，
顶层多出一层用目录名拼出来的目录（本地 `~/qsync` 配 NAS `/home`，结果里面又出现
`~/qsync/home/`）。Qsync 自己的「配对文件夹」就是一对一的，所以这一版把它删干净：
**一个挂载点 = 一个 NAS 文件夹**，挂载点里**直接**就是那个文件夹的内容。
要同步多个 NAS 文件夹就建多个任务 —— 多任务本来也更清楚：每个任务有自己的本地文件夹、
冲突策略、方向与开关。

## 删了什么

| 层 | 删掉的东西 |
|---|---|
| 配置 | link 里的 `roots`、`home_root`（连接页「高级」栏整块消失，表单只剩 host / port / user / password / https / insecure / ipv4-only） |
| 命令行 | `mount --remote A --remote B`、`task add --root A --root B` —— 这两个参数现在只能给一次 |
| FUSE | 多根虚拟根（`ViewLayout::Multi` / `RootSpec` / `new_multi` / `multi_root` 分支） |
| IPC | `MountInfo.roots`、`RootsData.configured` / `roots` / `home_root`、`RootInfo` |
| 任务 | `Task.roots: Vec<String>` → `Task.root: Option<String>`（一个任务一个 NAS 文件夹） |
| 验收 | `xtask/tests/m6-matrix.sh`（29 项多根矩阵）随功能删除 |

**旧文件怎么办**：任务 JSON 里只有一个 `roots` 条目 → 自动迁移成 `root`；
有多个条目 → 在任务列表里报成坏任务文件，错误信息写明「旧的多根格式，请为每个 NAS
文件夹各建一个任务」。**不会静默缩小同步范围**，这是刻意的：宁可吵，不可悄悄少同步。

## 新东西

**「NAS 文件夹」下拉 + 「浏览…」**。「文件夹对设置」里的 NAS 侧从「每行一个」的 textarea
变成一对一下拉：

* 候选来自 NAS 上登记的 Qsync 同步文件夹（`qbox_get_syncing_folder_list&detail=1`），
  并把共享路径换算成客户端能用的路径（`/share/homes/<用户>/x` → `/home/x`，
  有真机抓包的直接证据）；
* 选不到就点「浏览…」逐层挑（复用文件页的 `ls`），或选「手动输入」兜底任意路径。

## 一并修掉的两处

* **`qbox_get_syncing_folder_list` 的真机字段一直解析错了**：真机回的是
  `name` / `path` / `privilege`，旧代码按项内 `folder` / `permission` 读 —— 于是只要 NAS
  上真登记了同步文件夹，界面就会显示成「空名字 + 0 权限」，把**能列举**误判成**列不出来**。
  这也是当初 NAS 目录只能手打的真正原因。现在两种拼法都认，并补了真机响应原文的回归测试。
* **能不能写不再由客户端预判**：以前按「是不是家目录」一刀切成只读，那是错的判据 ——
  能写的判据在 NAS 侧（目录有没有被登记成 Qsync 同步文件夹）。现在勾了「读写」就按读写挂，
  真被服务端拒绝（`status:20`）由上传队列与「更新 / 错误」页如实报出来。

## 升级

1. 如果还有多根挂载点挂着：`qxync umount <挂载点>`，升级后按一对一重新配（每个 NAS 文件夹
   一个挂载点 / 一个任务）。
2. 任务文件不用手改：单个 `roots` 会自动迁移；多个 `roots` 的任务会在列表里报错，照着提示
   拆成多个任务即可（本地文件夹也要各用各的，嵌套挂载会互相遮挡，提交时会检查）。
3. 连接配置里的 `roots` / `home_root` 字段会被忽略，不需要删（删了也行）。

已有任务的本地缓存、baseline、pin、上传队列**都不动** —— 路径键本来就是远端路径，
一对一之后这个前提没变。

## 验证

* `cargo check --workspace --all-targets`：无 error / 无 warning；`cargo test --workspace --lib`：**160/160**
* `xtask/tests/pair-1to1.sh`（**新增，不需要 NAS、不需要 FUSE**）：**17/17** —— 一对一登记 ·
  `--root` 给两次被拒 · 本地文件夹重复/嵌套被拒并点名任务 · 同一 NAS 文件夹只 warning ·
  旧文件单个 `roots` 自动迁移 / 多个 `roots` 报错
* `qxync-gui --self-test` 的 `ui_spec`：无 HTML 拼接、文案表两边缺词 0、a11y 9 项全绿
* 真机矩阵（`fuse-matrix` / `m82-matrix` / `gui-matrix`）本版**未复跑**，如实记在
  [验收记录](https://github.com/mlzxgzy/qxync/blob/master/docs/验收记录.md)

## English

**⚠️ Breaking release: the `roots` / `home_root` config fields and multi-root mounts are gone.**
Nothing on the NAS (data, cache, baseline, credentials) is affected; the three-line migration
table is in [README §2.6](https://github.com/mlzxgzy/qxync/blob/master/README.en.md#26-upgrading-from-02x-one-to-many-is-gone).

### Why

"One local folder ⇄ several NAS folders" never made sense: with multiple roots the mount point
became a virtual root with an extra top-level directory named after each root (mount `~/qsync` at
NAS `/home` and you got `~/qsync/home/` inside it). Qsync's own "paired folder" is one-to-one, so
this release deletes one-to-many for good: **one mount point = one NAS folder**, and the mount
point *is* that folder's content. To sync several NAS folders, create several tasks — which is
also clearer: each task has its own local folder, conflict policy, direction and switch.

### What was removed

* config: `roots` and `home_root` in the link (the Connection page "Advanced" section is gone; the
  form is host / port / user / password / https / insecure / ipv4-only);
* CLI: `mount --remote A --remote B` and `task add --root A --root B` — both flags now take one value;
* FUSE: the multi-root virtual root (`ViewLayout::Multi` / `RootSpec` / `new_multi` / `multi_root`);
* IPC: `MountInfo.roots`, `RootsData.configured` / `roots` / `home_root`, `RootInfo`;
* tasks: `Task.roots: Vec<String>` → `Task.root: Option<String>`;
* `xtask/tests/m6-matrix.sh` (29 multi-root items) went away with the feature.

**Old files**: a task JSON with a single `roots` entry migrates to `root` automatically; several
entries are reported as a bad task file telling you to create one task per NAS folder. The sync
scope is **never silently narrowed** — noisy beats quiet here.

### What is new

**A "NAS folder" dropdown plus "Browse…".** The NAS side of Folder Pair Settings is no longer a
one-per-line textarea:

* candidates come from the Qsync sync folders registered on the NAS
  (`qbox_get_syncing_folder_list&detail=1`), with the share path mapped to the path the client can
  use (`/share/homes/<user>/x` → `/home/x`, backed by a real-machine capture);
* if that is not enough, "Browse…" walks the tree (reusing the Files page `ls`), and "type
  manually" accepts any path.

### Two fixes that came along

* **`qbox_get_syncing_folder_list` never parsed the real-machine fields**: the NAS returns
  `name` / `path` / `privilege`, while the old code read the item-level `folder` / `permission` —
  so as soon as the NAS really had a sync folder registered, the UI showed "empty name + 0
  permission" and mistook *listable* for *not listable*. That is why the NAS folder used to be
  type-only. Both spellings are accepted now, with a verbatim regression test.
* **Writability is no longer pre-judged by the client**: the old guard cut everything that was not
  the home directory down to read-only, which was the wrong test — the NAS decides (is the folder
  registered as a Qsync sync folder?). Ticking "read-write" now mounts read-write; if the server
  refuses (`status:20`) the upload queue and the Updates / Errors page report it verbatim.

### Upgrading

1. If a multi-root mount is still mounted: `qxync umount <mountpoint>`, then re-create it
   one-to-one (one mount point / one task per NAS folder).
2. Task files need no hand-editing: a single `roots` migrates; a task with several will be
   reported as bad — split it as the message says (each task also needs its own local folder;
   nested mounts hide each other and are rejected on submit).
3. `roots` / `home_root` in the connection config are ignored — no need to delete them.

Local caches, baselines, pins and upload queues are untouched: they were always keyed by remote
path, and one-to-one does not change that premise.

### Verification

* `cargo check --workspace --all-targets`: no errors / no warnings; `cargo test --workspace --lib`: **160/160**
* `xtask/tests/pair-1to1.sh` (**new; no NAS, no FUSE needed**): **17/17**
* `qxync-gui --self-test`'s `ui_spec`: no HTML string building, zero missing i18n keys, all 9 a11y
  checks green
* The real-NAS matrices (`fuse-matrix` / `m82-matrix` / `gui-matrix`) were **not** re-run for this
  release — recorded as such in the acceptance log.

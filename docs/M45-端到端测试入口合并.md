# M45 端到端验收入口合并（五档 + 并行 + 去重 + 环境隔离）

> 用户原话：「commit 下本版，然后看看所有的 e2e 能不能化简一下或者合并一下，现在发布前的
> 测试提交太久了」。

这一轮没有改产品代码，只改「验收怎么跑」：把 `xtask/tests/` 下 19 个脚本 + 3 个 node 套件
登记成一张表，按档位取子集、能并行的并行、已被大矩阵覆盖的不重复跑；顺手修掉三处让
「跑验收」变成负担的真问题（下面 §1.3 / §1.4）。**脚本本体一行没合并**，理由见 §6。

## 1. 审计：先量再改

### 1.1 现状盘点

`xtask/tests/` 下 19 个 `*.sh` + 3 个 `*.test.mjs`，覆盖 M1～M44 的验收。按依赖可以分成
四层（这也是后来分档的依据）：

| 层 | 套件 | 依赖 |
|---|---|---|
| 单测 / 格式 | `cargo test --workspace --locked`、`cargo fmt --all --check` | 无 |
| 隔离 e2e（CI 同级） | `m19-purge`、`m20-offline`、`m21-offline-restart`、`m40-multipath`、`m42-search`、`pair-1to1`、3 个 node 源文本单测 | python3 / sqlite3 / jq / node / `target/debug` 二进制；`m21` 另需 `/dev/fuse` |
| GUI | `gui-matrix`（另含真机登录）、`gui-task-defaults`、`gui-purge`、`m33-dl-toast-gui` | chromium / DISPLAY / 真机凭据 |
| 真机 | `fuse-matrix`、`m5` / `m7` / `m82` / `m83` / `m84-matrix`、`m20/m21/m40-real-nas` | `/dev/fuse`、测试连接凭据、本地夹具 |

### 1.2 实测耗时（本机，2026-10-29）

| 套件 | 耗时 | 备注 |
|---|---|---|
| `m40-multipath` | **16s** | 全套最慢的隔离套件（Python 假 NAS + 多条选路/冷却/切回） |
| `m20-offline` | 6s | 不可达 NAS + 跨 daemon 重启 |
| `m19-purge` / `m42-search` / `pair-1to1` | 各 1s | |
| 3 个 node 单测 | 各 1s | 纯源文本级，无浏览器 |
| `gui-task-defaults` / `gui-purge` / `m33-dl-toast-gui` | 各 1s | chromium `--headless=new --dump-dom` |
| `gui-matrix --no-window` | **14s** | 真机登录 + self-test + 4 个内部子套件 |
| `gui-matrix`（全量，含 9 目的地截图） | ~2min | 脚本自报；本轮未跑（会在你桌面上开 20 次窗口） |
| `fuse-matrix` 快测 / `m5` / `m7` / `m82` / `m83` / `m84` / 三个 real-nas | — | **本环境无法验证**（无 `/dev/fuse`；真机档会往真 NAS 测试目录写），耗时取自脚本自报：快测 ~30s，其余各 1～5min |

结论：**单跑都不慢，慢在「怎么跑」**——发版前人肉一个个敲、串行叠加、还要记住哪些需要
什么环境；而全套里既有重复执行，又有 4 个脚本会动到你自己的守护（§1.3）。

### 1.3 真问题一：验收会把你正在同步的 daemon / 托盘杀掉

`gui-matrix.sh` 的设计假设是「本脚本独占本机 qxyncd」，于是：

```bash
pkill -x qxyncd     # 起 daemon 前清场（gui-matrix / m82 / m83 / m84 共 8 处）
pkill -x qxync-gui  # 开窗口前清场（gui-matrix / m84）
```

`pkill -x` 是按**进程名**杀，不区分 socket / 配置目录 —— 跑一次验收，桌面上正在同步的
守护和托盘一起没了。**2026-10-29 真事故**：维护者跑 `gui-matrix.sh --no-window` 做本轮
验证时，自己的 daemon 被脚本停掉（日志里是 `收到 shutdown 请求（IPC）`）。

同时 `gui-matrix` 把 daemon 起在 `$RUNDIR/gui-matrix.sock`，而 GUI 只认
`$XDG_RUNTIME_DIR/qxync/qxyncd.sock`（M16 之后的已知问题，见 `docs/验收记录.md` 里那条
「GUI 的 default socket 只看 `$XDG_RUNTIME_DIR`」）——于是「daemon 不在时 self-test 必须
失败」这条负向对照，在你**有** daemon 在跑时永远失败。

### 1.4 真问题二 / 三：scratch 状态与测试配置会「越跑越脏」

* `gui-matrix` 的状态目录（`.local-run/state`）里留着**过期的 NAS 身份 UID**；M40 的身份
  守卫会把它当「这条路径指向了另一台 NAS」直接禁掉 → 登录失败。同一台机器上表现为
  「有时能过、有时过不了」。
* 测试配置目录 `.local-run/config/qxync/links/` 里留着历史连接 `m6.json`（同 host / 端口 /
  账号的第二个连接）；`login_flow` 见到重复连接会**直接拒绝登录** → `--self-test-login`
  永远失败。而且自检会写 link / 凭据 —— 直接跑在源配置上等于让验收改配置。

## 2. 设计：合并「跑法」，不合并断言

新增 `xtask/tests/e2e.sh`，一张注册表 + 五档 + 四个执行阶段：

```text
套件注册表（name | tier | needs | timeout | 说明）
   tier  : unit / fast / gui / fuse / nas
   needs : fuse / chromium / display / node / python3 / sqlite3 / jq / creds / realnas / fixture
   另有一条 covers 关系：gui-matrix 内部已跑过 m19 / gui-task-defaults / gui-purge /
   M18·M28 源文本单测，m84 内部跑过 M28 源文本单测 → 同一轮里不重复跑

档位：gate(默认)=unit+fast   fast=隔离 e2e   gui / fuse / nas = 对应真机层   all=全部
执行：unit → fast(并行 jobs) → gui(串行) → fuse(串行) → nas(串行)
输出：每个套件一份日志 + 汇总表 + 失败自动贴日志尾部 + 退出码
```

四个刻意的选择：

1. **档位默认 gate**：日常提交/发版只跑「单测 + 隔离 e2e」，实测 **24s**；真机/GUI 档按改动
   路径点跑（§4 映射表）。这就是「发布前测试太久」的直接解法 —— 不是把断言删掉，而是
   把「每次都必须跑」和「改了才要跑」分开。
2. **能力探测 + 显式 SKIP 理由**：缺 `/dev/fuse`、缺测试凭据、缺 chromium 都只 SKIP 并
   打印缺什么，不会出现「跑了 10 分钟，最后 8 个 FAIL 全是环境问题」。
3. **并行只给 fast 档**：隔离套件各自 XDG/socket/端口，实测并行 4 把 9 个套件从 ~28s 压到
   **18s**；gui / fuse / nas 串行（共用真机凭据与 NAS 目录，并行会互相踩）。
4. **守护保护**：入口在跑之前记下你桌面上 `qxyncd` 的 pid，跑完核对；任何一个套件把
   它带走 → 退出码 **3** 并指名疑似加害者。这是把 §1.3 的事故变成「会被 CI/人看见的
   失败」，而不是无声无息。

## 3. 改了哪些文件

| 文件 | 改动 |
|---|---|
| `xtask/tests/e2e.sh` | **新增**：注册表 / 五档 / 并行 / 去重 / 能力探测 / 汇总 / 守护保护 |
| `xtask/tests/gui-matrix.sh` | 私有 `XDG_RUNTIME_DIR`（daemon 起在 default socket 上，GUI 才找得到）+ 私有配置副本（只复制本连接）+ **删掉 8 处 `pkill -x`**（只停自己 socket 上的 daemon、只收自己窗口）+ 开跑前清过期 NAS 身份记录 |
| `xtask/tests/m82-matrix.sh` / `m83-matrix.sh` / `m84-matrix.sh` | 同上：`pkill -x qxyncd` → `qxync --socket <自己的 socket> daemon stop --force`；`pkill -x qxync-gui` → kill 自己的 pid |
| `.github/workflows/ci.yml` | 7 个 step（2 node + M19/M20/M40/M42/M21）→ **1 个 step**：`bash xtask/tests/e2e.sh --tier fast --jobs 4`；FUSE `user_allow_other` 那步保留 |
| `CONTRIBUTING.md` / `.github/PULL_REQUEST_TEMPLATE.md` / `docs/发布清单-v0.1.0.md` | 复跑指引改成「先跑 gate，再按改动路径点档」 |
| 本文 + `CHANGELOG` 中英 + `docs/验收记录.md` + `docs/开发规划.md` | 记录 |

`gui-matrix` 的私有化细节：

* `XDG_RUNTIME_DIR=$RUNDIR/runtime`，daemon 的 socket 就是 GUI 认的 default 路径；
  runtime 目录里其它条目（`wayland-1`、`bus`…）用符号链接透传 —— 窗口照常能开，但
  你桌面那台 daemon 与它互不可见。
* `XDG_CONFIG_HOME=$RUNDIR/guicfg`，从源配置（默认 `$REPO/.local-run/config`，即测试连接；
  显式设了 `XDG_CONFIG_HOME` / `QXNYC_TEST_SRC_CONFIG` 才用你指定的）**只复制本连接**的
  link + 凭据；自检写文件也只写这份副本，绝不改动源配置。

## 4. 用法与档位映射

```bash
bash xtask/tests/e2e.sh                 # gate：单测 + 格式 + 隔离 e2e（24s）
bash xtask/tests/e2e.sh --tier fast     # 只跑隔离 e2e（CI 用，18s）
bash xtask/tests/e2e.sh --tier gui      # GUI：4 个套件（含 gui-matrix 真窗口 2min）
bash xtask/tests/e2e.sh --tier fuse     # 真 FUSE 挂载矩阵
bash xtask/tests/e2e.sh --tier nas      # 真机 NAS 矩阵（测试连接，会写测试目录）
bash xtask/tests/e2e.sh --tier all      # 全部（缺环境的自动 SKIP）
bash xtask/tests/e2e.sh --list          # 看注册表
bash xtask/tests/e2e.sh --only m42-search,gui-purge   # 点名跑
```

「改了哪块跑哪档」：

| 改了什么 | 至少跑 |
|---|---|
| 文档 / 注释 / 打包脚本 | `e2e.sh`（gate） |
| CLI 输出、隔离 XDG 行为 | `e2e.sh`（gate） |
| `ui/` 任意文件 | `--tier gui` |
| FUSE 读 / 写 / 水合 / 脱水 | `--tier fuse` + `--tier gui`（GUI 也读 FUSE 状态） |
| 同步引擎 / 状态库 schema / 任务登记 | `--tier nas`（含 `m5` / `m82` / `m83`） |
| 多路径 / DDNS / 连接管理 | `--tier nas`（含 `m40-real-nas`） |

老脚本都还能单独跑（一个字节都没改语义），只是「发版前该跑什么」以入口为准。

## 6. 边界：为什么没有把 19 个脚本合并成几个大文件

「合并脚本本体」的收益是少几个文件，代价有三条，都不划算：

1. **它们不是同一种测试**：`m19` 是隔离 XDG 的 CLI e2e，`m84` 是真机 + 真挂载 + GUI 托盘，
   `fuse-matrix` 是 FUSE 语义矩阵。合并只会得到三个巨型 case 分支，可读性反而更差。
2. **断言是历史验收证据**：`docs/验收记录.md` 与各 `docs/M*.md` 都是按「脚本名 + 断言数」
   引用的（例如「`m84-matrix.sh` 92/92」）。合并后引用全断，review 也没法逐条对照。
3. **风险面**：这些脚本里有真机写操作、挂载、窗口操作，重写等于把已验证的流程全部重来
   一遍，却没有新覆盖。

所以合并的是**跑法与门禁**（入口、档位、并行、去重、隔离、汇总），不是断言。新增套件
仍然写在各自脚本里，同时在 `e2e.sh` 注册表加一行。

## 7. 迁移对照（老命令 → 新入口）

| 老做法 | 新做法 |
|---|---|
| 发版前手敲 `m19` / `m20` / `m40` / `m42` / `m21` | `bash xtask/tests/e2e.sh`（24s） |
| CI 里 7 个 step | 1 个 step：`e2e.sh --tier fast --jobs 4` |
| 全量人肉串行跑 19 个脚本 | `--tier all`（并行 + 去重 + 自动 SKIP） |
| 跑完自己数哪几个没过 | 汇总表 + 失败自动贴日志尾部 |
| `gui-matrix` 跑一次把自己的 daemon 杀了 | 不会了；万一还有套件这么干，入口退出码 3 并点名 |
| `gui-matrix` 在「有 daemon 的桌面」上负向对照恒失败 | 私有 runtime，真机自检 43/43 |

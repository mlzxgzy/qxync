# v0.7.14 —— 日志降噪（同样的诊断信息，体积砍掉 96%）

> 发布日期：2026-10-28
> 上一版：[v0.7.13](发布说明-v0.7.13.md)（多路径连接与失败自诊断）
>
> **降噪版，没有新功能**：这一版只改「日志里写什么」，不改数据格式、不改 IPC、
> 不改配置。上一版（[M39](M39-日志轮转与保留.md)）管住的是「日志文件多大、留几天」；
> 这一版管的是「每天写进去的内容有多吵」—— 真机三天日志里 **九成以上的字节都在
> 重复同一批内容**。把同一批真机日志按新规则离线重放：**16.35 MB → 0.58 MB（-96%）**。
>
> 默认 `INFO` 下真正需要的信息（首次、变化、恢复、计数）一条不少；逐条明细在
> `RUST_LOG=debug` 时原样写盘。升级只需装新二进制 + 重启 daemon。

## 一句话

```text
升级 + 重启 daemon 后：
  → 日志按「同一句话 + 同一个原因」限流：首次一条，之后每个窗口只留一条，并附带
    「过去一个窗口内另省略 N 条同类」——不再一条路径一行、一条文件一行
  → 轮询异常 / 会话失效 / 上传暂停 / outbox 回放中断改成「状态变化时才一条」：
    断网 10 分钟不再是 600 条 WARN，而是「进入离线」和「恢复在线」两个事件
  → 逐目录对账失败：每轮最多 3 条样本 + 1 条「本轮另有 N 条」汇总，其余只写 debug
  → 空转「同步轮询」降成 10 分钟心跳；逐文件「已上传」收成每分钟一条汇总；
    删除名单截断到 120 字符
  → 真机三天日志 16.35 MB → 0.58 MB（-96%），单日降幅 -87% ~ -99%
  → 要看逐条明细：RUST_LOG=debug（或 --log-level debug）时一条不少
  → 数据 / IPC / 配置零变更：qxync status、GUI 错误列表、更新中心内容都不变
```

## 一、起因：日志文件不涨了，但内容还是重复的

用户原话：

> 「现在日志的数据量也太大了，看看能不能砍一些。」

[M39](M39-日志轮转与保留.md) 之后日志不会长成 5 GB 了（按天 + 按大小切段，
14 天 / 总量 256 MiB 自动清理）。但**每天写进去的字节**仍然以重复为主 ——
同样的真机现场（只读取证，2026-10-27）：

| 日期 | 日志文件 | 其中最大的重复类 |
|---|---:|---|
| 10-25 | **11.19 MB / 5.66 万行** | `创建缓存文件失败 … Too many open files` **48 983 行 / 10.33 MB**（每条只差一个路径；fd 泄漏是另一个问题） |
| 10-26 | **4.46 MB / 1.90 万行** | 逐目录 `对账列举失败` 3 677 行、断网时逐文件 `上传暂停` 941 行、逐文件 `已上传` 1 022 行 |
| 10-27 | **0.71 MB / 0.24 万行** | 逐目录 `对账列举失败` 1 260 行、`轮询有异常` 33 条（每条 1.8 KB，把整串 errors 数组再抄一遍） |

### 重复长什么样

```text
# ① 同一句错误 + 不同路径（fd 泄漏时按文件刷）
2026-10-26T06:30:24Z ERROR qxync_fuse: 创建缓存文件失败 …/8964b47bda098aa0___.xlsx: Too many open files (os error 24)
2026-10-26T06:30:24Z ERROR qxync_fuse: 创建缓存文件失败 …/7c1e…xlsx: Too many open files (os error 24)
…（同一天 7 018 条；10-25 是 48 983 条）

# ② 每轮每个目录一条，内容只差「第 N/M 个」
2026-10-27T08:01:14Z  WARN qxyncd::sync: 同步引擎: 同步「qsync」对账列举失败…（第 47/5245 个目录）→ …

# ③ 同一批错误被「再抄一遍」（单行 1.8 KB）
2026-10-27T01:37:05Z  WARN qxyncd::daemon: 轮询有异常: conflicts=0 blocked=0 errors=["…第 56/5418…", "…第 57/5418…", …]
```

一句话：**信息量是一句话，体积是几 MB。**

### 为什么不是「把日志级别调低」

* **级别调低会把「第一次」也藏掉**：把 `已上传` 改成 debug 省事，但以后排查
  「这个文件到底传上去没有」就少了一条线索；这里压掉的是**第 2..N 次重复**。
* **保留策略不解决写入量**：`log_max_total_mb` 只是把「几天前的重复」删掉，
  当天的盘写入与 journal 事件量不变。
* **告警要按事件记，不按状态记**：断网 10 分钟不是「600 条 WARN」，是「进入离线」
  「恢复在线」两个事件。

## 二、修法：四件事

### 2.1 地基：同签名限流（新模块 `qxync_core::noise`）

同一 `(站点, 签名)` 只放行「首次 + 每窗口一条」（默认窗口 60s），放行的那条带上
「过去一个窗口内另省略 N 条同类」。语义刻意简单：

| 情况 | 结果 |
|---|---|
| 该签名第一次 | 放行（省略数 0） |
| 窗口内再出现 | 压掉，内部计数 +1（调用方仍写 `debug!` 留全量） |
| 窗口到期后的第一次 | 放行，并报出上个窗口压掉的条数 |
| 故障恢复后再次发生 | `reset` 后**立刻放行**（复发不会被窗口吞掉） |

边界：**签名里绝不允许出现路径/数字/序号**（否则每条都是新键，等于没限流），
路径与具体值只出现在放行的那一条里；状态有界（最多 512 个签名，超了淘汰最旧的），
极端刷屏不会吃内存；锁中毒照样继续记日志；窗口用单调时钟，系统时间跳变不影响。

### 2.2 状态迁移式：四个「每轮刷」的点改成门闩

时间窗对「每轮一行」基本无效（轮询间隔 30~45s，60s 窗口几乎每轮都跨窗口）。
这几处改成**日志记事件、不记状态**：

| 门闩 | 管什么 | 语义 | 什么时候复位 |
|---|---|---|---|
| `AnomalyLatch` | 轮询有异常 | 异常签名变化才一条摘要 WARN；同签名持续只写 `debug!` 全文 | 无异常的一轮自动清状态 → 复发立刻再报 |
| `AuthLatch` | 轮询遇会话失效 | 只有「正常 → 失效」一条摘要；持续失效 `debug!` | 重登成功 / 恢复在线 |
| `ReplayInterruptLatch` | outbox 回放中断 | 每次打断一条（首个受阻 kind + path + 恢复方式） | 回放清空 / 成功 |
| `OfflineLatch` | 上传因网络不可用暂停 | 一次断网一条（带示例路径），断网期间每次 `debug!` | 任一次上传成功 |

共同的不变量是**不吞复发**：恢复后状态清空，下一次故障一定会再报一条。

### 2.3 聚合与截断

| 站点 | 旧行为 → 新行为 |
|---|---|
| 逐目录 `对账列举失败` | 每目录一条 WARN（10-27 1 260 行 / 295 KB）→ 每轮 **3 条样本**进 `errors`（GUI 可见）+ 轮末 **1 条**「本轮另有 N 条」汇总；其余 `debug!`。网络类失败**原样**走探活/中止逻辑 |
| 空转 `同步轮询: …` | 每轮一条 INFO（三天 3 775 行 / 0.73 MB）→ **有实际动作才 INFO**；空转降 `debug!` + **10 分钟心跳** |
| 逐文件「已上传」 | 每文件一条 INFO（三天 1 743 行）→ `debug!`；INFO 由 **60s 心跳**承担：「近一分钟上传完成 D 项 / B 字节（累计 …）」 |
| 逐条「离线操作已回放」/ 恢复未完成的上传·删除 | 逐条 INFO → 一条汇总 + 逐条 `debug!` |
| `已删除` / 父目录同批被删的名字名单 | 一行里拼全部名字（可能几 KB）→ 截到 **120 字符**（`…` 收尾），完整名单 `debug!` |
| 逐缓存文件的水合位图读取/落盘失败、删除熔断（`rm -rf` 逐项）、离线操作入缓冲 | 逐文件逐项 → 按签名 **60s（离线入缓冲 30s）一条** + 省略计数 |
| fuser 「[Not Implemented]」等诊断 | 逐条转写 → 归一化签名（首行 + 连续数字压 `#`）后 **10 分钟一条** |
| `accept 失败`（上一版那次 5.17 GB 洪水的来源） | 每 100ms 一条 → 按 **errno 60s 一条** |

最后一行是**顺手兜底**：即使 fd 再泄漏，最坏也只有 1 条/分钟（≈ **1.5 MB/天**），
不可能再复现「一天 5 GB」。

### 2.4 明确不动的边界

* **用户可见的错误语义不变**：`SyncReport.errors` 仍是「本轮错误清单」（上限 20 条），
  IPC / GUI 错误列表 / journal（更新中心）的内容与条数都不受影响；只是每轮 WARN 的
  **样本**限到 3 条 + 1 条汇总，完整清单仍在 `errors` 里。
* **不做**：全局日志级别调整、随机采样（会丢首次）、GUI 设置页 / `qxync log` 输出改动、
  保留策略默认值改动。
* **不把 `debug` 写进文件**：默认 `INFO` 过滤在 subscriber 层，逐条明细在
  `RUST_LOG=debug`（或 `--log-level debug`）时照旧写盘。

## 三、效果：同一批真机日志重放

方法：把**真机历史日志**当输入，按上面的新规则离线重算一遍输出
（脚本 [`xtask/probe/m41_log_volume.py`](../xtask/probe/m41_log_volume.py)）。

| 日志 | 旧 行 | 旧 字节 | 新 行 | 新 字节 | 降幅 |
|---|---:|---:|---:|---:|---:|
| 2026-10-25（fd 泄漏刷屏日） | 56 565 | 11 189 910 | 924 | 156 096 | **-99%** |
| 2026-10-26（断网 + 逐目录失败日） | 18 983 | 4 456 321 | 1 720 | 328 850 | **-93%** |
| 2026-10-27（逐目录 status=5 刷屏日；16:25 快照） | 2 463 | 707 898 | 543 | 91 248 | **-87%** |
| **合计** | **78 011** | **16 354 129** | **3 187** | **576 194** | **-96%** |

分类明细（三天合计，挑主要的）：

| 类别 | 旧 行 / 字节 | 新 行 / 字节 | 降幅 |
|---|---:|---:|---:|
| `创建缓存文件失败`（EMFILE，逐路径） | 56 001 / 10.88 MB | 7 / 1 604 B | **-100%** |
| 逐目录 `对账列举失败` | 5 892 / 1.38 MB | 448 / 98 877 B | -93% |
| 空转 `同步轮询` | 3 775 / 0.73 MB | 347 / 66 967 B | -91% |
| 水合位图落盘 / 读取失败（逐路径） | 4 867 / 0.94 MB | 76 / 18 164 B | -98% |
| 轮询异常 / 会话失效（抄 errors 数组） | 319 / 0.96 MB | 199 / 44 737 B | -95% |
| 上传因网络不可用暂停（逐文件逐次） | 1 037 / 0.39 MB | 61 / 22 401 B | -94% |
| 逐文件 `已上传` | 1 743 / 0.28 MB | 176 / 24 846 B | -91% |
| 其它（一次性启动 / 恢复 / 统计） | 1 673 / 0.26 MB | 1 673 / 0.26 MB | **0%（原样保留）** |

> **口径（别当精确账）**：窗口用 60s 桶近似真实「每轮 / 每窗口」；被压掉的逐条在默认
> `INFO` 下不落盘（估算按 0 字节），`RUST_LOG=debug` 时仍全量。旧规则一侧与 `ls` 的
> 文件字节**逐字节一致**，误差只来自新规则一侧的文案近似。

## 四、默认 `INFO` 下还能看到什么

| 想知道 | 日志里怎么看 |
|---|---|
| 文件到底传上去了没有 | 每 60s 一条「近一分钟上传完成 D 项 / B 字节（累计 …）」，空闲不打印 |
| 同步还在跑吗 | 10 分钟一条「同步轮询」心跳；有事件 / 冲突 / 上传 / 删除时照样立刻 INFO |
| 现在断网了吗 | 进入离线时**一条**「上传因网络不可用暂停」（带示例路径），恢复后一条，再断再报 |
| 哪些目录列举失败 | 每轮 3 条样本 + 1 条「本轮另有 N 条同类同步错误未逐条列出」，`errors` 里仍是完整清单（上限 20） |
| 磁盘会不会又被写爆 | 名单类消息截到 120 字符、同类错误压成一行汇总；最坏量级从「GB/天」降到「MB/天」 |
| 要看逐条 | `RUST_LOG=debug` 重启 daemon（或 `--log-level debug`），量会回到旧量级，查完记得去掉 |
| 用户可见的错误 | `qxync status` / GUI 错误列表 / journal 一切照旧，形状与条数都没变 |

## 六、升级

```bash
# 1) 换二进制（qxyncd 是关键：降噪在 daemon 进程里生效；
#    qxync / qxync-gui 一起换可保持版本一致。GUI 本版无界面变化）
sudo install -m755 target/release/qxync target/release/qxyncd target/release/qxync-gui /usr/bin/

# 2) 重启 daemon（正在跑的进程不会自己变；这一步之后日志立刻变安静）
systemctl --user restart qxyncd
# 没有 systemd 时：qxync daemon stop && qxync daemon start

# 3) （可选）用你自己的旧日志验证一下能压掉多少
python3 xtask/probe/m41_log_volume.py

# 4) （可选）要看逐条明细：让 daemon 跑在 debug 级别
#    systemctl --user edit qxyncd   → 在 [Service] 段加一行：Environment=RUST_LOG=debug
#    systemctl --user restart qxyncd
#    量会回到旧量级，查完把那行删掉再重启
```

升级须知：

* **不需要迁移任何文件**：无数据格式变更、无 IPC 变更、无配置变更；`sync.db` / 缓存 /
  link 文件原样可用。
* **降噪只在「装新二进制 + 重启 daemon」之后生效**：旧 daemon 继续按旧规则写日志。
* **不会回头处理旧日志**：已有日志文件不删、不改写，继续按上一版的保留策略
  （14 天 / 总量 256 MiB）自然淘汰。
* **没有要改的设置项**：GUI 设置页、`settings.json` 与日志策略字段都不变。

## 已知限制（如实记）

* **真机新二进制没有跑**：降噪要重装 / 重启 daemon 后才生效；本版验收是
  「真机历史日志只读重放 + 635 条测试 + 隔离 e2e」，**不是**「新二进制在真机跑一整天」。
* **GUI 真窗口 / `gui-matrix.sh` 未重跑**：改动不涉及 IPC 形状，既有单测覆盖
  `errors` 语义；整套矩阵会起停多个 daemon，本版没重跑。
* **`RUST_LOG=debug` 下逐条量等于旧量级**（有意设计：明细不丢，只是默认不写盘）；
  因此「日志变小」的前提是保持默认 `INFO`。
* **fd 泄漏（EMFILE）根因仍未定位**（上一版起就单列待查）：本版只保证它不再刷屏 ——
  重放里这类从 56 001 行 / 10.9 MB 降到 7 行 / 1.6 KB，但泄漏本身依旧存在，
  `Too many open files` 仍会在限流后以每分钟一条出现。
* **`cargo clippy` 未运行**（发版环境未安装）。
* 限流状态是**每进程一份**：daemon 与 GUI 各写自己的日志文件，窗口互不影响
  （这正好符合「各看各的」）。
* **不做**：全局日志级别调整、随机采样、把 `debug` 明细写进默认文件、改动保留策略默认值。

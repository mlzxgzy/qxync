# qxync v0.2.3 —— 界面看得懂了：术语去黑话 + 主页「添加任务」落点修正

**中文** · [English](#english)

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](https://github.com/mlzxgzy/qxync/blob/master/LICENSE-MIT)

**没有破坏性变更：配置文件、QNAP 协议、命令行一字未动，升级即用。**
这一版只改了界面文案和一处按钮落点 —— 但恰恰是这两处在持续消耗耐心：界面上满是
「远端根」「多根」「视图名」这类读过源码才懂的词，而主页那颗「＋ 添加任务」点下去
会把你送到「诊断 → 挂载」。

## 主页「＋ 添加任务」现在真的去添加任务

点它就等于「任务」页右上角的「＋ 添加配对文件夹」：切到任务页并**直接摊开**
「文件夹对设置」表单（本地文件夹 + NAS 文件夹 + 冲突策略等），而不是原来的
「诊断 → 挂载」新建挂载表单。

原因很朴素：这颗按钮的处理函数还是 M8.2 **之前**的老写法。那时 GUI 里还没有任务登记，
把用户送去挂载页是唯一能做的事。后来 M8.2 加了任务页与
`openTaskForm()`、M8.4 又把冲突策略 / 同步方向 / 节省空间并进同一张表单，主页这个
快捷动作就一直没跟着改 —— 于是它和任务页自己那颗按钮走了两条不同的路。

> 任务卡片上的「**管理**」按钮仍然去「诊断 → 挂载」：要看 / 卸载已经建好的挂载，
> 那里才是正确落点，这次没动它。

## 界面术语：屏幕上不再有「远端根」

「远端根」是 root 的中译，指「NAS 那一侧、一个同步范围的**起点目录**」。它既不是
共享文件夹的公共前缀（在「要同步哪些 NAS 目录」里写 `Public` 会被补成 `/Public`，
**不是** `/home/Public`），也不是「很多个根」——所以对没读过源码的人来说，这三个字
基本等于没说。同一个概念在界面上还散着三个别名（任务页、挂载页、诊断页口径各不相同）。

现在统一成人话：

| 位置 | 之前 | 现在 |
|---|---|---|
| 连接页（折叠栏内） | `远端根（roots，每行一个）` | **要同步哪些 NAS 目录（每行一个）** |
| 连接页（折叠栏内） | `home_root（远端家目录根）` | **家目录的名字** |
| 任务页表单 | `NAS 文件夹（远端根，每行一个）` | **NAS 上要同步的目录（每行一个）** |
| 诊断 → 挂载 | `远端根（每行一个，第一个是默认根）` | **NAS 上要挂载的目录（每行一个，第一个是默认）** |
| 诊断 → 状态的面板 | `远端根` | **要同步的 NAS 目录** |
| 挂载表列头 | `远端` | **NAS 目录** |
| 任务卡徽章 | `多根` | **多个目录** |
| 文件页 / 右键菜单 | `远端目录`、`复制远端路径`、`删除（远端）` | **NAS 上的目录**、**复制 NAS 路径**、**删除（NAS 上的）** |
| 冲突策略文案 | `远端占原名`、`⚠ 远端那份会丢` | **NAS 上的文件占原名**、**⚠ NAS 上那份会丢** |

**连接页多了一个「高级」折叠栏，默认收起。** 「要同步哪些 NAS 目录」与「家目录的名字」
这两格普通账号根本不用填（默认就只同步家目录），原来裸放在表单里，既看不懂、又容易
被误填；现在收进原生 `<details>`，展开后各带一段大白话说明，两处都写明「配置文件里
这个字段叫 `roots` / `home_root`」，方便对着配置文件排障。

字段名本身**没有改**：`roots` / `home_root` 在配置、`--json` 输出和诊断面板的
kv 标签里照旧，`docs/` 与 CLI 也继续用技术术语 —— 界面只负责让人看懂。

## 「说明」不再被画成红色错误

`qbox_get_sync_log` 恒返回 `status:-17`（本账号从未登记同步文件夹，区间内没有事件）时，
引擎走的本来就是「正常提示」分支（`report.note(...)`），GUI 主页却用渲染真错误的
`addAlert()` 画它，于是主页常驻一个红框、计数每轮 +1 且永不消失。现在这类提示走
`.alert-warn`（黄色）；真错误与删除熔断仍然是红色。

## 兼容性

| 维度 | 结论 |
|---|---|
| 配置文件（`links/` / `tasks/` / 设置） | 格式一字未动，直接沿用 |
| QNAP 协议面 | 一字未动 |
| 命令行 / 环境变量 / xattr / 缓存目录 | 一字未动 |
| 从 0.2.2 升级 | 覆盖安装即可，无需重新登录 |

唯一「变了」的是界面上的中文措辞，以及主页那颗按钮的落点（这正是本次修复的内容）。

## 安装

| 资产 | 说明 |
|---|---|
| `qxync-0.2.3-x86_64-unknown-linux-gnu.tar.gz` | 三个二进制 + 桌面项 / 图标 + 许可证 / 免责声明 |
| `qxync-bin-0.2.3-1-x86_64.pkg.tar.zst` | **Arch 包**（`sudo pacman -U` 直接装） |
| `qxync` · `qxyncd` · `qxync-gui` | 三个裸二进制，同一份构建 |
| `SHA256SUMS` | 校验和（`sha256sum -c SHA256SUMS`） |

解包后三个二进制**放在同一个目录**即可：GUI 先找自己旁边的 `qxyncd`，找不到再退回 `PATH`。
运行 GUI 需要系统里有 WebKitGTK 4.1 / GTK 3 运行时（Debian/Ubuntu：
`libwebkit2gtk-4.1-0` + `libgtk-3-0`），FUSE 3 需要 `/dev/fuse` + `fusermount3`。

```bash
tar xzf qxync-0.2.3-x86_64-unknown-linux-gnu.tar.gz
cd qxync-0.2.3-x86_64-unknown-linux-gnu
./qxync --version        # qxync 0.2.3
./qxync-gui              # 或者把三个文件放进 PATH 里的某个目录
```

**Arch Linux**：直接下 `qxync-bin-0.2.3-1-x86_64.pkg.tar.zst`，
`sudo pacman -U qxync-bin-0.2.3-1-x86_64.pkg.tar.zst`。想自己打或走 AUR：
仓库里带同一份包定义（`packaging/arch/`，包名 `qxync-bin`），`makepkg -si` 即可，
推到 AUR 之后就是 `yay -S qxync-bin`。

也可以从源码构建（可复现、可审计）：

```bash
git clone https://github.com/mlzxgzy/qxync.git
cd qxync
cargo build --workspace --release
```

需要 **Rust 1.90+**；完整依赖、用法与已知限制见
[README](https://github.com/mlzxgzy/qxync/blob/master/README.md)。

## English

# qxync v0.2.3 — the UI is readable now: jargon removed, and "Add task" goes where it says

**No breaking changes: config files, the QNAP protocol and the command line are untouched —
just upgrade.** This release only touches UI copy and one button's destination, but those two
were exactly what kept costing you time: the UI was full of words like "remote root",
"multi-root" and "view name" that only make sense if you have read the source, and the home
page's "＋ Add task" button took you to Diagnostics → Mounts.

## The home page's "＋ Add task" now really adds a task

Clicking it is now identical to the Tasks page's "＋ Add a folder pair": switch to the Tasks page
and **open the folder-pair form directly** (local folder + NAS folder + conflict policy), instead
of the old "Diagnostics → Mounts" new-mount form.

The reason is mundane: that button's handler was still the pre-M8.2 form. Back then the GUI had no
task registry, so sending you to the mount page was the only useful thing it could do. M8.2 then
added the Tasks page and `openTaskForm()`, and M8.4 folded conflict policy / sync direction /
space-saving into the same form — but the home shortcut was never updated, so it took a different
path from the Tasks page's own button.

> The task card's **Manage** button still opens Diagnostics → Mounts: that is the right place to
> inspect or unmount an existing mount, and it was deliberately left alone.

## Terminology: "remote root" is gone from the screen

"Remote root" is a literal translation of *root*: the **starting directory** of one sync scope on
the NAS side. It is not a common prefix for shared folders (typing `Public` in "which NAS folders
to sync" becomes `/Public`, **not** `/home/Public`), and it does not mean "many roots" — so for
anyone who has not read the source, the phrase explains nothing. The same concept also had three
different aliases across the Tasks, Mount and Diagnostics pages.

Now it is plain language:

| Where | Before | After |
|---|---|---|
| Connection page (collapsed section) | `远端根（roots，每行一个）` | **要同步哪些 NAS 目录（每行一个）** |
| Connection page (collapsed section) | `home_root（远端家目录根）` | **家目录的名字** |
| Tasks page form | `NAS 文件夹（远端根，每行一个）` | **NAS 上要同步的目录（每行一个）** |
| Diagnostics → Mounts | `远端根（每行一个，第一个是默认根）` | **NAS 上要挂载的目录（每行一个，第一个是默认）** |
| Diagnostics → Status panel | `远端根` | **要同步的 NAS 目录** |
| Mounts table header | `远端` | **NAS 目录** |
| Task card badge | `多根` | **多个目录** |
| Files page / context menu | `远端目录`, `复制远端路径`, `删除（远端）` | **NAS 上的目录**, **复制 NAS 路径**, **删除（NAS 上的）** |
| Conflict policy copy | `远端占原名`, `⚠ 远端那份会丢` | **NAS 上的文件占原名**, **⚠ NAS 上那份会丢** |

**The connection page gained an "Advanced" section, collapsed by default.** "Which NAS folders to
sync" and "the name of the home folder" never need to be filled in by ordinary accounts (the
default is home-folder-only), yet they used to sit naked in the form — impossible to understand
and easy to fill in wrongly. They now live in a native `<details>`; expanding it shows a
plain-language explanation for each, and both name the raw config fields (`roots` / `home_root`)
so you can still match them against the config file.

The field names themselves are **unchanged**: `roots` / `home_root` remain as-is in the config,
in `--json` output and in the diagnostics panel's key/value labels, and `docs/` plus the CLI keep
the technical vocabulary. The UI's only job is to be understandable.

## The engine's "note" is no longer painted as a red error

When `qbox_get_sync_log` keeps returning `status:-17` (no sync folder registered on this account,
so there are no events in range), the engine already takes the normal "informational" branch
(`report.note(...)`), but the GUI home page drew it with the same `addAlert()` used for real
errors — so a red box sat on the home page forever, with a counter that incremented every round.
Such notes now use `.alert-warn` (yellow); real errors and the delete circuit-breaker stay red.

## Compatibility

| Area | Verdict |
|---|---|
| Config files (`links/` / `tasks/` / settings) | format unchanged, reused as-is |
| QNAP protocol surface | untouched |
| CLI / environment variables / xattrs / cache dirs | untouched |
| Upgrading from 0.2.2 | just install over it, no new login needed |

The only things that changed are the Chinese UI wording and where the home button takes you —
which is precisely what this release fixes.

## Install

| Asset | What it is |
|---|---|
| `qxync-0.2.3-x86_64-unknown-linux-gnu.tar.gz` | all three binaries + desktop entry / icons / licences / disclaimer |
| `qxync-bin-0.2.3-1-x86_64.pkg.tar.zst` | the **Arch package** (`sudo pacman -U`) |
| `qxync` · `qxyncd` · `qxync-gui` | the three binaries on their own, from the same build |
| `SHA256SUMS` | checksums (`sha256sum -c SHA256SUMS`) |

Keep the three binaries in the **same directory**: the GUI first looks for `qxyncd` next to
itself and only then falls back to `PATH`. Running the GUI needs the WebKitGTK 4.1 / GTK 3
runtime (`libwebkit2gtk-4.1-0` + `libgtk-3-0` on Debian/Ubuntu); FUSE 3 needs `/dev/fuse` +
`fusermount3`.

```bash
tar xzf qxync-0.2.3-x86_64-unknown-linux-gnu.tar.gz
cd qxync-0.2.3-x86_64-unknown-linux-gnu
./qxync --version        # qxync 0.2.3
./qxync-gui
```

**Arch Linux**: grab `qxync-bin-0.2.3-1-x86_64.pkg.tar.zst` and run
`sudo pacman -U qxync-bin-0.2.3-1-x86_64.pkg.tar.zst`. To build it yourself or via the AUR, the
same definition lives in `packaging/arch/` (package name `qxync-bin`) — `makepkg -si` works, and
once published to the AUR it is `yay -S qxync-bin`.

You can also build from source (reproducible and auditable):

```bash
git clone https://github.com/mlzxgzy/qxync.git
cd qxync
cargo build --workspace --release
```

Requires **Rust 1.90+**; see the [README](https://github.com/mlzxgzy/qxync/blob/master/README.en.md)
for the full dependency list, usage and known limitations.

**Features, performance, known limitations and acceptance results are identical to v0.2.2**

# QSync-Linux（qxync）开发规划

> 基于 `qsync-reverse-report`（Qsync for Windows v6.1.0.0831 静态逆向报告）规划的 Linux 第三方客户端。
> 核心目标：**on-demand 按需同步** + Rust + Tauri GUI + FUSE。
> 本文档为第一版（MVP）规划，日期：2026-09-30。
>
> ⚠️ **2026-09-30 真机验证后的修正**（已实测通过，见 [`执行方案-M0M1.md`](执行方案-M0M1.md) §1–§3）：
> 登录请求体是 `serviceKey=1` + `pwd=base64(口令)`（不是 `service=Qsync`，也不涉及 AES）；
> `q_token` 非必需；`qsyncsrvPrepare.cgi` 已 404（改用 `qbox_get_nas_uid`）；
> `stat` 要 `path`+`file_name`+`file_total=1`；**下载必须走 `utilRequest.cgi?func=download`
> （`qsyncsrv` 的 download 恒返回 `status:20`）**，上传走 `POST upload.php` + multipart 字段 `files[]`；
> URL 里空格要编码成 `%20`。

## 0. 一页速览（先看这页）

| 决策项 | 结论 | 依据（报告篇目） |
|---|---|---|
| 语言/库 | Rust（`reqwest` + `fuser` + `tokio` + `sqlx/sqlite`） | 08 §8.1、12 §10 |
| 进程模型 | **单进程守护**（qsyncd：FUSE + 同步引擎 + 服务器）；CLI 和 GUI 都是这个守护的客户端 | 12 §6.1 |
| 占位符表示 | **稀疏文件 + `user.qsync.*` xattr + SQLite 双写**（SQLite 为准） | 12 §2 |
| 水合粒度 | 128 KiB 区间（与 Qsync 的 CfAPI FETCH_DATA 对齐） | 05 §5.4、12 §5.4 |
| 缓存模式 | 默认 page cache；提供 `--cache-mode=direct` 保守兜底 | 12 §8.3 |
| 脱水安全 | 先 `inval_inode` → 再清内容 → 再更新状态（M2 才做） | 12 §8.2 |
| 服务端配合 | **零**——on-demand 完全是客户端语义，NAS 不感知 | 05、08 §8.0 |
| 首版协议范围 | 普通账号密码登录 + 主目录（`home`）+ 单向只读 FUSE（已确认） | 08 §8.8 MVP |
| Workspace 布局 | 7 crate：core/client/daemon/fuse/cli/gui/proto-test + xtask；**daemon 二进制 `qxyncd`，前端（CLI/GUI）二进制 `qsync`**（已确认） | 用户需求 |

**两条铁则（整个项目不许违反）**：
1. 每次 `read()` 必须返回真实数据或明确 EIO，**绝不短读**（短读 = 数据静默损坏，内核会把缺页零填充并缓存）。
2. 每次脱水必须**先让内核失效缓存（inval_inode）再清内容**，顺序反了 = 数据错乱。

## 1. Workspace 结构（Rust）

```
qxync/                            # 项目名（workspace）
├── Cargo.toml                 # [workspace]
├── crates/
│   ├── qxync-core/            # 共享类型：错误码、路径模型、配置、状态机
│   ├── qxync-client/          # NAS HTTP API 封装（登录/列举/传输/日志游标）
│   ├── qxync-daemon/          # 守护进程：元数据缓存、传输队列、轮询、IPC 服务器（= 二进制 qxyncd）
│   ├── qxync-fuse/            # FUSE 文件系统（lib: FileSystem 实现；daemon 内调用）✅ M1
│   ├── qxync-cli/             # 命令行（= 二进制 qsync）
│   ├── qxync-gui/             # Tauri 桌面应用（src-tauri + 前端，应用名 qsync）
│   └── qxync-proto-test/      # 协议集成测试：对真实 NAS 的验证（probe 的 Rust 版）
└── xtask/                     # 开发辅助任务（生成本地 mock NAS 等）
```

命名约定（已确认）：**后端 daemon 叫 `qxyncd`，前端叫 `qsync`**。CLI 与 GUI 同属前端，共用 `qsync` 这个名字（CLI 二进制 `qsync`，GUI 应用显示名 `QSync`）。crate 统一用 `qxync-` 前缀。

依赖方向（只允许向下）：

```
gui ──┐
cli ──┼──► daemon ──► fuse ──┐
      │           └─► client ┴──► core
proto-test ─────────► client
```

- `core` 不依赖任何运行时；`client` 只依赖 `core`（协议层可被 proto-test 独立驱动）。
- `fuse` 是库 crate（实现 `fuser::Filesystem`），由 `daemon` 组装——不做独立 FUSE 进程，理由见 12 §6.1（跨进程 IPC 拉长水合路径，调试成本高）。
- `gui` / `cli` 不直连 NAS，一律走 daemon 的 IPC（本版：本地 HTTP + JSON；隐藏为 SDK 模块）。

### 版本与工具链

- Rust 1.85+（edition 2024），本机 nightly 1.101 可用。
- libfuse3 3.18.3 已装（`fuser` 0.15 起纯 Rust 实现挂载协议，不再需要 libfuse3 链接，但 `fusermount3` setuid 需在）；`fuser` crate 版本锁定 ≥ 0.14（需要 `Notifier::inval_inode`，这是脱水正确性的硬前提）。
- 关键 crate 清单：

| crate | 用途 | 备注 |
|---|---|---|
| `tokio` | daemon 运行时 | FUSE 回调里用 `block_on` 桥接 |
| `reqwest`（rustls） | NAS HTTP | 自签证书需 `danger_accept_invalid_certs` 开关 |
| `fuser` | FUSE | `inval_inode` / `direct_io` 支持 |
| `sqlx` 或 `rusqlite` | SQLite（游标/baseline/队列） | 建议先 `rusqlite`（同步简单），量大再换 |
| `serde` / `serde_json` | 配置 + IPC + NAS JSON | XML 用 `quick-xml`（authLogin 响应是 XML） |
| `clap` | CLI | |
| `tauri` 2.x | GUI | |
| `keyring` 或文件 0600 | 凭据存储 | 首版用文件 0600（`credentials.json`） |

## 3. 关键设计

### 3.1 状态模型（core crate）

```rust
enum HydrationState { Placeholder, Hydrated, Dirty, Conflict }
enum PinState { Unspecified, Pinned, Unpinned, Excluded }
// xattr 键（FUSE 挂载点上的 xattr 是虚拟的，由 daemon 应答，值存 SQLite）
// user.qsync.state / user.qsync.pin / user.qsync.fid / user.qsync.vsize / user.qsync.etag
```

- **xattr 与 SQLite 双写，SQLite 为准**（工具复制文件会丢 xattr，不能只信 xattr）。
- 双视图模型（比 Qsync 的三视图简化）：

```
local(挂载点真实状态)  vs  remote(stat/get_list + etag)  vs  baseline(上次同步成功 {size,mtime,etag}，SQLite)
local==baseline && remote!=baseline → 下载；local!=baseline && remote==baseline → 上传；都变 → 冲突副本
```

### 3.2 登录链（client crate，照 02 篇还原的时序）

```
authLogin.cgi(user/pwd[/code], service=Qsync, client_app=Qsync) → authSid(+2SV 分支)
→ qsyncsrv_login.cgi(user, qbox_user, qbox_computer, qbox_device_type, Qsync_client_version) → q_token(持久化)
→ qsyncsrvPrepare.cgi?user= → NAS UID
→ qsyncsrvPrepare.cgi?func=activate&token= → server name / admin
→ get_list(share_root) 探活（后续作为 CheckSessionAlive）
```

要点：
- **两套命名空间都要实现并探测**：`/cgi-bin/qsync/qsyncsrv.cgi`（新 QTS）与 `/cgi-bin/filemanager/utilRequest.cgi`（旧）；`qsyncsrv_login.cgi` vs `wfm2Login.cgi` 同理。启动探测，404 自动切换。
- 密码字段名是**动态验证项**（probe 0.1 定论）；`auth_data`+`iv` 的 AES（共享文件夹/file-level 授权）**首版不做**——普通用户主目录 `home` 的上下传只需 `sid`（08 §8.0 明确）。
- 错误码分支要接：`WFM_NEED_USER_NAME`（重登）、`WFM_QSYNC_DISABLED`（提示 NAS 侧未启用 Qsync）、`QFILE_ERROR_QSYNC_QPKG_NOT_EXIST`（未装 QPKG）。

### 3.3 FUSE 水合路径（fuse crate）

```
read(path, offset, size):
    state = meta(path)
    if state == Placeholder:
        ensure_hydrated(path)          # 去重 + 超时 60s + 失败→EIO（绝不返回 0）
    data = cache(path, offset, size)
    if data.len() != size && offset+size <= vsize: return EIO   # 铁则 1
    return data
```

> 水合取字节用 **`utilRequest.cgi?func=download&source_path=&source_file=&isfolder=0&source_total=1`**
> （实测支持 `Range` → `206 + Content-Range`；M2 的 128 KiB 区间水合就靠它）。
> `qsyncsrv.cgi?func=download` 恒返回 `status:20`，**不要用**。

- `open(O_WRONLY|O_RDWR)` → **先完整水合**（M1 只读，O_WRONLY/O_RDWR 直接返回 EACCES，M2 再实现写路径）。
- mmap 风险：M1 对 < 8 MiB 文件 open 即整文件水合，大文件按需 + 文档注明（12 §7.3）。
- 临时文件过滤（`*.crdownload`、`~$*`、`.goutputstream-*`、`.upload_cache`）做成路径规则引擎，M2 用。

### 3.4 本地状态布局（照 09 §9.6 蓝本）

```
~/.config/qsync/config.json                 # 全局设置（轮询间隔、并发、代理）
~/.config/qsync/links/<link_id>.json        # NAS 连接
~/.config/qsync/credentials.json (0600)     # q_token
~/.local/share/qsync/sync.db                # SQLite：baseline / 游标 / 队列 / 占位符状态
~/.local/share/qsync/cache/<pair_id>/       # 下载缓存（CacheFileName 模式：先写缓存再原子 rename）
~/.local/state/qsync/log/                   # 日志
```

游标持久化（M2 用，先定规矩）：**临时文件 + fsync + rename() + fsync 父目录**，先处理事件再推进游标。

## 5. 风险与注意事项（开发时盯住）

| 风险 | 等级 | 应对 |
|---|---|---|
| **短读 → 数据静默损坏** | 🔴 最高 | 铁则 1；测试矩阵 #3/#4 必测 |
| **脱水顺序错误** | 🔴 | 铁则 2；M2 才做脱水，做成 `--cache-mode=direct` 可切换 |
| 密码字段/AES 封装未定 | 🟠 | probe 0.1 先行；AES 不通则范围收缩到主目录 |
| `q_token` 有效期未知 | 🟠 | 实现 `CheckSessionAlive`（get_list 探活）失败重登；probe 观察有效期 |
| 轮询间隔/分片大小未测量 | 🟡 | 首版定值（轮询 5s、下载整文件），抓包后再调 |
| NAS 大小写不敏感 vs Linux 敏感 | 🟡 | M1 只读影响小；M2 rename 必须两阶段（`A→A.tmp→A'`） |
| QTS 版本路径差异 | 🟡 | 启动探测两套命名空间 |
| 自签证书 | 🟡 | `--insecure` 开关 + 可导入 CA |
| 与官方 Windows 客户端同时在线 | 🟢 | 不冲突（不抢 LAN 直连端口，首版不实现 LAN Sync） |
| 合规 | 🟢 | 只对自己拥有/授权的 NAS 使用；不分发 QNAP 二进制 |

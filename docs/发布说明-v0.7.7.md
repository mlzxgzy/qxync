# v0.7.7 —— 修复 v0.7.6 daemon 启动即 panic

> 发布日期：2026-10-21
> 上一版：[v0.7.6](发布说明-v0.7.6.md)（WPS 保存 + Dolphin 复制，FUSE 兼容双修）
>
> **热修版**：v0.7.6 的 `qxyncd` 启动即 panic（`log` 桥与 `LogTracer` 抢同一个
> 全局 logger），daemon 化后 stderr 指向 `/dev/null`，故障完全静默 ——
> **v0.7.6 的 Release 资产整体不可用，请直接升级到 v0.7.7**。CLI / GUI 二进制
> 本身没有这个问题（它们不初始化进 daemon 的那套日志），但没有 daemon 一切
> 功能都不可用。

## 一句话

```text
qxync daemon start
  → ❌ v0.7.6：qxyncd 已派生但 socket 未就绪（日志零线索，子进程 101 退出）
  → ✅ v0.7.7：正常起来，挂载恢复、同步继续
```

## 一、根因

v0.7.6 为了把 fuser 的诊断日志（`[Not Implemented] link(...)` 之类）接进
daemon 日志，在 `init_logging()` 里做了这件事：

```text
log::set_logger(&FuserLogBridge)     // 自建 log → tracing 桥，占住 log 全局 logger
tracing_subscriber::registry()
    .with(...)
    .init()                           // 默认 feature 含 tracing-log
                                      // → init() 内部再调 LogTracer::init()
                                      // → 也去占 log 全局 logger → SetLoggerError
                                      // → .expect() → PANIC
```

而 `main` 在 daemon 化之后才初始化日志 —— 此时 fd 0/1/2 已指向 `/dev/null`，
**panic 无声无息**。父进程（`qxync daemon start`）看到的是「子进程退出了 →
socket 没出现」，于是报「qxyncd 已派生但 socket 未就绪」，日志里一个字都没有。

现场取证（修复前二进制）：

```text
$ /usr/bin/qxyncd --foreground
thread 'main' panicked at tracing-subscriber-0.3.23/src/util.rs:94:
failed to set global default subscriber: SetLoggerError(())
# exit 101
```

## 二、修法（三项）

| 项 | 改动 |
|---|---|
| log 桥 | 改用 `tracing::subscriber::set_global_default()`，绕开 `init()` 内置的 `LogTracer`；log → tracing 桥继续由 `FuserLogBridge` 负责，fuser 日志照常可见 |
| 日志初始化加固 | `tracing_appender::rolling::daily()` 在日志文件建不出来时内部 `.expect()` 也会 panic（同样被 `/dev/null` 吞掉）—— 改用 builder 拿 `Result`，失败降级为只写 stderr，并在 stderr 留一条警告 |
| 防复发 | 新增 `crates/qxync-daemon/tests/logging_init.rs`：`--print-config` 存活回归（启动含日志初始化并正常退出）+ 日志目录不可写时降级 stderr |

## 三、验证（2026-10-21）

| 项 | 结果 |
|---|---|
| `cargo test --workspace` | ✅ **526 通过 / 0 失败 / 21 忽略**（新增 2 个回归） |
| `cargo fmt --all -- --check` | 0 diff |
| 修复前复现 | 旧二进制 `--foreground` / `--print-config` 均 panic，exit 101 |
| 修复后 | `--foreground` 正常启动；隔离 XDG 目录 + 临时 socket 下 `start` → socket 就绪 → `status` pong → `stop` 干净退出 |
| 日志 | 正常落盘（`~/.local/state/qxync/log/qxyncd.log.<日期>`），启动事件齐全 |

## 四、已知边界

* 本版只修「启动期必然 panic」的两条路径；「daemon 化后 stderr → `/dev/null`」
  这个环境事实没有改变 —— 将来若再有启动期 panic，仍是静默的，需要
  `--foreground` 复现才能拿到回溯；
* v0.7.6 的 Release 二进制作废；已装 v0.7.6 的用户升级 v0.7.7 即可，设置与
  数据零迁移；
* CLI / GUI 二进制在 v0.7.6 里本身正常，但本版按整套重新构建、版本号对齐。

## 五、升级 / 卸载

* 升级：换二进制（`sudo cp` 或装包）+ **完整重启 daemon**（stop/start，或
  重启托盘 GUI —— 它会一并重启挂载）；设置文件零迁移；
* 回退：换回 v0.7.5 或更早的二进制即恢复旧行为（v0.7.6 的二进制请勿使用）。

# M44 · 同步错误可处置（幽灵目录自动清理 + 说明行 + 不再伪报会话失效）

> 状态：**代码完成，待真机部署验证**（2026-10-29）
> 前置：[M41 日志降噪](M41-日志降噪.md)（把「同一条错误每轮刷屏」压到每轮 3 条样本；
> 但**样本进了 `errors` → GUI 红字常驻**，M44 解决的是「这条红字本身该不该存在」）

## 0. 结论先行

用户原话：

> 同步错误（kami@qnap.kdajv.com:9834）：同步「qsync」对账列举失败（stat 确认也失败，
> 第 71/5505 个目录）→ 本轮不判定该目录及其内容: stat: status=5 (路径不存在 / 无权限)
>
> 老是显示报错，我也不知道错哪，显示了也解决不了，显示他干啥……咋处理一下，烦死了

三件事一次解决：

| 问题 | 修法 |
|---|---|
| 报错看不懂是哪几个目录 | 说明行里给**路径样例**（相对挂载根，最多 3 个 + 总数） |
| 报错永远修不好（真实原因：30 个目录在远端已经不存在，baseline 里却还留着） | **幽灵目录自动清理**：远端列不出来 + 父目录清单里也没有 + 本地没有任何节点 → 清掉这棵子树的同步状态（**只清状态，不动任何文件**） |
| 同一批目录每轮都触发「会话失效 → 立即重登」 | 4/5 只有在**本轮一个目录都没列成**时才算会话失效（延迟到轮末判定） |

改完之后：这类目录**第一轮就被清掉**，`last_error` 下一轮自动清空，GUI 不再常驻红字；
剩下的「本地还有内容 / 父目录看得见但列不进去」的目录只进**说明行**（黄色），
不再进 `errors` / `last_error` / journal 的错误列表。

### 1.4 根因链

```text
`.lo` 整棵被移进 `.build-tmp`（旧路径从远端消失）
  → baseline 留着旧路径 80 行
  → 列 `.lo`：status=5（路径不存在/无权限）
  → 用 stat 正向确认：stat 也 status=5（目录列不出来时 stat 也答不了「存在」）
  → unresolved_dirs：目录条目自身与整棵子树本轮都不判定（数据安全，方向对）
  → 但这批目录**永远**判不掉（远端不会回来），于是每轮都走同一条路
  → M41 每轮 3 条样本进 errors → last_error 常驻 → GUI「⚠️ 同步错误」
  → 同时 `e2.is_auth()` 把 status 4/5 当会话失效 → 每轮「立即重登」（一天 163 次）
```

**为什么不能直接把 4/5 当「远端已删」**：4/5 同时是「会话失效 / 权限拒绝」的码
（真机 `/Download`、`/homes` 就回 4/5）。所以数据安全阀门（stat 正向确认）必须保留；
M44 只在**再确认「本地没有任何东西」**之后才清状态 —— 那就不存在「误删数据」，
最坏只是丢了对一个当前不可见目录的跟踪记录（远端文件一个不动）。

## 2. 修法（`crates/qxync-daemon/src/sync.rs`）

### 2.1 幽灵目录自动清理（`purge_ghost_dir`）

在 `Err(e2)`（stat 确认也失败）分支里，对**非网络类**错误再做两个判断：

```text
列不出来 + stat 也失败
  ├─ 本地这棵子树还有节点？ ──────────── 是 → 不删、不判定 → 说明行
  ├─ 父目录本轮列到了，清单里还看得见它？ ─ 是 → 只是列不进去（权限）→ 说明行
  └─ 都不是 → 纯历史残留 → purge_ghost_dir：清 baseline 子树 + 清单快照，不动任何文件
```

* 清理**不等**父目录这一轮也进窗口：轮转一圈要 ~40 轮（20 分钟），等它就等于让红字
  多挂 20 分钟；判定安全性来自「本地没有任何节点」，与父目录这一轮在不在窗口无关；
* 清理后把该目录记进 `cleaned_ghosts`，本轮窗口里排在它后面的后代直接跳过（不再白列）；
* `SyncReport.ghost_cleaned` 记录清掉的行数，说明行 + journal（`kind=sync,status=ok`）
  各出现一次；`SyncReport.unreachable_count / unreachable_dirs` 记录剩下的「无法核对」。

### 2.2 无法核对 → 说明行（不进 `errors`）

```text
对账：N 个目录无法核对（远端可能已删除，或当前账号没有权限），其内容本轮不判定
（不影响其他目录）；样例：2026/29-四川赛/.lo、…
```

* 只进 `notes`（GUI「说明（…）」黄色行 / `qxync status` 的「说明」）；
* 日志按 `noise::dedupe_in("sync.unreachable", …, 600s)` 限流：首次 + 每 10 分钟一条 WARN，
  其余 debug —— 不再每轮 3 条 WARN；
* **不进** `last_error`（红字）、不进 journal 错误列表。

### 2.3 不再把 4/5 伪报成会话失效

旧的 `Err(e2)` 分支无条件 `report.auth_failed = true`。现在改成**记票、轮末判定**：

```rust
// 只要本轮成功列过哪怕一个目录，会话就是好的；4/5 只是那几个路径不可见。
if notfound_auth_votes > 0 && scanned == 0 {
    report.auth_failed = true;
}
```

轮末判定而不是遇到即置，是为了处理「窗口一开头就命中幽灵簇」的情况（那时 `scanned`
还是 0，但后面会列成功）。真正的会话失效（根都列不出来）仍由 `dir == root` 分支与
`max_log` 失败路径触发，行为不变。

## 3. 数据安全边界（逐条）

| 场景 | 行为 | 理由 |
|---|---|---|
| 远端列不出来 + stat 失败 + 本地无节点 + 父清单没有它 | **清 baseline 子树 + 清单快照** | 纯历史残留；远端文件不动，将来可见会重新登记 |
| 同上但**本地还有节点**（哪怕一个占位符） | 不动，只进说明行 | 本地可能有用户改动，清状态会让它变成「本地新增」被重传 |
| 父目录本轮列到了、清单里**有**它（只是列不进去） | 不动，只进说明行 | 典型权限/ACL；目录确实存在 |
| 网络类失败（HTTP 5xx / 断网） | 原样走 `record_list_failure_or_abort` | 探活 / 中止语义一字不动（M30） |
| stat 确认 `exist=0`（真删除） | 原样走删除判定 | 不变 |
| 根目录 4/5 | 原样按权限/会话/卸载处理 + 重登 | 不变 |
| **挂载视图一个节点都没有**（本地状态没接上） | 一律不清，只进说明行 | 否则「本地视图是空的」会被误当成「本地什么都没有」——一次权限抖动就能清空整份 baseline |

清理动作只碰两类东西：`baseline` 行、挂载视图的目录清单快照（`drop_listing`）——
**不调 `remove_remote`**（那条 API 会删节点 + 缓存；幽灵的前提正是本地没有节点）。

## 5. 未做 / 待观察

* **没有做「一键忽略某目录」**：自动清理已覆盖真机这批；剩下无法核对的目录属于
  「本地还有内容」或「权限」，前者不该静默忽略、后者要用户在 NAS 上改权限；
* **没有把样例路径展开成完整列表**：说明行只放 3 个样例 + 总数，完整清单在
  `RUST_LOG=debug` 的 `对账列举 … stat 确认也失败：父目录…` 里（含路径）；
* 真机上如果那 30 个目录在**跑过旧版本期间**又被写入了本地节点（理论上没有：
  `nodes` 表 0 行），新版本会保守地只报说明、不清理 —— 到时用
  `qxync state <路径>` 逐个看即可。

# M30：网络失败不刷屏、不带路径，按「已缓冲，等联网」表达

> 真机反馈（2026-10-21，qnap.kdajv.com）：
>
> ```text
> 对账列举 /home/.Qsync/2025/11-公安大赛/24.复赛.网络安全管理员/1218-全国/…/flink 失败:
> 网络错误: get_list /home/.Qsync/2025/11-公安大赛/…/flink:
> error sending request for url
> (https://qnap.kdajv.com:9834/cgi-bin/qsync/qsyncsrv.cgi?func=get_list&sid=lexymjya&…&path=%2Fhome%2F…)
> ```
>
> 用户的三句话就是验收口径：
> **① 咋还在报网络错误；② 本地路径和远程路径都不要显示了，就显示哪个同步的时候网络失败；
> ③ 放到缓冲区去等在线就行了。**

---

## 1. 三个问题

### 1.1 一次闪断被当成「同步失败」报出来

真机时序（2026-10-21 12:32）：

```text
12:32:47  对账列举 /home/.Qsync 失败: 网络错误: error sending request
12:32:48  网络错误后探活 → 可达（Some(true)）
12:33:11  会话失效（stat … status=5）→ 重登
```

请求被对端丢了，但**探活同时是通的** —— 探活的判据是「base_url 有回应」，
它回答的是「NAS 在不在」，不回答「这一条请求有没有被丢」。于是这一轮按
「在线 + 记录错误」处理：错误进 `last_error`（界面红字）、进 journal（更新中心）。

最常见的成因是 **keep-alive 竞态**：NAS 的 nginx 回收空闲连接，而 reqwest 连接池
恰好复用了那条刚被关掉的连接。GET 是幂等的，**重试一次就能成功** —— 用户不该为此
看到一条「网络失败」。

### 1.2 用户可见文案里带路径、URL、sid、查询串

错误在 client 层由 `reqwest::Error` 的 `Display` 拼成，而它**自带完整请求 URL**：

```text
… for url (https://qnap…/cgi-bin/qsync/qsyncsrv.cgi?func=get_list&sid=lexymjya&is_iso=0&…&path=%2Fhome%2F.Qsync%2F…)
```

再叠加对账层自己拼的「对账列举 {dir} …」，于是同一条消息里出现了：

* 远端路径（两遍：中文一遍、URL-encoded 一遍）；
* **会话 sid**（`sid=lexymjya` —— 这不是给用户看的东西）；
* 全部查询参数。

### 1.3 断网期间每轮写一条，更新中心一直刷

网络失败是 `error_is_network`（journal 里降级成 `warn`，不进错误列表/弹窗），
但**没有去重**：30s 一轮、断网 30 分钟 = 60 条一模一样的「网络失败」。
用户翻更新中心看到的还是「怎么还在报网络错误」。

---

## 2. 设计

### 2.1 幂等 GET 的有限重试（吸收一次闪断）

`qxync-client` 新增 `Client::send_get`：只给**幂等 GET** 用（`get_list` / `stat` /
`qsyncsrv.cgi` 的 `func=*` / `settime`），最多 3 次尝试，退避 200ms → 600ms。

* 重试条件：请求阶段失败（连接被对端提前关闭 / 协议中断 / 响应体读到一半断）
  **或** 反代 502/503/504；
* **不重试**：连接超时、连接拒绝、DNS 失败 —— 这些是「离线」的第一现场，
  重试会把一次 20s 的 connect timeout 拖成 60s，让断网检测反而变慢。
* 重试成功 → 这一轮**零错误**，用户什么都看不到（测试钉住）。

### 2.2 文案：去 URL、去路径，只留「哪一路同步 + 第几个目录 + 已缓冲」

* client 层新增 `http_error_text`：把 `reqwest::Error` 压成「哪一类失败 + 最底层 io 原因」，
  例如 `请求发送失败：Connection reset by peer (os error 104)`。
  **不出现 URL / sid / 查询串 / 远端路径**。
* `get_list` / `stat` 的错误上下文不再拼路径（路径只进 `tracing::debug`）。
* 对账失败的可见文案改成：

  ```text
  同步「qsync」对账列举失败（第 1/4987 个目录，已列 0 个）: 网络错误: 请求发送失败：…；
  已缓冲本轮进度，网络恢复后自动继续
  ```

  「哪一路同步」= 挂载点目录名（任务默认挂在 `<cache>/<link>/<task>`，目录名就是任务名；
  真机 `…/default/qsync` → `qsync`），**不打印完整路径**。
* 确认整台不可达时的中止文案同样去掉 NAS 地址：

  ```text
  网络不可用：探测 NAS 失败，本轮轮询中止（同步「qsync」对账列举失败…；
  本轮不判定任何远端缺失，恢复后自动继续）。底层错误：…
  ```

### 2.3 状态：网络失败进「说明」，不进「最近错误」

`absorb_round` 是 `last_error` / `last_note` 的唯一写入点。现在：

| 结论 | 写哪 | 界面 |
|---|---|---|
| 非网络错误（业务 status / 会话 / 本地 IO） | `last_error` | ⚠️ 最近错误（红字） |
| 只有网络失败 | `last_note`（+ 一条 journal `warn`） | 说明：…（黄字，含「已缓冲，网络恢复后自动继续」） |

理由：断网不是「同步坏了」，是「暂时连不上」——上传/删除队列已经停在「等联网」，
没列到的目录下一轮自动重试，**数据一条不丢**。把「暂时连不上」挂成红字，
用户唯一能得出的结论就是「同步坏了」。

`qxync status` / `qxync sync` 和 GUI 同步页/诊断页都读 `note`，所以缓冲态在 CLI 也可见。

### 2.4 journal：一次断网只记一条，恢复时补一条

`SyncStats.network_sig` 记住上一轮的网络失败签名（错误条数 + 最后一条消息），
只有**新失败 / 失败内容变了 / 已恢复**才置 `SyncReport::network_failure_changed`；
`journal_record_sync` 据此只写一条 `warn`，恢复时写一条 `ok`「网络已恢复：同步继续」。
重复轮次降为 `debug`，退出「每轮刷一条」。

### 2.5 数据安全不变

失败目录仍然**不进 `observed_dirs`**：内容「没看到」≠「远端删了」，本轮不判定、
不按缺失删本地、不删缓存。这一层没有任何改动（既有回归测试继续钉住）。

## 4. 升级后行为

daemon 需要重启才生效（新二进制）。重启后：

* 一次闪断：用户**看不到任何东西**（重试吸收）；
* 真断网：界面显示「说明：同步「qsync」… 已缓冲本轮进度，网络恢复后自动继续」，
  离线时另有「已离线 + 本地改动已先攒着（N 项）」横幅；更新中心**一条**网络记录，
  恢复后补一条「网络已恢复」；
* 所有相关文案里没有本地路径、远端路径、URL、sid、查询串。

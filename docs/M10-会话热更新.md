# M10 —— 会话热更新（sid 续期 / 重登录推挂载）

> 目标：sid 过期后，**挂载点不再一直 `EIO` 到重新挂载**，同步轮询也不再每轮都失败。
> 判据：真机 NAS（真登录 / 真登出）+ `cargo test --workspace`，见文末验收表。

---

## 1. 症状

* `ls /mnt`、`cat /mnt/x` 直接「输入/输出错误（EIO）」，直到 `umount` + 重新 `mount` 才好；
* `qxync status` 里 `会话 sid=… 存活=false`，但挂载点里的请求**永远不会**自己重登；
* 变更轮询每一轮都报错（`qbox_get_max_log 失败: status=3`），也不会重登。

## 2. 根因（三处，都在「会话」这条线上）

| # | 根因 | 位置 |
|---|---|---|
| 1 | `Client.sid` 是普通字段；挂载时把 sid **拷贝**给 FUSE 用的那个 `Client`。sid 过期后没有任何路径去更新它 | `qxync-client` 的 `Client` / `daemon::mount` |
| 2 | 「遇鉴权失败自动重登」只写在 IPC 命令的宏 `with_client!` 里 —— 挂载点（FUSE 回调）与同步引擎都不走那条路 | `daemon.rs` `with_client!` |
| 3 | `map_err` 把服务端的 4/5 号 status 泛化成 `ErrorKind::Status`，调用方分不出「会话失效」还是「日志缺失（-17）」 | `daemon.rs` `map_err` |

## 3. 改法

### 3.1 sid 变成可热更新的

`Client.sid: Arc<RwLock<Option<String>>>`，API 改成 `&self`：

```rust
pub fn sid(&self) -> Option<String>;       // 克隆出去（不再借 &str）
pub fn set_sid(&self, sid: impl Into<String>);
pub fn clear_sid(&self);
```

`Arc<Client>` 的持有者（daemon 主体 / 引擎客户端 / 挂载点 / 上传队列）**天然共享**同一个 sid，
一处 `set_sid` 处处可见（有单测钉住）。

### 3.2 「是不是会话失效」收到 core

`qxync_core::Error::is_auth()`：`Auth`，或 `Status` 为 4/5。client / daemon / FUSE 三层用同一个判据
（daemon 里的私有 `is_auth_error` 与 `map_err` 都改成调它；4/5 号 status 现在归 `ErrorKind::Auth`）。

### 3.3 重登后把 sid 推给所有挂载点

`login_internal` 成功后调 `push_sid_to_mounts(state, &sid, &user)`：

* 只推给**同一个账号**的挂载点；换账号（同一 link 不同 user）时只告警、不推 ——
  它的节点表/缓存还是上一个账号的树，推过去会张冠李戴（有单测）。
* `logout` 顺手把挂载点的 sid 也清掉，下一次访问按凭据重登（与 IPC 的懒登录语义一致）。
* 只推「sid 还不一样」的客户端，返回真正改了几个。

### 3.4 挂载点：鉴权失败 → 重登 → **原地重试一次**

daemon 在 `mount` 之后注入 `SidRefresher`（`Arc<dyn Fn() -> Option<String>>`）：

```
FUSE 线程（同步）                         daemon（async）
  ├─ NAS 调用失败且 is_auth()
  ├─ SidRefresher()  ──── std mpsc ────►  会话经纪人（串行重登，3s 内去重）
  │                                        └─ login_internal → 推 sid 给所有挂载点
  ├─ ◄──────────────── 新 sid ────────────┘
  ├─ client.set_sid(新 sid)
  └─ 重试一次（只重试一次）
```

覆盖的调用点：`readdir`（`list`）、`lookup`（`stat`）、区间水合/后台刷新（`download_range`）、
`mkdir`、`unlink/rmdir`、`set_mtime`、`rename/move`。写路径与读路径共用同一个 `Arc<Client>`，
所以上传队列也一起吃这个热更新。

### 3.5 会话保活（主动）

`spawn_session_keeper`：每 `QXNYC_SESSION_KEEPALIVE` 秒（默认 120，`0` = 关）探一次
`check_alive()`；判定抽成纯函数 `keeper_step`：

| 状态 | 动作 |
|---|---|
| 还没有 sid | `Idle` —— 不碰 NAS（保持「懒登录」：daemon 空转时不主动登录） |
| 探测说还活着 | `Ok` —— 什么都不做 |
| 探测说已失效 | `Relogin` —— 重登（顺带把新 sid 推给挂载点） |
| 探测本身失败（断网/解析） | `ProbeFailed` —— 这轮不动，下一轮再探（别在断网时反复打登录接口） |

变更轮询遇 `ErrorKind::Auth` 也会重登一次（以前只是记一条错误，sid 死了每轮都失败）。

## 4. 验收

### 4.1 真机：登出之后挂载点必须自己恢复（反应式）

隔离环境（独立 `XDG_*` + 独立 socket + 独立挂载点，`QXNYC_POLL_INTERVAL=0`、
`QXNYC_SESSION_KEEPALIVE=0`，把干扰项关掉），对真机 NAS：

| 步骤 | 结果 |
|---|---|
| 挂载 + 列一个目录建立会话 | ✅ |
| IPC `logout`（服务端 sid 作废 + 挂载点 sid 清掉） | `登录状态：未登录` |
| **登出后**列一个没进快照的子目录（`qxync-test/l1`） | ✅ 0.50 s（一次 NAS 往返） |
| **登出后** `cat` 一个没水合过的文件（`1k.bin`） | ✅ 1024 字节 |
| daemon 日志 | `WARN qxync_fuse: 挂载点会话失效（鉴权失败: 尚未登录（没有 sid）），请求 daemon 重登后重试` → `INFO 会话已热更新到 1 个挂载点（sid=…）` → `INFO 登录成功` |

修好之前：同一个 `logout` 之后挂载点的每一个请求都会一直 `EIO`，只能卸载重挂。

### 4.2 保活（主动路径）

尝试用「另一个隔离 daemon 用同一账号登录把 sid 挤掉」来触发，**本机 NAS 不互踢同账号会话**，
所以保活分支没能在真机上跑出来（如实记）。改法：

* 保活的分支判定抽成 `keeper_step`，4 个分支全部单测覆盖；
* 反应式路径（4.1）本身就是保活的兜底：即便探测漏了，挂载点下一次 NAS 调用也会自愈。

### 4.3 单测

|---|---|---|
| `qxync-fuse` | `auth_failure_refreshes_sid_and_retries_exactly_once`（重试**只**一次 / 非鉴权错误不重试 / 没刷出来就保留原错误） | 34 → **35** |

`cargo test --workspace` 全绿；`cargo fmt --all -- --check` 0 diff。

## 5. 取舍与已知边界

* **同 link 换账号**：不推新 sid（只告警），需要卸载重挂 —— 挂载点的节点表/缓存没有按账号重建。
* **保活间隔默认 120s**：探测本身是一次 `qbox_get_max_log`（很小）；间隔越短越"粘"，
  但如果 NAS 是「同账号单会话」，多个客户端会互相踢、看起来像在抢会话，所以默认给得保守。
* **轮询的 Auth 分支**（`ErrorKind::Auth` → 重登）没有真机端到端触发：要构造「本地有 sid 但服务端已作废」
  得直接对 NAS 调 `qsyncsrv_logout.cgi`，本次只做了单元测试（`map_err_marks_session_status_as_auth`）。
* **没做的**：`qxync logout` 目前没有 CLI 入口（IPC 有 `Logout`，GUI 用得到）；账号切换时自动重挂载。
* `fuse-matrix.sh` / `m8x-matrix.sh` 等真机矩阵本次未复跑。

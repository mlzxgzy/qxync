# qxync v0.2.1 —— 命令行改名：`qsync` → `qxync`

**中文** · [English](#english)

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](https://github.com/mlzxgzy/qxync/blob/master/LICENSE-MIT)

**这是一个改名版本，请先读升级说明再装。** 0.1.x 的命令行叫 `qsync`，会和
**QNAP 官方 Qsync 客户端**抢同一个 `/usr/bin/qsync`；这一版把它以及所有其它旧名
（配置目录、环境变量、xattr、临时文件后缀、GUI 显示名）统一收进 `qxync`。

> 顺带说明：`v0.2.0` 这个版本号只存在于 git 历史里（没有打 tag）——
> **第一个真正发布的是 v0.2.1**，它同时包含改名和下面这条 daemon 改动。

## daemon 现在「没配 NAS 也一直跑着」

之前 `qxyncd` 启动时要读一份连接配置，读不到就**直接退出** —— 于是「还没登录 / 还没配」
等同于「daemon 用不了」，和「daemon 常驻后台」的用法直接冲突（GUI 还会把你引到
`qxync daemon start` 那句提示上，照做依然报错）。现在：

- **空转待命**：一份连接配置都没有时，daemon 照样启动、照样常驻，只服务
  `ping` / `status` / `shutdown` 和**纯本地文件**的设置读写；`status` 里 `link` 为 `null`，
  界面显示「未配置」。要 NAS 的请求会被明确拒绝（附一句「先 `qxync login`」），
  不会拿着空 host 去发请求。
- **配好连接后自动生效**：空转的 daemon 每 2 秒看一眼 link 文件，出现就**原地**转入
  同步模式（同一进程、同一 pid，不 re-exec），然后开始同步 —— 不用重启、也不用再敲命令。
- `qxync daemon start` 与 GUI 的「启动 daemon」**不再因为缺连接配置而拒绝启动**。

> ⚠️ 只用于**你自己拥有或已获明确授权**的 QNAP NAS。本项目不分发任何 QNAP 二进制、
> 不绕过任何授权或保护措施，与 QNAP Systems, Inc. **无任何关联**。
> 完整条款见 [`DISCLAIMER.md`](https://github.com/mlzxgzy/qxync/blob/master/DISCLAIMER.md)。

## ⚠️ 破坏性变更（升级前必看）

| 0.1.x | 0.2.0+ |
|---|---|
| `qsync …`（二进制） | `qxync …` |
| `~/.config/qsync`、`~/.local/share/qsync`、`~/.local/state/qsync` | `~/.config/qxync`、`~/.local/share/qxync`、`~/.local/state/qxync` |
| `QSYNC_HOST` / `QSYNC_USER` / `QSYNC_PASSWORD` / `QSYNC_SOCKET`、`QSYNC_*`（调参与验收） | `QXNYC_HOST` / `QXNYC_USER` / `QXNYC_PASSWORD` / `QXNYC_SOCKET`、`QXNYC_*` |
| `getfattr -n user.qsync.state`（还有 `.pin` / `.remote` / `.vsize` / `.chunks`） | `getfattr -n user.qxync.state`（同上） |
| 下载临时文件 `*.qsync-part` / `*.qsync-tmp` | `*.qxync-part` / `*.qxync-tmp` |
| GUI 显示名 `QSync`、日志 `qsync-gui.log`、托盘 ID `qsync-tray` | `qxync`、`qxync-gui.log`、`qxync-tray` |
| 自启项 `~/.config/autostart/qsync.desktop` | `~/.config/autostart/qxync.desktop` |

**本地目录会自动迁移，不用重新登录。** 首次运行时，若新目录不存在而旧目录存在，
`qsync/` 会被直接改名成 `qxync/`（跨文件系统时退回复制 + 删除）；若新旧目录**同时存在**
（例如早期原型留下的 `~/.local/share/qxync`），只把旧目录里**缺**的条目补进去，
**已有的一律不覆盖**，并打印两个路径提示你核对。自启项在下次切换「开机自启」开关时
自动清理旧的。

**QNAP 协议面一字未动**：`cgi-bin/qsync/qsyncsrv.cgi`、`qsync_version`、`service=Qsync`、
`WFM_QSYNC_DISABLED` 等全部照旧 —— 只改了「我们自己的」标识。

## 安装

| 资产 | 说明 |
|---|---|
| `qxync-0.2.1-x86_64-unknown-linux-gnu.tar.gz` | 三个二进制 + 桌面项 / 图标 + 许可证 / 免责声明 |
| `qxync-bin-0.2.1-1-x86_64.pkg.tar.zst` | **Arch 包**（`sudo pacman -U` 直接装） |
| `qxync` · `qxyncd` · `qxync-gui` | 三个裸二进制，同一份构建 |
| `SHA256SUMS` | 校验和（`sha256sum -c SHA256SUMS`） |

解包后三个二进制**放在同一个目录**即可：GUI 先找自己旁边的 `qxyncd`，找不到再退回 `PATH`。
运行 GUI 需要系统里有 WebKitGTK 4.1 / GTK 3 运行时（Debian/Ubuntu：
`libwebkit2gtk-4.1-0` + `libgtk-3-0`），FUSE 3 需要 `/dev/fuse` + `fusermount3`。

```bash
tar xzf qxync-0.2.1-x86_64-unknown-linux-gnu.tar.gz
cd qxync-0.2.1-x86_64-unknown-linux-gnu
./qxync --version        # qxync 0.2.1
./qxync-gui              # 或者把三个文件放进 PATH 里的某个目录
```

**Arch Linux**：直接下 `qxync-bin-0.2.1-1-x86_64.pkg.tar.zst`，
`sudo pacman -U qxync-bin-0.2.1-1-x86_64.pkg.tar.zst`。想自己打或走 AUR：
仓库里带同一份包定义（`packaging/arch/`，包名 `qxync-bin`），`makepkg -si` 即可，
推到 AUR 之后就是 `yay -S qxync-bin`。

> 从 0.1.x 的 Arch 包装上来的话，包管理器会先把旧的 `/usr/bin/qsync` 换掉 ——
> 装完 `which qsync` 应该只剩 QNAP 官方客户端（如果你装过）那一个。

也可以从源码构建（可复现、可审计）：

```bash
git clone https://github.com/mlzxgzy/qxync.git
cd qxync
cargo build --workspace --release
```

需要 **Rust 1.90+**；完整依赖、用法与已知限制见
[README](https://github.com/mlzxgzy/qxync/blob/master/README.md)。

  端到端回归测试（无 link 也能 ping/status/设置读写/干净退出）。

完整清单见 [CHANGELOG](https://github.com/mlzxgzy/qxync/blob/master/CHANGELOG.md#021---2026-10-02)。

## English

# qxync v0.2.1 — the command line is renamed: `qsync` → `qxync`

**This is a rename release — read the upgrade notes before installing.** On 0.1.x the command
line was called `qsync`, which fought the **official QNAP Qsync client** for the same
`/usr/bin/qsync`. This release moves it — along with every other stale name (config directories,
environment variables, xattrs, temp-file suffix, GUI display name) — under `qxync`.

> Note: the version number `v0.2.0` only exists in git history (it was never tagged) —
> **v0.2.1 is the first actual release**, and it contains both the rename and the daemon change
> below.

## The daemon now keeps running with no NAS configured

`qxyncd` used to read a link config at startup and **exit outright** when it was missing — so
"not logged in yet" meant "the daemon is unusable", which directly contradicts running it
permanently in the background (and the GUI pointed you at `qxync daemon start`, which failed
again). Now:

- **Idle standby**: with no connection configured the daemon still starts and stays up, serving
  only `ping` / `status` / `shutdown` plus settings read/write (**plain local files**). `status`
  reports `link: null` and the UI shows "not configured". Requests that need the NAS are
  explicitly rejected (with a "run `qxync login`" hint) instead of being sent to an empty host.
- **Saving a connection takes effect automatically**: the idle daemon checks the link file every
  2 seconds and, when it appears, switches to sync mode **in place** (same process, same pid, no
  re-exec) and starts syncing — no restart, no extra command.
- `qxync daemon start` and the GUI's "start daemon" **no longer refuse to start without a link
  config**.

> ⚠️ For QNAP NAS devices **you own or are explicitly authorized to administer** only.
> This project distributes no QNAP binaries and circumvents no authorization or protection
> measure. It is **not affiliated with QNAP Systems, Inc.** See
> [`DISCLAIMER.md`](https://github.com/mlzxgzy/qxync/blob/master/DISCLAIMER.md).

## ⚠️ Breaking changes (read before upgrading)

| 0.1.x | 0.2.0+ |
|---|---|
| `qsync …` (binary) | `qxync …` |
| `~/.config/qsync`, `~/.local/share/qsync`, `~/.local/state/qsync` | `~/.config/qxync`, `~/.local/share/qxync`, `~/.local/state/qxync` |
| `QSYNC_HOST` / `QSYNC_USER` / `QSYNC_PASSWORD` / `QSYNC_SOCKET`, `QSYNC_*` (tuning + acceptance) | `QXNYC_HOST` / `QXNYC_USER` / `QXNYC_PASSWORD` / `QXNYC_SOCKET`, `QXNYC_*` |
| `getfattr -n user.qsync.state` (also `.pin` / `.remote` / `.vsize` / `.chunks`) | `getfattr -n user.qxync.state` (same suffixes) |
| download temp files `*.qsync-part` / `*.qsync-tmp` | `*.qxync-part` / `*.qxync-tmp` |
| GUI display name `QSync`, log `qsync-gui.log`, tray id `qsync-tray` | `qxync`, `qxync-gui.log`, `qxync-tray` |
| autostart entry `~/.config/autostart/qsync.desktop` | `~/.config/autostart/qxync.desktop` |

**The local directories migrate automatically — no new login.** On first run, if the new
directory is missing but the old one exists, `qsync/` is renamed to `qxync/` (falling back to
copy + delete across filesystems). If **both** exist (for example an early prototype's
`~/.local/share/qxync`), only the entries **missing** from the new directory are filled in —
**nothing already there is overwritten** — and both paths are printed for you to check. A
leftover autostart entry is cleaned up the next time you toggle "launch at startup".

**The QNAP protocol surface is untouched**: `cgi-bin/qsync/qsyncsrv.cgi`, `qsync_version`,
`service=Qsync`, `WFM_QSYNC_DISABLED` and friends are exactly as before — only **our own**
identifiers changed.

## Install

| Asset | What it is |
|---|---|
| `qxync-0.2.1-x86_64-unknown-linux-gnu.tar.gz` | all three binaries + desktop entry / icons / licences / disclaimer |
| `qxync-bin-0.2.1-1-x86_64.pkg.tar.zst` | the **Arch package** (`sudo pacman -U`) |
| `qxync` · `qxyncd` · `qxync-gui` | the three binaries on their own, from the same build |
| `SHA256SUMS` | checksums (`sha256sum -c SHA256SUMS`) |

Keep the three binaries in the **same directory**: the GUI first looks for `qxyncd` next to
itself and only then falls back to `PATH`. Running the GUI needs the WebKitGTK 4.1 / GTK 3
runtime (`libwebkit2gtk-4.1-0` + `libgtk-3-0` on Debian/Ubuntu); FUSE 3 needs `/dev/fuse` +
`fusermount3`.

```bash
tar xzf qxync-0.2.1-x86_64-unknown-linux-gnu.tar.gz
cd qxync-0.2.1-x86_64-unknown-linux-gnu
./qxync --version        # qxync 0.2.1
./qxync-gui
```

**Arch Linux**: grab `qxync-bin-0.2.1-1-x86_64.pkg.tar.zst` and run
`sudo pacman -U qxync-bin-0.2.1-1-x86_64.pkg.tar.zst`. To build it yourself or via the AUR, the
same definition lives in `packaging/arch/` (package name `qxync-bin`) — `makepkg -si` works, and
once published to the AUR it is `yay -S qxync-bin`.

> Upgrading from the 0.1.x Arch package replaces the old `/usr/bin/qsync` — after that,
> `which qsync` should only find the official QNAP client (if you have it installed).

You can also build from source (reproducible and auditable):

```bash
git clone https://github.com/mlzxgzy/qxync.git
cd qxync
cargo build --workspace --release
```

Requires **Rust 1.90+**; see the [README](https://github.com/mlzxgzy/qxync/blob/master/README.en.md)
for the full dependency list, usage and known limitations.

## Relationship to v0.1.1

Features, performance, known limitations and acceptance results are **identical to v0.1.1**
(all eight acceptance matrices green — 491 checks). The substantive changes are **the half of the
naming that is ours** plus the daemon idle state described above, and two smaller things:

- `client_agent` went from the hardcoded `QSyncLinux/0.1` to `qxync/<real version>`
  (`CARGO_PKG_VERSION`), so it can't drift again;
- added two unit tests (directory migration: migrates / fills gaps without overwriting /
  re-runnable) and one **NAS-free** end-to-end regression test (no link still means
  ping/status/settings/clean shutdown).

The full list is in the [CHANGELOG](https://github.com/mlzxgzy/qxync/blob/master/CHANGELOG.en.md#021---2026-10-02).

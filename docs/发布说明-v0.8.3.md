## 一、两步验证登录：先账密、后弹码，不重输口令（M47）

用户原话：

> 「官方的登录是可以先输入账号密码，然后如果要二次验证了，再问用户要二次验证码，
> 不用再输入密码，我们这里好像是强制要重新输入密码，然后甚至重新登录的时候
> 还会记住totp码，一点也用不到」

### 以前的问题

| # | 问题 | 根因 |
|---|---|---|
| 1 | 缺验证码时回的报错带 `--otp-secret`/`--otp-code` —— GUI 用户看着 CLI 参数发呆 | client 把 CLI 指引写进了错误文案（当时只有 CLI 一个前端） |
| 2 | 2SV 缺码 = 一次普通登录失败，用户要重走整张表单（30 秒一换的码很容易在折腾中过期） | 错误是纯文本，GUI 无法结构化识别「这是要验证码」 |
| 3 | 重新登录强制重输口令 —— 明明凭据文件里就有 | GUI `login_flow` 要求 `password` 必填；表单口令框每次填表必清空 |
| 4 | 「记住 TOTP」看不出用没用上 | 已存密钥时确实自动现算（M17 行为），但界面上没有任何反馈 |

### 现在

| 层 | 行为 |
|---|---|
| 信号 | client 在 NAS 回 `need_2sv=1` 且本次没带第二因素时，生成带 `need_2sv:` 机器前缀的错误；daemon 归一到 IPC message 最前；GUI/CLI 据此转各自的交互。选 message 前缀而不是新 `ErrorKind` 变体，是因为老客户端解未知枚举值会让整个响应解析失败，未知前缀只是当正文显示——符合「只加字段不 bump」的 IPC 策略 |
| GUI 表单 | 「保存并登录」先交账密（口令可留空 = 用已存凭据）；NAS 要码 → 弹「只输验证码」小窗（数字键盘 + `one-time-code` 自动填充语义）；拿到码后用同一份表单入参续登——口令第一步已写进凭据，**不再重输** |
| 「立即登录」 | 直接发 IPC `Login`（不重写 link/凭据文件），失败 message 带前缀时同样弹码续登 |
| 口令回退 | `login_flow` 口令缺省 → 回退该连接已存凭据（与 daemon `login_internal` 同一套顺序）；顺带修掉旧代码对**空字符串**口令也放行、会把凭据覆盖成空串的潜在 bug |
| TOTP 可见化 | 已存密钥 → 登录结果行「两步验证：已通过（TOTP）」；没存密钥 → 弹码小窗文案明说「账号口令已通过，NAS 还需要一步验证」 |
| CLI | 两条登录路径（直连 / 经 daemon）识别前缀后补 `--otp-code`（本次）/ `--otp-secret`（保存后自动）指引——指引从 client 错误文案挪到 CLI 层，GUI 用户不再看到 CLI 参数 |

### 升级后怎么确认

```bash
# 2SV 账号（未存 TOTP 密钥）：
qxync-gui   # 连接页 → 保存并登录 → 弹「只输验证码」小窗 → 输 6 位码 → 登录成功
# 已存 TOTP 密钥的账号：
qxync login # 直接成功，输出「两步验证: 已通过（TOTP）」—— 密钥自动现算，全程无感
```

### 边界（如实记）

- **码错不自动重弹**：弹码只问一次，错了按普通登录失败显示（NAS 的拒绝理由里已写明
  「验证码是否已过期（30 秒一换）」），再点一次登录重新弹码——不做自动循环，防止
  「口令错」被伪装成「码错」把用户困在弹窗里。
- **弹码只收 6 位数字**；粘贴 TOTP 密钥请走表单框（那里有归一化与「保存/一次性」
  的完整语义）。
- **验证码仍绝不落盘**；已保存 TOTP 密钥的账号行为与 M17 完全一致。

## 二、`status=3` 不再显示「未知状态码」

用户反馈：`qbox_get_max_log 失败: qbox_get_max_log: status=3 (未知状态码（按失败处理）)`。

这个码早有真机定论（[M10](M10-会话热更新.md) §3：sid 过期后每 30s 一条 `status=3`，
重登即恢复）——M10 时修了**行为**（轮询认 3 → 立即重登，自愈一直在发生），但**显示层**
码表没跟上，用户看到的还是「未知状态码」。现在：

1. 码表补 `3 = 会话失效 / sid 过期`（标注「实测仅 qbox_get_max_log；其它端点语义
   未验证」——不凭码值推广）；
2. 判据从 daemon 私有函数收进 `Error::is_auth()`（端点限定 `context == "qbox_get_max_log"`），
   client 保活、daemon 轮询、FUSE `with_session_retry` 三层自动统一；
3. 顺带修正一处注释与代码的矛盾（`alive_from_max_log` 兜底分支的 `Ok(false)` 在
   `keeper_step` 里就是 `Relogin`——正是 M10 真机日志里保活救回 sid 的那条路径）。

行为不变：status=8（服务端未就绪）依旧不进重登路径；其它端点回 3 依旧不判会话失效。

## 四、升级

```bash
# 1) 换二进制（qxync / qxyncd / qxync-gui 一起换，保持版本一致）
sudo install -m755 target/release/qxync target/release/qxyncd target/release/qxync-gui /usr/bin/

# 2) 重启 daemon（IPC 错误归一在 daemon 侧，需要重启才提供）
qxync daemon stop && qxync daemon start

# 3) GUI 退出重开（托盘右键退出再启动）
```

升级须知：

* **不需要迁移任何文件**：无数据格式变更、无配置变更；`sync.db` / 缓存 / link 文件
  原样可用。IPC 不加方法不加字段，只在错误 message 里引入前缀——老 GUI 配新 daemon
  或新 GUI 配老 daemon 都不会坏（前缀要么被识别、要么当正文显示）。
* **AUR 包**：`packaging/arch/` 的 `sha256sums` 仍需 `updpkgsums` 后再推 AUR
  （既定流程，与历版相同）。

# qxync v0.6.0 —— 同时连多台 NAS，冲突待裁决终于能看清、能处置

**中文** · [English](#english)

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](https://github.com/mlzxgzy/qxync/blob/master/LICENSE-MIT)

**`default` 连接零迁移**：配置、任务文件、缓存目录布局、命令行参数都保持原样，
升级就是换二进制 + 重启 daemon。新能力全部是「多出来的」：多出来的连接、
多出来的任务字段、多出来的待裁决出口。

## 一句话

这一版做了三件事：**① 可以同时连多台 NAS**（每条连接一个 `qxyncd`，各自独立，
停一台不影响另一台）；**② 攒下来的冲突终于能处理**（看不到差异、没有「这条我不想管」
的出口，都补上了）；**③ 按真机取证把一批会伤数据或造成「假象」的问题修掉**
（回收站不再同步、列举失败不再被当成远端删除、熔断告警不再刷屏、恢复后不再常红）。

## 一、多台 NAS，每台多个映射

以前 `qxyncd` 是**单例**：一个进程、一份会话、一套状态，只能连一台 NAS。
现在改成 **一条 NAS 连接 = 一个 `qxyncd` 进程**，每条连接下照旧可以建多个任务
（本地文件夹 ⇄ NAS 文件夹）。

- **彻底隔离**：每条连接有自己的 socket / pid / 日志 / 状态库 / 缓存 / 上传队列，
  **停掉一条连接不影响其它连接**；数据按连接命名空间落盘（`default` 沿用旧目录名，
  其它连接用 `#<id>@<host>`），同一台 NAS 的不同账号也不会互相串 baseline。
- **GUI**：「设置 → 连接」里新增 / 编辑 / 移除连接，可单独启动 / 停止，也能「全部启动 /
  全部停止」；顶栏多了「当前连接」选择器，任务页按连接分组聚合，每张卡标出来源 NAS；
  文件页、诊断页跟随当前连接；设置保存会广播到所有运行中的连接。
- **CLI**：

  ```bash
  qxync links                          # 所有连接 + 各自 daemon / 凭据状态（--json 可机读）
  qxync --link nas2 status             # 全局 --link 路由到指定连接
  qxync daemon start|stop|status|reload --all
  ```

- **systemd**：新增模板单元 `qxyncd@<link_id>`：

  ```bash
  systemctl --user enable --now qxyncd@nas2
  journalctl --user -u qxyncd@nas2 -f
  ```

  `default` 仍用 `qxyncd.service`；**别**再启用 `qxyncd@default`（同一条连接会被拉起
  两个进程），也别让 GUI 和 systemd 同时管同一条连接。
- **移除连接只删登记**（link / 凭据 / peers / 任务登记），**不删**本地文件、NAS 数据、
  cache 与状态库；同一 `(host, port, user)` 拒绝重复添加。
- **旧数据**：`default` 只迁上传队列（`sync/<host>`、`cache/<host>` 原路径继续可用）；
  非 default 连接升级时，legacy 目录会自动迁进新命名空间，迁不动就**拒绝启动**而不是
  带着半份状态跑。

完整设计（命名空间、迁移顺序、并发路径、安全边界与验收）见
[`docs/M16-多NAS连接.md`](M16-多NAS连接.md)。

**边界（重要）**：同一台 NAS 上的两条连接**不要同时双向同步同一个远端目录**
（各有独立 baseline，会互相判成对方的改动）；非 `default` 连接的数据在旧版本里不存在，
回退旧版本会让这些连接失效（`default` 不受影响）。

## 二、「每个文件都问我」攒下的冲突，现在能看清、能处置

以前这个队列只有三个裁决按钮（保留本地 / 保留 NAS / 两份都留），用户**看不到差在哪**，
也**没有「这条我不想管」的出口**。现在：

- **对比本地 / NAS**：行级文本 diff，`-` = 只有本地有、`+` = 只有 NAS 有；超 512 KiB、
  二进制、目录、一边内容读不到时**明确显示原因**，**绝不静默显示「两边逐行相同」**。
- **忽略这条**：只删队列行、不动任何文件；GUI 另有**清空全部**，CLI 对应 `--clear`。
- **引擎巡检自动出队**：远端已删 / 任务已删 / 策略不再是 `ask` / 冲突已自行消解的条目
  自动离开队列（同样只删队列行、不动文件），并说明原因。

这次一起修掉了对比面板的两个「看着正常、其实全错」的问题：**wire 形状读错一层**
导致永远显示 `+0 / -0 / 逐行相同`；**diff 方向标注反了**导致用户可能选错保留哪边
（不可撤销）。两处都补了用生产函数钉死的测试。

## 三、数据安全的几处硬修复（真机取证）

上一版遗留的现场：`baseline` 里 1991 条中 **1425 条在 `/home/@Recycle` 下**、13 条在
`.Trash-1000` 下；一轮对账打算删除 526 项（真机真实删除，但被熔断挡住后**每 30 秒重复
告警 13 小时**，journal 3046 条里 3023 条是同一句话）。据此修复：

- **回收站子树不再参与同步**：`@Recycle`、`.Trash`、`.Trash-<uid>` 从对账、baseline、
  改名配对、事件处理、待裁决队列、上传队列里**全部排除**（与 FUSE 既有的 `deny_trash`
  同一套段级语义）；即使用户写了 `!@Recycle` 这类反向规则也**不会**放回来。
- **列举失败 / 目录被截断不再被当成「远端已删」**：本轮只要有非 404 的列举失败，或目录数
  超过 `max_dirs_per_poll` 只扫了前 200 个，就**暂缓该视图的删除判定**，下一轮列全再删
  —— 这是可能真删本地节点和缓存的数据安全级问题。
- **baseline 的删除与改名真正落盘**：`persist()` 的增量合并会被内存里的旧快照复活删除项，
  导致回收站清理「下一轮又回来」。改为「无并发写 → 整份替换」+ 同步轮串行化。
- **熔断告警按签名去重、恢复后清除**：同一批删除不再每 30s 刷一条 WARN + journal；
  完整跑完的轮次零错误才清「最近错误」，`deletes_blocked==0` 才清熔断告警。
- **会话失效立即重登**：`qbox_get_max_log` 的 `status=3` 不再被塞进 errors 后继续跑，
  轮询循环会立刻重登，不用再等 120s 保活。
- **待裁决队列不再被整队静默删光**：没有挂载视图或本地节点未物化时，巡检不再用占位签名
  当事实（新增 `observed` / `local_observed` 两个观察位）。

同批还修了：diff 的 LCS 内存上界（最坏从 ~275 GB 降到 16 MiB 且明示截断）、
`download_range` 的「200 + JSON 错误体」死防护与区间边界、上传流把读错误吞成 EOF、
LAN 对端的路径重复剥前缀与 fail-open、`read_cached` 把半水合文件的 0 字节当本地内容、
CLI `conflicts` 参数静默优先、GUI 连接页保存静默抹掉选择性同步 / LAN 配置等。
完整清单见 [`CHANGELOG.md`](../CHANGELOG.md)。

## 四、行为变化（升级前请过一眼）

- 冲突策略为 `ask` 时，`conflicts` 计数现在是「**待裁决的文件数**」（首次入队才 +1），
  不再按轮次累计；`deletes_blocked` 仍是累计值，界面与 CLI 都已标注「累计，自 daemon 启动」。
- 回收站排除是**硬约束**：反向规则也放不回来。
- FUSE 挂载点里**仍能看到**回收站目录（引擎已不管理；是否隐藏属产品决定，见已知问题）。
- 非 `default` 连接、`qxyncd@` 模板单元、`links` 子命令都是本版新增；旧版本不认识它们。

## 五、验证状态（如实）

- `cargo test --workspace --lib --bins --tests`：**391 passed / 0 failed / 19 ignored**
  （19 条 `#[ignore]` 全部是需要真机 NAS 的用例，`qxync-proto-test` 里 18 条与 CI 钉死的
  数字一致；另 1 条在 fuse）。`cargo test --workspace --doc` 1 passed。
- `cargo fmt --all -- --check` 0 diff；`cargo check --workspace --all-targets` 0 error / 0 warning。
- `python3 xtask/release/check-version.py v0.6.0` 通过（tag / Cargo.toml / tauri.conf.json /
  AUR PKGBUILD 四处一致，`.SRCINFO` 同步）。
- `qxync-gui --self-test-multi`：两个假连接、两个独立 socket、任务隔离、跨连接覆盖被拒、
  收干净后退出码 0。
- GUI 离线夹具 `xtask/selftest/decisions.html`（真实 app.js / i18n / style + IPC 打桩）
  62/62 断言通过。

**没有验证的（不粉饰）**：本机只有一台可连 NAS，**没有做两台真机 NAS 同时双向同步的
端到端验收**；多连接隔离用假连接 + 单测验证。有条件时建议补一次：A 上建两个任务、
B 上一个任务，停掉 A 的 daemon，确认 B 继续同步、A 的任务在 GUI 里标「当前不会同步」。

# English

# qxync v0.6.0 — several NAS boxes at once, and conflict decisions you can finally see and act on

**中文** · [English](#english)

[![License](https://img.shields.io/badge/license-MIT%20OR%20Apache--2.0-blue.svg)](https://github.com/mlzxgzy/qxync/blob/master/LICENSE-MIT)

**The `default` connection needs no migration**: config, task files, cache layout and CLI
arguments stay exactly as they were; upgrading means swapping the binaries and restarting the
daemon. Everything new is additive: extra connections, an extra task field, extra ways out of
the pending-decisions queue.

## In one sentence

Three things: **(1) connect to several NAS boxes at once** (one `qxyncd` per connection, fully
isolated — stopping one leaves the others alone); **(2) actually handle accumulated conflicts**
(being unable to see the difference, and having no "I don't care about this one" exit, are both
fixed); **(3) fix a batch of data-damaging or illusion-creating problems found on a real device**
(recycle bins are never synced, a failed listing is no longer read as "deleted remotely", the
circuit-breaker alert stops flooding the log, errors stop staying red after recovery).

## 1. Several NAS boxes, several mappings each

`qxyncd` used to be a singleton: one process, one session, one set of state, one NAS. It is now
**one NAS connection = one `qxyncd` process**, and each connection can still host many tasks
(local folder ⇄ NAS folder).

- **Full isolation**: each connection gets its own socket / pid / log / state store / cache /
  upload queue, so **stopping one connection does not affect the others**. Data is namespaced
  per connection (`default` keeps the legacy directory names, other connections use
  `#<id>@<host>`), so two accounts on the same NAS never share a baseline.
- **GUI**: Settings → Connections can add / edit / remove connections and start / stop them
  individually or all at once; the top bar has a "current connection" switcher; the Tasks page
  groups by connection and every card names its NAS; Files and Diagnostics follow the current
  connection; saving settings broadcasts to every running connection.
- **CLI**:

  ```bash
  qxync links                          # all connections + daemon / credential status (--json)
  qxync --link nas2 status             # the global --link routes to that connection
  qxync daemon start|stop|status|reload --all
  ```

- **systemd**: new template unit `qxyncd@<link_id>`:

  ```bash
  systemctl --user enable --now qxyncd@nas2
  journalctl --user -u qxyncd@nas2 -f
  ```

  `default` keeps using `qxyncd.service`; do **not** enable `qxyncd@default` as well (it would
  start two processes for one connection), and do not let the GUI and systemd manage the same
  connection concurrently.
- **Removing a connection deletes only the registration** (link / credentials / peers / task
  entries); it never deletes local files, NAS data, caches or state stores. The same
  `(host, port, user)` cannot be added twice.
- **Existing data**: `default` only migrates the upload queue (`sync/<host>` and
  `cache/<host>` keep working at their old paths); for non-default connections the legacy
  directories are migrated into the new namespace, and a migration failure **refuses to start**
  rather than running with half the state.

Full design (namespaces, migration order, concurrency, safety boundaries, acceptance) is in
[`docs/M16-多NAS连接.md`](M16-多NAS连接.md).

**Boundaries (important)**: do **not** bidirectionally sync the same remote directory through two
connections to the same NAS at the same time (each has its own baseline and they would read each
other's writes as changes). Non-default connections **do not exist in older versions**, so
rolling back makes them unavailable (`default` is unaffected).

## 2. Conflicts accumulated under "ask me for every file" are now visible and actionable

The queue used to offer only three resolve buttons (keep local / keep NAS / keep both); users
could not see **what** differed and had **no "ignore this one" exit**. Now:

- **Compare local vs NAS**: a line-level diff where `-` means only the local side has the line
  and `+` means only the NAS side does. Above 512 KiB, for binaries, directories, or when one
  side cannot be read, the reason is stated explicitly — it **never silently claims "the two
  sides are identical line by line"**.
- **Ignore this one**: deletes only the queue row, never a file; the GUI also has **Clear all**,
  with `--clear` in the CLI.
- **The engine sweeps stale rows**: entries whose remote file is gone, whose task was removed,
  whose policy is no longer `ask`, or whose conflict resolved itself leave the queue
  automatically (again, queue rows only) with a stated reason.

Two "looks fine but is wrong" bugs in the compare panel were fixed too: a misread wire shape made
it always show `+0 / -0 / identical`; the diff direction labels were reversed, which could make
users pick the wrong side to keep (irreversible). Both now have tests pinned to the production
functions.

## 3. Hard data-safety fixes (from real-device evidence)

The previous release left this on a real device: of 1991 baseline rows, **1425 lived under
`/home/@Recycle`** and 13 under `.Trash-1000`; one reconciliation round wanted to delete 526
entries (genuine remote deletes, but after the breaker stopped them the alert repeated every
30 seconds for 13 hours — 3023 of 3046 journal rows were the same sentence). Fixes:

- **Recycle-bin subtrees never take part in sync**: `@Recycle`, `.Trash`, `.Trash-<uid>` are
  excluded from reconciliation, baseline, rename pairing, event handling, the decisions queue and
  the upload queue (same segment-level semantics as FUSE's existing `deny_trash`); even a
  user-written re-include rule such as `!@Recycle` cannot bring them back.
- **A failed listing or a truncated directory is no longer read as "deleted remotely"**: any
  non-404 listing failure, or a directory count above `max_dirs_per_poll` (only the first 200
  scanned), now **defers that view's delete decisions** until a complete listing is available.
  This could really delete local nodes and caches — data-safety level.
- **Baseline deletes and renames are actually persisted**: `persist()`'s incremental merge let
  the in-memory snapshot resurrect deleted rows, so recycle-bin cleanup "came back every round".
  It is now "replace the whole snapshot when no concurrent writer exists" plus serialised sync
  rounds.
- **Breaker alerts are de-duplicated by signature and cleared on recovery**: one batch of blocked
  deletes no longer writes a WARN + journal row every 30 s; "last error" is cleared only after a
  fully completed error-free round, and the breaker alert only when `deletes_blocked == 0`.
- **Session loss triggers an immediate re-login**: a `status=3` from `qbox_get_max_log` is no
  longer stuffed into errors and ignored; the polling loop re-logs in at once instead of waiting
  up to 120 s for keepalive.
- **The decisions queue is no longer silently wiped** when there is no mount view or no
  materialised local node: the sweep no longer treats placeholder signatures as facts (new
  `observed` / `local_observed` facts).

The same batch also fixed: the LCS memory bound in diff (worst case ~275 GB → 16 MiB, with an
explicit truncation note), `download_range`'s dead "HTTP 200 + JSON error body" guard and range
edges, upload streaming swallowing read errors as EOF, LAN peers double-stripping the path prefix
and failing open, `read_cached` treating a partially hydrated file's zero bytes as local content,
CLI `conflicts` silently preferring one flag, and the GUI connection page silently wiping
selective-sync / LAN settings. The complete list is in [`CHANGELOG.en.md`](../CHANGELOG.en.md).

## 4. Behaviour changes (check before upgrading)

- With the `ask` conflict policy, `conflicts` now counts **files waiting for a decision** (first
  enqueue only) instead of accumulating per round; `deletes_blocked` remains cumulative and is now
  labelled "(cumulative, since daemon start)" in the UI and CLI.
- Recycle-bin exclusion is a **hard rule**; re-include rules cannot override it.
- The FUSE mount still lists recycle-bin directories (the engine no longer manages them; hiding
  them is a product decision — see known limitations).
- Non-default connections, the `qxyncd@` template unit and the `links` subcommand are new in this
  release; older versions do not understand them.

- `cargo test --workspace --lib --bins --tests`: **391 passed / 0 failed / 19 ignored** (all 19
  `#[ignore]`d tests need a real NAS; the 18 in `qxync-proto-test` match the number pinned in CI,
  plus 1 in fuse). `cargo test --workspace --doc`: 1 passed.
- `cargo fmt --all -- --check`: 0 diff. `cargo check --workspace --all-targets`: 0 errors,
  0 warnings.
- `python3 xtask/release/check-version.py v0.6.0` passes (tag / Cargo.toml / tauri.conf.json /

- `qxync-gui --self-test-multi`: two fake connections, two independent sockets, task isolation,

**Not verified (no sugar-coating)**: this machine can reach only one NAS, so there was **no

covered by fake connections plus unit tests. When you have a second NAS, one good check is: two
tasks on A, one on B, stop A's daemon, confirm B keeps syncing and A's tasks still show up in the
GUI marked "not syncing right now". The `#[ignore]`d real-NAS tests were not run here either.

Known limitations (not fixed in this batch) are listed under "Known limitations" in
[`CHANGELOG.en.md`](../CHANGELOG.en.md); the ones worth scheduling: a FUSE materialise-by-path API,
hiding recycle bins from the mount view, and showing "N decisions waiting" on the home page.

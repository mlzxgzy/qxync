# v0.9.2 —— 会话失效自愈：别再弹「同步错误」

> 发布日期：2026-11-02
> 上一版：[v0.9.1](发布说明-v0.9.1.md)（截图与历史脱敏修复）

## 一句话

```text
sid 过期（status=3）现在是一个自愈事件，不是同步错误：
  → 立即重新登录、拿到新 sid、用新会话重跑本轮，用户完全无感
  → 不再有「⚠️ 同步错误（…）」红字、不再写 last_error、不再发桌面通知
  → 只有「重登也失败」才报一条告诉你去哪重新登录的错误
```

本版**没有新功能、没有数据格式变更**；发布说明也**不再嵌入任何截图**（正文纯文字）。

## 你看到的问题

同步时弹出：

```text
同步错误（…）：qbox_get_max_log 失败: qbox_get_max_log: status=3
(会话失效 / sid 过期（实测仅 qbox_get_max_log；其它端点语义未验证）)
```

问题不在「会话失效」本身——重登一次就好，而且自愈（重登）其实早就在跑。
问题在于**它被当成同步错误上报了**：同一件事同时出现在三处，并且重登后要等下一轮
（默认 30 秒）才重试，而不是立即重试。

## 根因

`qbox_get_max_log` 回 `status=3`（会话失效 / sid 过期）时，`poll_once` 和业务错误一样
把它写进 `errors`，于是：

| 落点 | 用户感受 |
|---|---|
| GUI 首页红字 | 「⚠️ 同步错误（…）」 |
| `last_error` | 首页 / 诊断页 / 托盘都显示错误 |
| journal `error` 条目 | **桌面通知弹窗**的数据源 |

而 `run_sync_once` 在重登成功后不会立刻重试，要等下一轮同步。

## 现在的行为

| 情况 | 行为 |
|---|---|
| sid 过期、重登成功 | **完全静默**：不写 `errors` / `last_error` / journal，无红字无弹窗；daemon 立即重新取凭证（sid）并用新会话**重跑本轮**（不等 30 秒） |
| 重登也失败（口令 / 两步验证 / 网络） | 只报**一条可操作**的错误：「会话失效且未能自动恢复：…。请确认 NAS 上的口令/两步验证没变，或在「设置 → 连接」里重新登录」；同一条只报一次，恢复后复位（复发会再报） |
| 重登成功但重跑仍失效 | 升级为「自动重新登录后仍然无法同步：…」，同样只报一次 |

实现要点：

- `SyncReport::auth_failure()`：会话失效只置 `auth_failed` + `auth_error`（debug 日志），
  **不进 `errors`**；`qbox_get_max_log` / `qbox_get_sync_log` / config log / notify
  任一跳鉴权失败直接收尾本轮（游标不越过未应用的批次），对账阶段会话失效也收尾。
- `run_sync_once` 看到 `auth_failed` → `login_internal` 换新会话 → **立即重跑一轮**；
  失败才走升级文案。每轮最多重登一次，避免凭据真坏时撞 NAS 的失败登录封锁。
- 顺带收窄两处会误触发整轮重登的判据：远端根列举 4/5 走自愈（说明行保留、红字去掉）；
  单行巡检 `stat` 的 4/5 不再置 `auth_failed`（4/5 也可能是「路径不存在 / 权限拒绝」，
  一条 ACL 路径不该让登录次数涨上去）。

## 升级

```bash
# Arch
sudo pacman -U qxync-bin-0.9.2-1-x86_64.pkg.tar.zst
# Debian / Ubuntu
sudo apt install ./qxync_0.9.2-1_amd64.deb
```

无数据格式变更、无配置变更，`0.9.1 → 0.9.2` 直接覆盖安装即可。

**修复在 daemon 里：升级后要重启守护进程**（旧进程不会自己变）：

```bash
# systemd 用户服务
systemctl --user restart qxyncd
# 或
qxync daemon stop && qxync daemon start
```

## 已知边界

- **真机 NAS 上的「重登 + 重跑」链路未验证**：本机没有可用 NAS 会话，mock 只覆盖
  `status=3` 的判定与「不进 errors」的语义。建议重启后再让它自然过期一次确认。
- `status=8`（服务端未就绪）不进入重登路径；其它端点回 `3` 依旧不判会话失效
  （只有 `qbox_get_max_log` 在真机观测到过 `3`，不按码值推广）。
- 会话失效本身仍会中断当次同步（本轮收尾），只是不再当作错误上报；下一轮由自愈补上。

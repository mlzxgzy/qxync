# M21：离线可重启 daemon

> **一句话**：断网时重启 daemon（或断电后开机），挂载点**立即**恢复 —— 不等登录、
> 不等网络；恢复出来的挂载点离线可用（`ls` 吃持久化清单、`cat` 走缓存认领、写操作
> 进缓冲区），联网后自动补登并热推会话。
>
> 用户原话（2026-10-19）：「做一下离线可重启 daemon，否则急用会出问题。。。」

---

## 0. 结论先行

M20 的已知限制「离线重启 daemon，挂载点要等联网才恢复」在本版消灭。核心是三件事：

1. **无会话挂载**：`mount()` 不再要求已登录。挂载本身不需要 NAS —— 需要网络的是
   水合与上传，而这两样离线时本来就有各自的诚实降级（EIO / 缓冲区）。
2. **目录清单持久化**（`sync.db` 新表 `listings`，schema v5 → v6）：M9 的清单快照
   让 `readdir`/`lookup` 不必问 NAS，但它只在内存 —— 重启即空。现在写穿到状态库、
   挂载时整份装回。
3. **挂载记录补 `cache_dir`**：`mounts.json` 以前刻意不存缓存目录，恢复时落回默认
   目录 —— 自定义 `--cache-dir` 的挂载恢复后**认领不到旧缓存**（在线重启白白重新
   水合，离线重启直接读不了已水合内容）。现在存**父目录**（`mount()` 按当前 link
   重拼命名空间，不固化「连的是哪台 NAS」）。

启动恢复也不再等 sid（旧实现最多等 10s 然后整批失败）—— 直接恢复，登录成功后
`push_sid_to_mounts` 把 sid 热推进来（`mount_user` 为空的挂载点按同账号处理）。

## 1. 旧行为到底哪里「有问题」

| 场景 | 旧行为 | 后果 |
| --- | --- | --- |
| 离线重启 daemon | 启动恢复先等 sid（最多 10s），`mount()` 里 `ensure_session?` + `require_sid?` 失败 → 整批挂载失败 | **挂载点消失，直到联网登录成功**。断电重启的机器没网时，文件管理器里整个目录树不见了 —— 「急用出问题」 |
| 重启后的挂载点（假设能挂上） | 节点表、清单快照全是进程内状态 → 空 | `ls` 根目录 EIO（无快照 + 已知离线）；已水合文件也无法读（节点物化不出来 → 无从认领缓存） |
| 自定义 `--cache-dir` 的挂载（任何重启） | `mounts.json` 不存 cache_dir → 恢复用默认目录 | 在线重启：重新水合一遍（浪费流量）；离线重启：已水合内容读不了 |
| 离线改名目录后重启 | 清单快照只搬目录自身（M20 修复），子目录快照留在旧路径 | 重启后 `ls 新路径/子目录` 无快照 → 离线 EIO |
| 远端改名/删除目录（daemon 侧推送） | `rename_remote` / `remove_remote` 不动清单快照 | 旧路径快照残留 → 离线重启后幽灵目录复活 |

**根因**：挂载点的「可用性」被绑在了「会话」上，而挂载点真正需要的本地状态
（清单、缓存、队列）其实都在盘上 —— 只是没人把它们接回来。

## 2. 设计

### 2.1 无会话挂载（`daemon::mount`）

```text
已知离线（connectivity 判定）      → 连登录都不试（省 20s connect timeout），直接无 sid 挂载
Unknown / Online                    → 保持旧语义：ensure_session（在线登录 ~1-2s）
登录失败（离线 / 凭据问题）          → WARN + 无 sid 挂载（不再 ? 传播失败）
```

无 sid 的挂载点：

- `ls` / `lookup`：吃装回的清单（见 2.2），不碰 NAS；
- `read`：已水合区间走缓存认领（签名 + 身份 + 逐区间 xxhash 校验，与在线路径同一套）；
  未水合区间诚实 EIO（M20 语义不变）；
- `write` / `mkdir` / `rename`：进 outbox / 上传队列（M20 语义不变）；
- 水合等需要 sid 的操作：失败 → 会话经纪人 / 轮询器懒登录 → `login_internal` →
  `push_sid_to_mounts`（`mount_user` 为空 = 按同账号热推）→ 原地恢复，无需重挂。

### 2.2 目录清单持久化（`sync.db` v6：`listings` 表）

```sql
CREATE TABLE IF NOT EXISTS listings (
  dir          TEXT PRIMARY KEY,   -- 远端绝对路径
  entries      TEXT    NOT NULL,   -- Vec<DirEntry> 的 JSON（含 file_id）
  updated_unix INTEGER NOT NULL DEFAULT 0
);
```

**写穿点**（内存改完顺手落库，失败只 WARN —— 内存是本次会话的真相，落库只服务
「离线重启后还能 ls」；与 outbox 的「落库失败必须 EIO」刻意不同：outbox 丢行 = 丢
操作，清单丢行 = 旧视图，联网后 `apply_listing` 会整份换新）：

| 变更点 | 位置 | 持久化动作 |
| --- | --- | --- |
| 轮询推送 | `FsHandle::apply_listing` | upsert |
| 挂载预热 | `FsHandle::seed_listing`（真灌入时） | upsert |
| TTL 后台补拉 | `run_listing_refresh` | upsert |
| 冷路径首次列举 | `QxyncFs::dir_entries` | upsert |
| 本地 mkdir | `materialize_local_dir`（父清单 upsert + 空清单） | upsert ×2 |
| 本地 create | `create` 回调 | upsert |
| 本地 unlink/rmdir | `remove_entry` | upsert |
| 本地 rename | FUSE `rename` 回调 | 子树 move + 两边父清单 upsert |
| 远端改名 | `FsHandle::rename_remote` | 子树 move + 两边父清单 upsert |
| 远端删除 | `FsHandle::remove_remote` | 子树 delete |
| 远端目录没了 | `FsHandle::drop_listing` | delete |

**装回**：`QxyncFs::with_nodes_store` 注入 Store 时一次性 `listing_load_all()`，
按 `fetched = now` 计龄（TTL 过期后后台补拉：离线失败、快照照常服务；在线换新）。
单行损坏只跳过该行（`listing_load_all` 返回损坏清单，调用方 WARN）。

**语义**：`listings` 是「最后一次已知的目录内容」，不是权威状态 —— 行丢了/旧了
都只是「离线重启后少看见一些东西」，与 `nodes` 表「可重建的派生索引」同一条
设计线。连接级 purge 删整个 `sync.db` 时一并消失；任务级 purge 不清（与 outbox
一致，见 M20 §5）。

### 2.3 子树搬移（修 M20 的一个缺口）

`listing_move`（内存）与 `Store::listing_move_prefix`（持久化）都改为**整棵子树**
搬：`/a → /b` 时 `/a/x` 的快照也搬到 `/b/x`。段级前缀（`/a` 不命中 `/ab`）与
`outbox_rewrite_prefix` 同一套规则。

只搬自身的后果（M20 遗留）：改名前已列过的子目录在新路径下「无快照」—— 在线时
多一次 NAS 往返，**离线（含离线重启后）`ls` 直接 EIO**。`rename_remote` /
`remove_remote`（daemon 侧远端改名/删除）同样补上子树搬移/清理。

### 2.4 清单条目的签名一致性（真机验收抓到的三个坑）

清单是「最后一次已知的目录内容」，但**条目的签名**（size/mtime）有四个来源会互相
打架，离线重启的认领（`cache_file_for`）要求清单签名与 `.qxstate` 完全一致 ——
任何一处没跟上就是「缓存明明在盘上却 EIO」。真机验收（2026-10-19，真 NAS + 真
挂载 + 断网）逐个抓到并修掉：

| 坑 | 现象 | 修法 |
| --- | --- | --- |
| create 的 upsert 输给挂载预热 | `hello.txt` 从此不在根清单里（预热 seed 落地前 create，upsert 是 no-op），断网重启后文件**不可见** | 上传成功钩子里补一笔：`note_uploaded_listing` 把「刚传上去的那版」签名刷进清单（上传完成的一瞬，竞态窗口从 30s 缩到 0） |
| 写完的文件清单条目停在 `size=0` | `cached.txt` 的清单条目是 create 时刻的占位，写完后没人更新 → 重启后按清单物化的节点与 `.qxstate` 对不上 → 认领失败 | `release`（关文件）时按**最终**签名刷新清单条目（dirty 的文件才刷，只读打开不写库）；`setattr`（截断/touch）用 `force` 刷新 |
| 轮询抓到 `set_mtime` 可见性窗口内的服务端时间 | 清单 mtime 比真值偏 1 秒 → 认领签名不匹配 → EIO（在线时 M9 内容刷新会自愈，离线重启卡在窗口内就死） | 认领的 **mtime 偏斜容差**：清单 mtime 与 `.qxstate` 不符时查 baseline —— baseline 记录的「我们最后传上去的那版」与 `.qxstate` 完全一致 → 按 `.qxstate` 认领并把节点签名对齐到真值；baseline 不认识（如「删了重建」的旧缓存）→ 仍拒绝，「绝不返回错误内容」红线不动 |

（第四个来源是轮询的 `apply_listing` 整份换新 —— 它本来就是权威路径，无需处理。）

### 2.5 `mounts.json` 补 `cache_dir`（父目录）

```json
{ "mountpoint": "...", "remote": "/home", "...": "...", "cache_dir": "/custom/parent" }
```

存的是调用方给 `mount()` 的参数原样（父目录），恢复时 `mount()` 按当前 link 重拼
`link_namespace` —— 换 NAS / 换账号不错位（旧版「故意不存」的理由针对的是**拼好
主机名的最终路径**，存父目录没有那个问题）。老文件没有这一栏（`serde(default)`）
→ `None` → 默认目录，行为不变。

### 2.6 启动恢复不等 sid

```text
旧：spawn { 等 sid 最多 10s → restore_mounts_on_start }
新：spawn { restore_mounts_on_start 立即跑 }
```

在线路径不受影响（挂载完成时登录通常已就位；就算没有，水合会在 sid 热推后自愈）。
离线路径从「等 10s → 整批失败」变成「立即恢复」。

## 5. 已知限制

1. **没列过的目录**离线重启后仍 `ls` 不了（诚实 EIO）—— 清单只持久化「列过的」。
   根目录在挂载/轮询时必然有清单；本地建的目录有空清单；其余要在线时被访问过
   （`ls` 过）才有。
2. **离线重启后物化的节点 `remote_known = true`**（从清单物化的默认值），哪怕它是
   离线新建、还没上传的。后果是有限的：改名/删除会多排一条远端操作，回放时按
   「源和目标都不在」放弃并留 journal，上传仍按新名字落地 —— 终态正确，多一条
   journal 噪音。不做「挂载时对照 outbox/上传队列修正」：那份快照会过期，过期后
   朝反方向错（漏发远端 rename → 冲突副本），比 journal 噪音危险。
3. **清单是快照不是订阅**：离线期间远端被别的设备改了，重启后看到的还是旧清单；
   联网后轮询 `apply_listing` 换新（根目录每轮必刷，其余按轮转窗口）。
   同理，清单条目在「写完到上传之间」的窗口里可能落后于真实签名 —— release /
   上传钩子已把窗口压到最小，但极端时序（写完立刻断电）下仍可能偏。
4. 任务级 purge 不清 `listings`（与 outbox 一致）；连接级 purge 删整个 `sync.db`。
5. `mounts.json` 的 `cache_dir` 存父目录：老版本二进制读新文件时忽略该字段
   （serde 默认忽略未知字段），但恢复会落回默认缓存目录 —— 跨版本降级时缓存
   认领不到，重新水合即可。
6. **离线时 `daemon stop`（不带 `--force`）的排空**：已知离线时直接跳过（M20）；
   排队**中途**断网（连通性还没翻成「已知离线」）时，worker 第一次上传失败
   置离线后 drain 立即中止 —— 最坏等一次在途请求的 connect timeout，不再
   陪等满 120s（★ M22 修复，见 [`M20-离线缓冲区.md`](M20-离线缓冲区.md) §5.8）。

## 6. 与既有设计的关系

- **M20（离线缓冲区）**：本版是它的直接续篇 —— M20 管「离线时会话内不丢」，
  M21 管「离线时跨重启不丢」。outbox / 队列冻结 / 回放 / 短探活全部复用，未改。
- **M9（目录清单快照）**：`listings` 表是 M9 内存快照的持久化形态，写穿点与
  M9 的更新点一一对应；`seed_listing` 的「只在还没有快照时灌入」语义原样保留
  （迟到的预热不覆盖新状态）。
- **M15/T5（挂载恢复）**：恢复的三个不变量里第 1 条（必须已登录）按 M21 修订；
  `cache_dir` 补进了「可复现参数」。
- **M15/T9（nodes 表）**：`listings` 与 `nodes` 同为「可重建的派生状态」，
  丢行只退化（少看见 / 配不上对），不丢数据。

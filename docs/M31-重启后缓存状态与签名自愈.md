# M31 · 重启后缓存状态恢复与位图签名自愈

> 真机反馈（2026-10-23）：
> **「重新挂载后，好像缓存就没了，原来水合过的文件又变成白云了。」**
>
> 结论：**内容一份没丢**。是两个「只在内存里正确」的状态叠在一起：
> ① 水合状态落盘了但**只在第一次 `read` 才读回来**（显示层全变回占位符）；
> ② 位图签名在 `mtime` 被改之后**没有跟着改**，重启后严格比对必然失配 →
> 整份缓存被当成「不可信」重新从 NAS 下载（数据面也真的回源了）。

## 1. 真机取证

| 检查 | 结果 |
|---|---|
| 缓存目录 `~/.local/share/qxync/cache/qnap.kdajv.com` | **392 份 `.qxstate` / 386 份全量就绪 / 约 495 MiB 内容**（内容都在） |
| 重挂后 `qxync status` | 已缓存 **7.6 KiB** / 水合文件 **1** / 共 210 |
| 重挂后 xattr | `user.qxync.state=placeholder`、`user.qxync.overlay=placeholder`、`chunks=0/0` |
| 读一个 5,261,339 字节的 `A.pdf` | `水合统计` 0 → **41 次 / 5,261,339 字节**（4.6 秒，真的回源下载了） |
| 签名核对 | 392 份里 **326 份**「清单 mtime 比位图 mtime 更旧」；66 份完全一致 |

396 份里 325 份的位图头 mtime 都落在同一天 09:4x —— 对得上那天一次 `cp -a` 批量拷入。

## 2. 根因

### 2.1 位图「写了」但「没读回来」（显示层）

M9 把区间位图（`chunks_done`）落盘到 `<cache>.qxstate`，但**读回它**只有一处：
`cache_file_for`（第一次 `read`/`open` 的认领路径）。

daemon 重启 / 重新挂载后，节点表从远端清单重建，每个节点的 `chunks_done` 都是空的；
而下面这些**读路径**全部只看内存节点：

* `getattr` 的 `user.qxync.state` / `user.qxync.chunks` / `user.qxync.overlay` / `user.xdg.tags`
  （Dolphin 角标、Tags 列）；
* `qxync status` 的「已缓存 N / 水合文件 M」（`FsHandle::cache_stats`）；
* GUI 文件页的三态（仅在线 / 本地可用 / 始终可用）。

于是「磁盘上有内容」不等于「报出来有内容」—— 重启后整列已水合文件都变回 ☁，
用户看到的就是「缓存没了」。内容其实一份不少，第一次读就会默认认领回来
（**除了** 2.2 的签名失配：那部分即使读也会重新下载）。

### 2.2 mtime 被改后位图签名不更新（真实的回源下载）

`cp -a` / `rsync -a` 往挂载点里拷文件的时序：

1. 写内容 → `close` / `release`：位图落盘，记下**写盘时刻** `T1`；
2. 工具再 `utimensat`，把源文件时间戳 `T0` 设回来；
3. FUSE `setattr` 更新节点 attr、把新 mtime 推到 NAS、刷新清单 ——
   **但没有回写 `.qxstate` 头**；
4. 重启后清单/节点说 `T0`、位图说 `T1` → `cache_file_for` 严格比对签名 →
   拒认领 → 整份缓存重新下载。

真机 326/392 命中；`A.pdf` 实测回源下载 41 个区间。
次要放大器：在线 `setattr` 只推远端 `set_mtime`，**没有同步在途上传作业的 mtime**
（离线路径有），上传 worker 随后可能再用旧 mtime 覆盖一次。

这两个缺陷方向相反又互相掩盖：只要不重启，内存里的 `chunks_done` 一直是对的，
谁都不会发现盘上的位图和清单已经分叉。

## 3. 修复

### 3.1 挂载时重建水合索引（显示立刻正确，零网络）

* `scan_cache_index()`：挂载时扫 `<cache>/*.qxstate`，**只读头 + 位图、不读内容**
  （代价与文件大小无关，真机 392 份约几毫秒），建
  `HashMap<fnv1a64(remote) → CachedSig>`；挂载日志打一行
  「缓存状态索引：N 份水合位图 / 已缓存 X MiB」。
* `insert_node` 物化节点时按签名**预填** `chunks_done` / `whole_xxhash`（不建缓存文件、
  不发网络）。条件与认领同源：size 一致，且「mtime 一致」或「清单更旧 + 全量就绪」。
  清单更新方向**不预填**（远端可能真改过）。
* `cache_stats()` 改从索引统计（与「浏览到哪个目录、物化了几个节点」无关）；
  `status` 的「共 N」分母改用 baseline（已知远端文件数），不再出现
  「水合文件 386 / 共 210」这种分子大于分母。
* GUI 文件页三态：节点未物化时用 `cached_bytes_for(remote, size, mtime)` 兜底，
  不再把已缓存文件显示成「仅在线」。
* 索引维护：`persist_chunk_state` / 认领对齐 → 更新；删除 / 脱水 / 失效 / 删除队列 →
  同步清掉（`index_forget`）。

### 3.2 认领的第二种容差（历史数据自愈，不重下）

`cache_file_for` 在签名失配时新增一条分支：

> 清单 mtime **比位图更旧** + 位图**全量就绪** + **逐区间 `xxhash64` 全过**
> → 认领本地内容，并把 `.qxstate` 头签名**对齐到清单**（内容没变，只是签名来源不同）。

严格边界不变：

* 清单 mtime **更新**（远端可能真的改过）→ 不认领，回源；
* 任一区间校验和不过 → 不认领，回源；
* 「绝不返回错误内容」的红线不动 —— 乐观的只允许是**显示**，不是内容。

### 3.3 从源头不再制造分叉

`setattr` 只改 mtime（`touch` / utimensat）且内容没变时，
`resync_cache_signature()` 把 `.qxstate` 头的 mtime + `file_id` 同步过去；
在线路径也补上 `update_pending_mtime()`（与离线路径一致）。
已排队 / 在飞的后台刷新期间跳过 —— 那会儿签名本来就是中间态。

## 4. 安全边界

| 场景 | 行为 |
|---|---|
| 清单 mtime 更新（远端可能改过） | 不预填、不认领、回源 |
| 清单更旧但内容校验和不过 | 不认领、回源 |
| 只是显示（xattr / status / GUI） | 可乐观（来自索引），不影响内容 |
| 首次 `read` | 仍然逐区间核 `xxhash64`（T3 原样保留） |
| 内容写入 / 截断 / 后台刷新 | 位图由原路径（write/release/install_refreshed）刷新 |

## 6. 已知限制

* 0 字节文件的 `hydrated_bytes=0`，GUI 三态仍显示「仅在线」（读不受影响）。
* 未物化节点的 `pin` 显示仍沿用旧行为（本次只修缓存状态，不动 pin）。
* 历史失配条目在**首次读取**时自愈；不读就只显示「已缓存」（索引口径），
  不主动回写签名（下一次读写会顺手落盘）。
* **`.qxsum` 陈旧（独立问题，未在本次修复范围）**：真机 193 份缓存的
  `.qxsum` 与内容不符，但抽查内容本身与 NAS 一致 —— 属于「校验和表写坏了」，
  不是「内容坏了」。T3 安全闸会照章拒绝认领 → 这些文件在首次读取时重新下载
  一次（内容正确、带宽浪费一次）。`qxync verify` 能列出全部 193 个。
  修复方向（M32）：找出 `.qxsum` 与内容分叉的写入路径；在此之前安全闸不能放宽。

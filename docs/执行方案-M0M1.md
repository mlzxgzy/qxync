## 1. 实测事实（可复现，附证据路径）

### 1.1 登录链

权威参考不是 Windows 二进制，而是 **NAS 自己的 Web UI 前端 JS**：
`/cgi-bin/js/qos-core-login.js`（本地副本 `report/probe/probe-out/webui/qos-core-login.js`），
其中 `login()` 组装的请求体是：

```js
params = { user, serviceKey: 1, client_agent: navigator.userAgent, client_app: "Web Desktop", vtoken }
params.pwd = QNAPTool.ezEncode(QNAPTool.utf16to8(pwd))   // ezEncode = 标准 base64
```

**实测确定的最小可用请求**（已验证 `authPassed=1`）：

```http
POST /cgi-bin/authLogin.cgi
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
X-Forwarded-For: 127.0.0.1

user=test1&serviceKey=1&client_app=Qsync&client_agent=<UA>&remme=0&dont_verify_2sv_again=0
&pwd=<base64(utf8(口令))>&gen_client_id=1&r=<随机数>
```

响应：`<authPassed>1</authPassed>` + `<authSid>xxxxxxxx</authSid>` + `<username>test1</username>` + `<cuid>…</cuid>`

**对照实验（关键！排除猜测）**：

| 实验 | 请求体差异 | 结果 |
|---|---|---|
| 原始 probe 写法 | `service=Qsync` + `pwd=明文` | ❌ `authPassed=0 errorValue=-1` |
| A | `serviceKey=1` + `pwd=明文` | ❌ 同上 → **base64 是必需的** |
| B | `serviceKey=1` + `pwd=base64` + `client_app=Qsync` | ✅ **通过** |
| C | `service=Qsync` + `pwd=base64`（Windows 客户端风格） | ❌ → **`service` 这个字段名是错的** |

> 推论：报告 02 §2.4「口令以 `auth_data`+`iv` 提交」只适用于**共享文件夹二次鉴权**；
> 账号密码登录就是 QNAP 前端的 `ezEncode`（标准 base64）。静态逆向在这点上被误导了。

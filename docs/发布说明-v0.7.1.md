# v0.7.1 —— Dolphin 集成：水合状态进 Tags 列（M23）

> 发布日期：2026-10-20
> 上一版：[v0.7.0](发布说明-v0.7.0.md)（离线可用与累计缓冲区 + 离线可重启）
>
> **新功能版**：KDE 用户在 Dolphin 里**一眼看清每个文件的水合状态** ——
> `仅在线 / 部分本地 / 已水合` 直接显示在 Dolphin 自带的 Tags 列（F11 信息面板
> 同样可见），不用装任何插件、不用改 Dolphin。开关默认关，开启前有 Baloo 门禁
> 与 GUI 一键排除，真机验证 9/9 全绿。

**升级就是换二进制 + 重启 daemon**（`systemctl --user reload qxyncd` 可不断挂载点）。

## 一句话

以前想知道「这个文件到底下载下来没有」要 `getfattr` 或者去设置页翻缓存统计。
现在 KDE 用户右键列头勾一个 **Tags**，状态就在文件列表里 —— 原理是 qxync 的
FUSE 层把水合状态动态写进 freedesktop 标准的 `user.xdg.tags` xattr，而 Dolphin
的 Tags 列恰好直接读这个属性（不经过 Baloo 索引库）。改动全部在 Rust 侧，
十几行核心逻辑，零 C++ 插件。

## 〇、怎么用（三步）

```text
1. 把挂载点排除出 Baloo 索引（一次性）：
   balooctl6 config add excludeFolders ~/qxync-mnt
2. 打开开关（GUI：设置 → 高级 → 「在 Dolphin 里显示水合状态」；
   或 qxync settings --set dolphin_tags=true）
3. Dolphin 里右键列头 → 勾 Tags
```

GUI 的流程更顺：预检不过会弹确认框，点「打开终端，自动添加排除」—— konsole
（`--hold`）里逐条自动执行 `balooctl6 config add excludeFolders <挂载点>` 并列出
最终排除清单，跑完回来重试保存即可。全程看得见每一条命令。

## 一、为什么必须排除 Baloo 索引

Baloo 是**内容**索引器：索引 = 读文件内容 = 按需水合。让它扫挂载点，等于把
整个 NAS 静默拉到本地磁盘 —— 节省空间模式直接报废，还可能陷入「索引 → 水合 →
脱水 → 再索引」的拉锯循环。所以 daemon 在开启开关前**强制检查每个挂载点都已
排除**（门禁），没排除就拒绝保存并给出可执行的排除命令。

排除索引**不影响** Tags 列显示 —— 这是本次调研最关键的发现：Dolphin 的 Tags
列标着 `requiresIndexer=false`，它直接 `getxattr` 读 `user.xdg.tags`，只要求
Baloo 全局开关开着，不要求这个文件被索引过。代价只有一个：这些标签进不了
`tags://` 虚拟目录和 Baloo 标签搜索（那走索引库）—— 状态本来是拿来看的，
不是拿来搜的。

## 二、行为细节

| 方面 | 行为 |
|---|---|
| 开关默认 | **关** —— xattr 名单里根本没有 `user.xdg.tags`，0.7.0 行为一字不变 |
| 三态 | 占位符 `仅在线` / 部分下载 `部分本地` / 完整缓存 `已水合`；目录为空串（无标签） |
| 热切换 | 开关与 FUSE 共享原子标志，改设置**不用重挂载**，关掉立刻消失 |
| 按挂载点生效 | 每个挂载点独立判定「设置开了 && 不会被索引」，一个没排除的点不牵连其它 |
| 挂载警告 | 挂载点会被索引时 `mount` 给非阻塞警告（**与开关无关** —— Baloo 自己就会读文件） |
| 用户标签 | 挂载点上加不了自己的标签（`setxattr` 有意不实现，状态是系统生成的只读值） |
| 刷新 | 不实时：F5 / 重进目录更新（FUSE 服务端改 xattr 不触发内核 inotify） |
| 没装 Baloo | 开关可以开（没有索引风险），`getfattr` 能看，只是 Dolphin 的 Tags 列不显示 |
| 新命令 | `qxync baloo-status`（人话 / `--json`）：Baloo 装没装、索引开关、每个挂载点的结论与排除命令 |

## 三、真机验证与本版修复的两个 bug

fuse-matrix 的 M23 段（真机 `/dev/fuse` + NAS + KDE）**9/9 全绿**：默认关 →
门禁拒绝 → balooctl 排除后放行 → 三态值 → 目录空串 → 热切换消失 → 净退出。

真机首跑暴露了两个实现 bug（单测和假连接实测都没覆盖到），已修复：

1. **读侧不认 `XDG_CONFIG_HOME`**：balooctl 写配置走 KConfig 语义，读侧写死了
   `$HOME/.config` —— 设了 `XDG_CONFIG_HOME` 的环境里门禁永远看不到刚写的
   排除项。真实用户环境两者恰好一致所以没炸。已对齐 KConfig 语义；
2. **不认 balooctl 实写的键格式**：balooctl 写 `exclude folders[$e]=$HOME/…/`
   （KConfig 扩展标记 + `$HOME` 变量形式 + 尾斜杠），精确匹配一个条目都读不到。
   现在键匹配前剥 `[...]` 后缀。

顺带修了 fuse-matrix 自身的两处测试缺陷（M23 段不重置起始状态、缓存清理不认
host 子目录 —— 都是假失败来源）。基线对照（M23 之前的代码）确认矩阵剩余失败
为 WAN 环境固有（NAS 端 rename / 删除判定的抖动），与本版无关。

## 四、已知限制（全部继承自调研结论）

* 不实时刷新（F5 / 重进目录）；
* 依赖 Baloo 全局开关：`balooctl6 disable` 后 Tags 列整个消失（KDE 设计）；
* 进不了 `tags:` 虚拟目录 / Baloo 标签搜索；
* 标签是纯文本：没有颜色、图标、排序权重；
* 多连接 fanout：GUI 保存广播到所有 daemon，其它连接的挂载点若未排除，
  那台 daemon 的门禁会拒（fanout 结果里如实显示失败）。

## 六、兼容性

* `settings.json` 新增 `dolphin_tags` 字段带 `#[serde(default)]` —— 旧文件零迁移；
* 开关默认关 → **不开启就完全没有行为变化**（xattr 名单、`getfattr`、Dolphin 全部照旧）；
* `MountInfo.baloo_warning` 是 `Option` + `skip_serializing_if` → 老 CLI/GUI 无感；
* `IPC_VERSION` 不动：`baloo_status` 是新方法名，老 daemon 对未知方法回可读错误，
  GUI 预检失败时不拦保存（daemon 侧门禁自己说话）。

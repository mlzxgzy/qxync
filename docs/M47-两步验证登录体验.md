# M47 · 两步验证登录体验（先账密、后弹码，不重输口令）

> 状态：**代码完成**（2026-11-01）
> 前置：[M17 两步验证（2SV / TOTP）](CHANGELOG.md#0.8.0)（协议层两步登录早已打通：
> `authLogin.cgi` 先发不带 `security_code` 的请求，`need_2sv=1` 时补码重发；
> TOTP 密钥随凭据保存、daemon 重登现算验证码）。M47 修的是**交互层**：
> 官方 QTS 登录是「先账号密码 → NAS 要 2SV 时单独问验证码」，我们的 GUI
> 却把所有东西挤在一张表单里一次性交，缺码时回一句 CLI 报错。

## 0. 用户原话与问题清单

> 官方的登录是可以先输入账号密码，然后如果要二次验证了，再问用户要二次验证码，
> 不用再输入密码，我们这里好像是强制要重新输入密码，然后甚至重新登录的时候
> 还会记住totp码，一点也用不到，这块给优化一下使用体验把

拆出来的四个具体问题：

| # | 问题 | 根因位置 |
|---|---|---|
| 1 | 缺验证码时回的报错带 `--otp-secret`/`--otp-code` —— GUI 用户看着 CLI 参数发呆 | client `login_once` 把 CLI 指引写进了错误文案（当时只有 CLI 一个前端） |
| 2 | 2SV 缺码 = 一次普通登录失败，用户要重走整张表单（30 秒一换的码很容易在折腾中过期） | 错误是纯文本，GUI 无法结构化识别「这是要验证码」 |
| 3 | 重新登录强制重输口令 —— 明明凭据文件里就有 | GUI `login_flow` 要求 `password` 必填；表单口令框每次填表必清空 |
| 4 | 「记住 TOTP」看不出用没用上 | 已存密钥时确实自动现算（M17 行为），但界面上没有任何反馈；没存密钥时「立即登录」直接报错，用户不知道下一步 |

## 1. 设计

### 1.1 机器可读信号：`need_2sv:` 前缀（而不是新 ErrorKind）

「NAS 要 2SV、本次没带第二因素」必须能从登录失败里**结构化**区分出来，GUI 才知道
该弹码。两个候选：

| 方案 | 淘汰/采纳理由 |
|---|---|
| 新 `ErrorKind::Need2sv` 枚举变体 | 老客户端（CLI/GUI）解到未知枚举值 → **整个 IPC 响应解析失败**，连 message 都丢。与「只加字段不 bump」的版本策略冲突（[ipc.rs](../crates/qxync-core/src/ipc.rs) 头部注释） |
| **错误 message 前缀** `need_2sv:`（采纳） | 老客户端把前缀当正文显示，无害；新客户端 `starts_with` 检测。字面量钉死在 core 测试里 |

契约三方：

```text
client login_once          Error::Auth("need_2sv: 该账号已开启两步验证（2SV）…")
                             （正文不写 CLI 参数 —— 指引归各前端层）
        │
daemon map_err             归一：thiserror 的 Display 是「鉴权失败: need_2sv: …」，
                           前缀被顶到中间 → 剥壳重排，IPC message 以 need_2sv: 开头
        │
        ├─ GUI login_flow  login_needs_2sv()：ok=false + kind=auth + 前缀 →
        │                   返回 need_2sv:true（message 里的前缀顺手剥掉）
        └─ CLI             两条登录路径（直连取 Error::Auth 内层 / 经 daemon 取
                            IpcError.message）识别前缀 → 打印 --otp-code/--otp-secret 指引
```

**双条件判定**（kind=auth **且** 有前缀）：口令错误也是 auth，绝不能触发弹码 ——
否则用户输一百次正确的码也登不进去（口令错时 NAS 不置 `need_2sv=1`，但防御上
仍然双条件钉死，有测试）。

### 1.2 GUI 两步式登录（对齐官方）

```text
「保存并登录」/「立即登录」
  │  账密（表单口令可留空 = 用已存凭据；密钥已存则自动现算，全程无感）
  ▼
NAS: need_2sv=1，本次没带第二因素
  │  login_flow 返回 need_2sv:true（或「立即登录」的错误 message 带前缀）
  ▼
弹「只输验证码」小窗（复用既有 modal：数字键盘 + one-time-code 自动填充）
  │  取消 → 显示正文（用户知道下一步该干嘛）
  ▼
拿到 6 位码 → 续登：
  · 表单路径：同一份表单入参 + otp_secret=<码> 再走 login_flow
    （口令第一步已写进凭据，续登 delete password —— 不重输）
  · 立即登录：IPC Login{otp:<码>}，user/password 由 daemon 从凭据读
  ▼
码对 → 登录成功（two_step=true）；码错/过期 → 普通登录失败（NAS 拒绝理由原样透传），
再点一次登录会重新弹码 —— 不会无限弹窗
```

「立即登录」**不走 login_flow**：它不该重写 link/凭据文件，而且 `links_status`
的 JSON 里没有 `ipv4_only`，走 login_flow 会把该设置覆盖成 false（合并逻辑只保留
exclude/filter_temp/peer_*/endpoints，见 `link_with_existing_and_id`）。它直接发
IPC `Login{None,None,None}` —— daemon 凭据回退本来就有。

### 1.3 口令不再强制重输

- `login_flow`：`password` 缺省 → 回退该连接已存凭据里的口令（与 daemon
  `login_internal` 同一套顺序：参数 > 凭据文件），两边都没有才报「缺少口令」。
- 前端：`state.credPresent`（`fillConnectForm` 时从 `credential_present` 记下）
  为真时口令框留空放行；placeholder 改「留空则用已保存的口令」。
- 顺带修掉一个潜在 bug：旧代码 `li.password.clone().ok_or("缺少 password")`
  对**空字符串**也放行 —— 会把凭据文件里的口令覆盖成空串。现在空串按「没填」
  处理，走回退。

### 1.4 「记住 TOTP 用没用上」可见化

- 已存密钥 → 登录成功行的「两步验证」列显示 `已通过（TOTP）`（M17 已有，
  `two_step=true` 即「NAS 要了码且自动现算通过」）。
- 没存密钥 → 弹码小窗的文案明说「账号口令已通过，NAS 还需要一步验证」——
  用户能看出账密这步是过了的，只差码。
- 表单「两步验证」输入框的 hint 更新：说明「没填时若 NAS 要求验证码，登录中会
  单独弹框询问，无需重新输入口令」—— 这个框的定位回归「存密钥」为主。

## 4. 边界与取舍

- **码错不自动重弹**：弹码只问一次，错了按普通登录失败显示（NAS 的拒绝理由里
  已写明「验证码是否已过期（30 秒一换）」），再点一次登录重新弹码。不做自动
  循环：口令错时 NAS 理论上不置 `need_2sv=1`，但万一置了，无限弹码会把「口令错」
  伪装成「码错」，用户会陷进去。
- **弹码只收 6 位数字**（`/^\d{6}$/`）：粘贴 TOTP 密钥请走表单框（那里有归一化
  与「保存/一次性」的完整语义）；小窗保持极简。
- **前缀对老版本无害**：老 GUI/CLI 收到带前缀的错误只是把 `need_2sv:` 当正文
  显示；老 daemon 发的错误没有前缀，新 GUI 照常按普通失败处理。
- **`need_2sv` 检测在 IPC 层不做**（不加 `IpcError` 字段）：GUI 的 `login_flow`
  是 Rust 命令，检测收在它那层即可；「立即登录」走通用 `ipc_call`，前端用同一
  字面量前缀判断（app.js 里有注释指向 Rust 常量）。两处共用一个契约，core 测试
  钉死字面量。

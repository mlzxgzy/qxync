# v0.6.6 —— 事件快路径修复 + 不再凭空生成冲突副本

> 发布日期：2026-10-19
> 上一版：[v0.6.5](发布说明-v0.6.5.md)（Debian/Ubuntu 单一 .deb 与面向用户的文档）
>
> **同步引擎修复版**：三个互相独立的 bug 在同一次真机操作里一起显形（用户在挂载点里
> 连续保存一个文件 → 凭空多出一个与原文件**字节完全相同**的冲突副本；删掉副本之后
> 每轮同步都报 `事件 stat … status=5`）。本版把它们全部修掉，并给「事件快路径失效」
> 加了观测性哨兵。**没有新功能、没有数据格式或配置变更**，`sync.db` schema 不变。

## 一句话

任务选的 NAS 文件夹在家目录**子目录**里（比如 `~/.Qsync`）的用户，事件快路径之前是
整体失效的（每条事件都 `status=5`，远端变更只能等对账兜底）；连续保存文件会凭空生成
冲突副本；任务页改的冲突策略对实际挂载不生效。三个都修了。

## 一、事件路径双写：`/home/.Qsync/.Qsync/…`（事件快路径整体失效）

### 1.1 症状与取证

任务把 NAS 文件夹选成家目录里的子目录（`root=/home/.Qsync`，NAS 上就是 `~/.Qsync`）时，
**每一条事件**的 `stat` 都回 `status=5 (路径不存在 / 无权限)`：

* 事件快路径等于不存在 —— 远端变更只能等 baseline 对账（默认 30s 一轮）兜底；
* 「最近错误」被同一类噪音刷满。真机取证：2026-10-18 的 daemon 日志里
  `事件 stat` 共 **79 670 条，100% 是 `/home/.Qsync/.Qsync/…` 双写路径**
  （79 667 条 `status=5`，3 条网络错误）；`journal` 里那一轮**拉到 87 580 条事件**。

### 1.2 根因与修法

旧 `map_event_path` 把「剥掉 `/share/homes/<user>` 后剩下的 `/.Qsync/…`」又拼到视图根
`/home/.Qsync` 后面 → `.Qsync` 出现两遍，NAS 上当然没有这个路径。视图根**就是**家目录
（`/home`）时这个巧合恰好成立，所以之前没暴露。

现在事件路径先经 `client_path_from_share` 换算到客户端命名空间（前缀恒为 `/home`，
同时认卷内 `realpath` 与 `/homes/<user>` 短形态、拒绝他人路径），再按视图根收窄 ——
不属于本视图的事件返回 `None` 交对账兜底，不再拼出一个不存在的路径。

顺带两件：

* 事件 `stat` 的 4/5/6 不再记成硬错误刷屏（那三个码同时是「权限拒绝 / 会话失效」，
  本来就不该当错误；也不据此触发重登，避免撞 NAS 的失败登录封锁）；
* **跳过原因计数**写进 `remote_change` journal 详情（删除事件无路径 / 本机回声 /
  非本账号 / 被规则隐藏 / 远端不可见 / 映射失败）—— 4/5/6 降级之后
  `events_skipped` 是唯一痕迹，不归因的话「事件快路径整体失效」会变成无声故障。

## 二、凭空冲突副本：一轮进行中自己上传成功，判定却拿开轮快照当 base

### 2.1 症状与取证

连续保存（每次保存都触发一次上传落地）之后凭空出现
`防火墙配置 (conflicted copy from devhost 2026-10-19).txt`，且**与原文件字节完全相同**
（12218 = 12218）。副本名里的 `devhost` 是本机 hostname —— 是自己跟自己打出冲突。

### 2.2 根因与修法

`poll_once` 开轮时克隆 baseline 快照、整轮（几十秒、要列几百个目录）都用它判定；而
上传成功 hook 会在本轮**进行中**就把权威 baseline 推进到刚落上去的签名并清掉节点的
dirty 标记。于是判这个文件时：快照里还是旧签名、远端已经是自己刚传的新版、本地已
干净 → 三向比较判**双方都改** → 按当时的冲突策略生成副本。

现在开轮时同时清空一张「本轮 hook 推进」表，判定（对账 / 事件 / 冲突重判）统一用
「快照 ∪ 本轮 hook 推进」当 base，并照顾三个时间窗口：

1. 远端列到的就是开轮快照或本轮任一推进 → 以远端为准（目录列举可能落在本轮两次
   上传**之间**，所以按列表匹配，不能只比最新那次）；
2. 远端比本轮最后一次推进还旧 → 视为陈旧列表，本轮不动（下一轮收敛），**不能**拿来
   把本地元数据/内容刷回旧版；这条捷径只在**本地干净**时生效 —— 本地带未上传改动时
   退回正常判定，否则别处设备「mtime 偏小的新写入」（时钟慢 / `rsync -t` / 备份恢复）
   会被本地直接覆盖；
3. 其余（别处设备改的新版）→ 正常刷新本地。

同一轮内的多次落盘也修了：轮内 persist 发生多次（事件阶段每批一次 + 轮末一次）时，
第一次合并后不再清标记，否则第二次整份替换会把 hook 刚推进的签名在盘上抹掉 ——
同一个凭空冲突**晚一轮重现**。

## 三、任务页改的冲突策略对实际挂载不生效

冲突策略由同步引擎按挂载记录分派（视图不读任务文件），而 `mounts.json` 的语义是
「上次实际挂了什么」、重启时现场优先；保存任务又**不回写**已挂载视图。真机上因此
出现过：任务写 `ask`（冲突时入待裁决队列、不落副本文件），实际一直按更早的
`rename_local` 走 —— 本该进「冲突中心」等裁决的冲突直接生成了副本。

现在：① 保存任务时把新策略同步到已挂载的同路径视图并落进记录（免重启生效、
重启后不回退）；② 启动恢复时任务表里有同名任务就以任务里的冲突策略为准
（其余挂载参数仍现场优先）。

本轮新增的回归测试（都先在**旧实现上跑红**、再在新实现上跑绿）：

* 事件路径：视图根是家目录子目录时不双写（真机原样中文路径）、视图外路径 / 他人
  家目录 / 空 user → `None`；mock NAS 事件级端到端（真 `Client` + 真 HTTP）断言
  实际请求是单前缀 `stat:/home/.Qsync/…`、永不出现双写路径、4/5 只跳过不记错误
  不触发重登；
* 凭空冲突：复刻真机时序（旧逻辑必现 Conflict、新逻辑 Noop），并逐条锁住上面三个
  时间窗口；同轮多次 persist 后重新 `load` 仍是 hook 推进的值；穿透
  `reconcile_view` 的端到端回归（hook 轮内推进 → 0 冲突、不进待裁决队列、
  权威 baseline 不回退）；
* 冲突策略：开轮生命周期 + 多次推进去重 + 每路径封顶（防无界增长）。

## 五、已知边界（如实写）

* **共享文件夹（`root=/Public`）的事件仍映射为 `None`**：`client_path_from_share`
  只认 `/homes/<user>` 标记，`/share/Public/…` 形态映射不出来（旧实现同样 `None`，
  不是本版回归）。NAS 对共享文件夹事件到底发哪种路径形态尚未实测，确认后补映射
  与测试。这类任务目前靠对账兜底，行为与 0.6.5 一致。
* **编辑器交换文件（`.kate-swp` 等）仍会被当普通文件同步一次**：这是
  `filter_temp` 临时文件规则的问题，本版未动（双写路径修好后它们不再刷错误）。
* **冲突副本名里的设备名是本机 hostname**，不是「文件来自哪台设备」；多台机器同名
  时无法区分（沿用既有行为）。
* 其余打包 / 平台边界（amd64、glibc ≥ 2.34、有意不 strip 约 190 MB、AUR 校验和
  发版后更新）与 [v0.6.5](发布说明-v0.6.5.md) 相同，本版没有变化。

## 六、升级须知

* **受影响的用户**：任务选的 NAS 文件夹在家目录子目录里（`~/.Qsync` 这类）、或
  遇到过「保存几次就多出一个一模一样的冲突副本」、或任务页改过冲突策略但没生效的
  —— 这三类都建议升级。
* **升级方式**：`.deb` 用户 `sudo apt install ./qxync_0.6.6-1_amd64.deb`；Arch /
  tar.gz 用户换二进制。**升级后重启 daemon**（`systemctl --user restart qxyncd`，
  新二进制不会替换正在跑的旧进程）。
* **升级后第一轮同步的 journal**（`remote_change` 详情）会显示事件跳过的原因分布 ——
  那是给「事件快路径是否在干活」留的哨兵：如果「映射失败」占比很高，说明又出现了
  本版没覆盖的路径形态，欢迎带着 journal 来报 issue。
* **回退**：装回 0.6.5 即可；`sync.db` schema 没有变化，回退不需要迁移。

# v0.10.0 — Complete English UI, a language switch that works, English-first release notes

> Released: 2026-11-02
> Previous: [v0.9.2](发布说明-v0.9.2.md) — session self-heal: no more "sync error" popups

## In one sentence

```text
The GUI is now fully bilingual (English / Simplified Chinese).
  Settings → Personal → Language → Follow system / English / 简体中文
  → the whole window switches immediately, and the choice is remembered
  → in the daemon settings, so the CLI shares it too.
And starting with this release, release notes are written in English first.
```

## What's new

### 1. Complete English UI

The English string table used to cover only a handful of two-step-verification messages;
everything else fell back to Chinese, so the language dropdown was decoration. Now:

- the `en` table mirrors the `zh-CN` table **key for key** (a full mirror);
- every user-visible string in the UI — page and section names, statuses, empty / loading /
  error states, buttons, badges, confirmations, toasts, table headers, `title` tooltips,
  `placeholder` and `aria-label` attributes, even the sample tokens inside `<code>` snippets —
  goes through the i18n layer;
- dynamic text built in JavaScript (statuses, errors, confirmations, the operation log shown
  in the log panel, counters) is translated too;
- the security rule stays: text is only ever set with `textContent` — still no `innerHTML`
  anywhere in the GUI.

No i18n framework and no new dependency were added; the tables are plain JavaScript objects.

### 2. The language setting now actually works

**Settings → Personal → Language** offers three choices:

| Choice | Behavior |
|---|---|
| Follow system | `zh*` → Simplified Chinese, `en*` → English, anything else → Simplified Chinese |
| English | always English |
| 简体中文 (zh-CN) | always Simplified Chinese |

The preference is stored in the daemon's `settings.language` (the CLI and the GUI share the
same preference; `qxync settings --set language=en` works too). The GUI renders its first
frame from the last preference cached on this machine (so you never see a Chinese flash
before English) and then defers to the daemon setting once settings arrive; if the two
disagree, the page reloads once. `<html lang>` follows the language, so screen readers and
spell checkers behave correctly.

A static guard was added on top: a Rust test (`ui_spec`) now fails if the English table ever
stops covering every Chinese key, if an English value contains CJK characters, if a key used
by the HTML or JS is missing from either table, or if the language wiring is broken — the
English UI cannot silently rot back into "decoration". A headless browser check
(`xtask/tests/gui-i18n.sh`) renders the real UI in both languages and asserts there is no
Chinese text and no full-width punctuation left in English mode.

### 3. Release notes are English-first from now on

The release workflow now picks the GitHub Release body in this order:

```text
docs/发布说明-<tag>.en.md   ← English (first choice)
docs/发布说明-<tag>.md      ← Chinese (fallback)
GitHub auto-generated notes ← only if neither file exists
```

The Chinese version stays in the repository. Rule documented in §3.4 of the release checklist.

## Upgrade

```bash
# Arch
sudo pacman -U qxync-bin-0.10.0-1-x86_64.pkg.tar.zst
# Debian / Ubuntu
sudo apt install ./qxync_0.10.0-1_amd64.deb
```

No data format change and no settings schema change — `0.9.2 → 0.10.0` is a drop-in upgrade.
The changes live in the GUI (and one Rust-side test), so **just close and reopen `qxync-gui`**;
the daemon does not need a restart.

## Known limitations

- **Lower-level strings are still Chinese**: the GUI diagnostics log and all daemon / CLI
  output remain Chinese. In the English UI, the closer a message is to the low-level
  machinery (daemon errors, daemon-side log lines), the more likely it still appears in
  Chinese. Localising those is left for a later release.
- The language switch reloads the window once when the saved setting differs from what the
  page rendered on boot — this is intentional (it avoids any half-Chinese / half-English frame).

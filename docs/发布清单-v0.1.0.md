#### 怎么复跑清洗验证

**不要**把敏感串直接写进命令行（会进 shell 历史，也会被再次提交）。用一份**本地的**清单文件：

```bash
# 1) 建一份敏感串清单（放在仓库外，逐行写你的真实域名 / 用户名 / 设备指纹）
cat > /tmp/qxync-sensitive.txt <<'EOF'
<你的真实 DDNS 域名>
<你的本机用户名>
<你的真实 device_uid>
<你的本机计算机名>
EOF

# 2) 扫工作区
git grep -nIiF -f /tmp/qxync-sensitive.txt && echo "❌ 工作区有残留" || echo "✅ 工作区无残留"

# 3) 扫**全部历史**（关键：只扫工作区是不够的）
for rev in $(git rev-list --all); do
  git grep -lIF -f /tmp/qxync-sensitive.txt "$rev" 2>/dev/null
done | head && echo "❌ 历史有残留" || echo "✅ 历史无残留"

# 4) 口令从未进入历史
git log --all --format=%H | while read -r r; do
  git grep -l '你的口令片段' "$r" 2>/dev/null
done | head && echo "❌ 口令进过历史" || echo "✅ 口令从未进入历史"

# 5) 收尾：删掉清单文件
shred -u /tmp/qxync-sensitive.txt 2>/dev/null || rm -f /tmp/qxync-sensitive.txt
```

> **`docs/测试环境.local.md` 仍然留在本地且在 `.gitignore` 里**（规则 `*.local.md`）。
> 它含真实域名与口令。**绝对不要**用 `git add -f` 绕过忽略规则。

### 1.5 历史重写记录

原仓库**从未关联任何远程**（`git remote -v` 为空），所以清洗是在推送前完成的，**不需要 force-push**。

- 方法：`git filter-branch --tree-filter`，对每个提交只对**命中敏感串的文本文件**做替换
  （`grep -rlI` + `xargs sed -i`，`-I` 保证不碰二进制）。
- **重写前的完整历史已备份**：仓库**上一级目录**下的 `qxync-prepublic-backup.bundle`
  （`git bundle create --all`，已 `bundle verify` 通过）。确认新历史没问题后可以删掉它。
- 重写一共跑了**四轮**：① 清敏感串；② 清「裸片段」；③ 撤出分析报告（见 §1.6）；
  ④ **清提交信息**。每一轮之后都做了全历史扫描。
- ⚠️ **最大的一个坑：`--tree-filter` / `--index-filter` 只重写「树」，不动提交信息。**
  本仓库的清洗记录本身把原值写进了提交信息，于是内容清干净了、`git log` 里却还挂着原值。
  必须再用 `--msg-filter` 清一遍：
  ```bash
  git filter-branch --force --msg-filter 'python3 /tmp/clean-msg.py' -- --all
  ```
  验证方式是扫**提交信息**，而不只是扫文件：
  ```bash
  git log --all --format='%B' | grep -inE '<敏感串清单>'
  ```
  （另外：`filter-branch` 的 `--msg-filter` 脚本**必须有可执行权限与 shebang**，
  否则会被 `/bin/sh` 当脚本解析并**挂死** —— 本次就踩了，用 `timeout` 兜住更稳。）
- 重写后清理了 `refs/original/`、过期 reflog 并 `git gc --prune=now`，
  确认**旧对象已不可达**。
- ⚠️ **本文件曾经踩过一个自指陷阱**：初版把真实域名 / 用户名当作「搜索模式」和「映射原值」写了
  进来，导致历史里仍留有这些**裸字符串**（完整域名已被替换，但裸片段没有）。
  现已改为**只描述类别、不写原值**，并重跑了一次清洗。**以后写这类文档务必遵守这条。**

### 1.6 撤出逆向分析报告，probe 工具迁到 `xtask/probe/`

逆向分析报告正文**属于另一个项目**，不应随本仓库发布，已在推送前撤出。

- **撤出仓库**（`mv` 到仓库外 `<仓库上一级目录>/qxync-report-offrepo/`，**未删除**）：
  `report/01-*.md`…`report/12-*.md`、`report/*-evidence.md`、`report/README.md`、
  `report/TOOLKIT.md`、`report/categorize.py` 等分析脚本、`report/out/`、
  `report/tools/reveal-credentials.sh`、`report/.gitignore`。
- **保留并迁移**：`report/probe/` → **`xtask/probe/`**
  （`qs_probe.py` / `qs_fixture.py` / `nas_manifest.py` / `p0_device_probe.py` + README）。
  它们不是报告正文，而是本项目自己的协议探测与造夹具工具 —— 验收矩阵与真机集成测试都依赖它们。
  同时新增 `xtask/probe/.gitignore`，根 `.gitignore` 的 `report/probe/probe-out/`
  改为 `xtask/probe/probe-out/`；未跟踪的 `probe-out/`（含真实响应与 sid）随目录一起移动，
  **始终不进仓库**。
- **新增根目录 `DISCLAIMER.md`**：**不是**原 `report/DISCLAIMER.md` 的搬运，而是**面向本项目重写**的
  版本（性质 / 目的 / 分析边界 / 知识产权 / 凭据 / 无担保 / 使用者责任 / 通知即删），中英双语。
  原文件的定位是「逆向分析笔记的免责声明」，与本项目（一个客户端）不符，照搬会误导读者。
- **引用全部改写**：19 个文件 / 88 处引用逐条处理，**不留悬空链接**。
  其中 `xtask/tests/fuse-matrix.sh` 的夹具路径补了 `QSYNC_TEST_LOCAL_FIXTURE` 环境变量覆盖；
  `.gitattributes` 去掉 `report/**`；Issue 模板里的 report 入口换成 `DISCLAIMER.md`。
- **历史第三次清洗**：`report/` 分布在 3 个提交里，必须从**全部提交**剔除 ——
  否则 `git log --name-only` 仍能列出报告文件名、`git show` 仍能取出正文。做法：

  ```bash
  git filter-branch --force --index-filter \
    'git rm -r --cached --ignore-unmatch report' -- --all
  git update-ref -d refs/original/refs/heads/master
  git reflog expire --expire=now --expire-unreachable=now --all
  git gc --prune=now
  ```

  验证（两条都要为空）：

  ```bash
  git ls-files | grep '^report/'                                   # 工作区索引
  git log --all --name-only --pretty=format: | sort -u | grep '^report/'   # 全部历史
  ```

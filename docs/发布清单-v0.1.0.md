**清洗时修掉的两处「清洗引入的破坏」**（务必保留这两处修法）：

1. `xtask/tests/m83-matrix.sh` 原先**把具体域名写死在状态库路径**里
   （`DB="$XDG_DATA_HOME/qsync/sync/<域名>/sync.db"`）。替换成占位符后会与 `--link` 读到的真实
   host 对不上，矩阵必挂。已改成和 `m5-matrix.sh` 一样**从 link 配置推导**：
   ```bash
   DB_HOST="$(jq -r .host "$RUNDIR/config/qsync/links/$LINK.json")"
   DB="$XDG_DATA_HOME/qsync/sync/$DB_HOST/sync.db"
   ```
2. `report/probe/qs_fixture.py` 的 `HOST` 是模块级常量（只认 `--small`，没有 `--host`）。
   已改成环境变量驱动，默认值为指不到任何真实设备的占位符：
   ```python
   HOST = os.environ.get("QSYNC_TEST_HOST", "nas.example.com")
   PORT = int(os.environ.get("QSYNC_TEST_PORT", "9834"))
   ```

## 3. 推送与打 tag

```bash
cd <repo>

# 0) 先备份「重写前」的历史（万一要回头）
git bundle create /path/to/qxync-publish-backup.bundle --all

# 1) 自查
git status                       # 确认 docs/测试环境.local.md 不在列表里
bash -n xtask/tests/*.sh         # 脚本语法
python3 -m py_compile report/probe/*.py
cargo test --workspace           # 全绿

# 2) 关联远程并推送
git remote add origin git@github.com:mlzxgzy/qxync.git
git push -u origin master

# 3) 打 tag（用带说明的 tag）
git tag -a v0.1.0 -m "qxync v0.1.0 —— 首个公开版本"
git push origin v0.1.0
```

然后在 GitHub 上：
1. 用 [`docs/发布说明-v0.1.0.md`](发布说明-v0.1.0.md) 的内容建 Release（对应 `v0.1.0`）。
2. 建议**不要**勾选「上传构建产物」—— 仓库目前不提供预编译二进制。
3. 确认 Actions 里的 `CI` 工作流已在 tag 上跑过一遍。

## 4. CI 首次跑通后要处理的

工作流里有**两项刻意的非阻断**（`continue-on-error: true`），首次跑完请按结果收紧：

- [ ] **`msrv`（Rust 1.85）**：开发机是 nightly，`rust-version = "1.85"` **尚未实测**。
  - 若通过 → 把 `continue-on-error: true` 删掉，让它变成硬门。
  - 若不通过 → 把 `Cargo.toml` 的 `rust-version` 抬到实际下限，并在 README 里同步。
- [ ] **`fmt`**：仓库尚未整体格式化（约 21 个文件 / 200+ 处差异）。格式收口**单独一个 commit**，
  不要在功能 PR 里夹带：

  ```bash
  cargo fmt --all
  git commit -am "style: cargo fmt --all（格式收口，无行为变更）"
  ```
  收口之后把 `continue-on-error: true` 删掉。
- [ ] **clippy**：目前**只跑不设 `-D warnings`**。等告警清零后，把
  `cargo clippy --workspace --all-targets --locked -- -D warnings` 收紧为阻断。

# M32：本地写入的校验和与缓存文件搬运

> 起因：M31 真机取证时发现 `qxync verify` 报出一批「区间内容损坏」，但抽查内容与 NAS
> 重新下载的字节 **sha256 完全一致**（内容没坏，是 `.qxsum` 坏了）。进一步排查确认这是
> **两个独立的写入侧缺陷**，与 M31 的「状态没恢复」是两个不同的坑。

## 1. 现象

| 观察 | 数据 |
|---|---|
| `qxync verify` 报告 | 403 个已水合文件里 **198 个**坏（183 个全区间坏、15 个只坏前缀），2247 个区间 |
| 内容抽查 | `B.pdf` 盘上内容 == NAS 重新下载内容（sha256 一致）；抽查的 docx 也一致 |
| 校验和 vs 内容 | 抽样文件里 `whole_xxhash` 有记录的 48 个，47 个整文件哈希**与内容一致** → 内容没变过，是逐区间表不对 |
| 损坏文件分布 | **全部**是本地写入过的文件（`.qxstate` 里 `whole_xxhash = NO_HASH`），下载得到的文件全对 |

结论：内容没坏，坏的是 **`.qxsum`（逐区间 xxhash64 表）与内容分叉**。T3 安全闸按设计
拒绝认领 → 重启/重新挂载后这些文件被当成「损坏缓存」整份重下（哪怕盘上字节就是好的）。

## 2. 根因一：未对齐写入被当成「整区间写完了」

`mark_written_chunks()` 的旧判据：

```rust
let c_end = ((idx + 1) * chunk_size).min(n.attr.size);   // ← 用 EOF 当区间尾
if c_start >= offset && c_end <= end {                   // ← 只要求「写到 EOF」
    hash(chunk_now);                                     // ← 立刻算成最终校验和
}
```

对**正在长大**的文件，第一次写进某个区间时 `min(区间尾, EOF) == EOF == end` 恒成立，
于是**刚写进来的几 KB 就被当成整个区间的内容**算了 hash；之后继续追加/补写时，
那些写没有「完整覆盖」区间 → **不会重算**，`.qxsum` 永久停在第一版。

真机证据（最干净的样本是单区间文件：任何 ≤128 KiB 的文件只有 1 个区间）：

| 缓存文件 | 大小 | 盘上 `.qxsum` | 实际内容 hash | 命中 |
|---|---|---|---|---|
| `._26…第一轮-技术文件.docx` | 162 B | `0x64b9da3ed69d6732` | `0x3e4549388d47a458` | `xxh64(content[..1])` —— 第一次写只有 **1 字节** |
| `04-软件清单-1.xlsx` | 13324 B | … | … | `xxh64(content[..4096])` —— 第一次写 **4 KiB** |
| `1________….xlsx` | 28725 B | … | … | `xxh64(content[..16000])` —— 第一次写 **16000 B** |

19 个「单区间且损坏」的样本全部命中「盘上 hash == 内容前 N 字节的 hash」，N 正好是
那个程序第一次写进来的长度（1 / 4096 / 16000 字节——WPS 与 KIO 的写块大小）。
多区间文件同理，只是第一次写进每个区间时还会混入「远端旧内容」（写前
`hydrate_all` 补过未覆盖的区间），所以看起来是「旧版本 + 新前缀」的混合，更难认。

另外 119 个文件 `内容 mtime` 比 ``.qxsum` mtime 晚 0.2–12 ms —— 同一轮写里先算了
校验和、后面又有写改了内容没重算，与上面的机制吻合。

## 3. 根因二：改名/物化只搬了「内容 + 位图」，漏了 `.qxsum`

`rename()` 与 `link()`（O_TMPFILE 物化）都把缓存文件迁到新名字，旧代码：

```rust
std::fs::rename(&old_cache, &new_cache)?;
let _ = std::fs::rename(state_path(&old_cache), state_path(&new_cache));   // 位图搬了
// ← .qxsum 没搬
```

后果分两种，都很难查：

* 目标位置原本没有三件套（KIO 的 `.part` → 正式名）→ 新名字**没有校验和表**，
  T3 把「没有基准」当损坏 → 内容完好也要整份重下；
* 目标位置有旧文件残留的 `.qxsum`（覆盖保存）→ **新内容 + 旧基准** → 每次认领都判损坏。

真机证据：缓存目录里 `398` 份 `.qxstate` 却只有 `~403` 个内容文件，另有 **22 份孤儿
`.qxsum`**，名字全是 `.part` / `.tmp` / `wpsdiag_*`（改名前的临时名）——正是这条路径
留下的残骸。另有 8 个内容文件完全没有 `.qxsum`。`hard link` 的复制语义那条分支也只
复制内容、不复制校验和表。

## 4. 修复

### 4.1 写入：脏区间延后到「文件写完」再算（`Node::stale_sums` + `finalize_written_chunks`）

* `Node` 新增 `stale_sums: Vec<bool>`：**内容变过但校验和还是旧的**区间。
* `mark_written_chunks()`：
  * 这次写**完整覆盖**到「当前文件里的区间尾」→ 立刻算 hash（与旧行为一致，cp 的整块
    写零额外开销）；
  * 只覆盖一部分 → 只置位图 + 标记 `stale_sums`，**不**拿半截内容算 hash。
* 新增 `finalize_written_chunks()`，在 **`release` / `flush` / `fsync`** 时调用：
  对 **dirty** 节点，把「未就绪 或 校验和待重算」的区间按**最终内容**一次读齐、
  一次 `pwrite` 写进 `.qxsum`，再落位图。
  为什么 `dirty` 就够：写路径开头的 `hydrate_all()` 已经保证每个区间要么被本地写过、
  要么从远端补齐过；新建文件的空洞按 0 算（与稀疏文件语义一致）。
* 只读**脏区间**，不是整份文件：整块对齐的 `cp`（区间全被完整覆盖）一个脏区间都没有，
  `finalize` 是零开销。

### 4.2 改名/物化：三件套一起搬（`move_cache_triplet`）

新增 `move_cache_triplet(old, new)`：先清掉目标位置残留的位图/校验和（**宁可没有基准，
也不能拿错版本的基准去对**），再把内容 + `.qxstate` + `.qxsum` 一起 `rename`。
`rename()` 与 `link()`（O_TMPFILE 物化）都改走它。硬链接（复制语义）分支在复制内容后
**同时复制 `.qxsum`**。

## 5. 对现存脏数据的影响

已损坏的 198 份 `.qxsum` **不会被自动重算**——那等于「拿可能坏了的内容给自己发合格证」，
违反 T3「没有基准就不声称内容正确」的红线。三条出路，按推荐顺序：

1. **什么都不做**：第一次读这些文件时 T3 会拒绝认领、重新下载一次（内容本来就是对的，
   只是白花一次带宽），下载路径会写回正确的 `.qxsum`，之后不再复发。
2. **`qxync verify --repair`**：提前把坏区间退回「按需水合」，下次读再下载（等价，只是
   提前知道了范围）。
3. **用这些程序再保存一次**：经 FUSE 写过的文件会在 `release` 时自动补算校验和
   （不需要回源）。

## 6. 验收

新增 3 个单测（`crates/qxync-fuse/src/lib.rs`）：

| 测试 | 覆盖 |
|---|---|
| `m32_partial_writes_keep_checksums_in_sync` | 1 字节 + 4 KiB 未对齐写入 → 中间态确有脏区间/校验和不过 → `finalize` 后与最终内容一致；「重新挂载」后直接认领为 `hydrated` |
| `m32_aligned_writes_hash_immediately` | 整块对齐写（cp 形态）零脏区间、当场算对——不引入额外全文件读 |
| `m32_rename_moves_content_state_and_sums` | 改名搬三件套；目标位置预先放了旧文件的坏 `.qxsum`/位图，搬完必须用这份内容的，不得继承 |

`cargo test --workspace` **540 passed / 0 failed / 22 ignored**（M31 的 537 + 本次 3）；
`cargo fmt --check` 干净（`cargo clippy` 本环境未安装）。

## 7. 与 M31 的关系

| 缺陷 | 症状 | 修复 |
|---|---|---|
| M31-1 状态只在第一次 read 时读回 | 重启后角标/status 全变 placeholder（**内容没丢**） | 挂载时重建水合索引 |
| M31-2 `setattr` 改 mtime 不回写位图头 | 重启后认领失配 → 整份重下 | `resync_cache_signature` + 认领容差 |
| **M32-1 未对齐写入的半截 hash** | `.qxsum` 与内容分叉 → 认领被判损坏 | `stale_sums` + `finalize_written_chunks` |
| **M32-2 改名漏搬 `.qxsum`** | 新名字没有基准 / 继承旧基准 | `move_cache_triplet` |

四个缺陷可以叠加出现（真机正是同时中了 4 个），修完之后「重启 → 已水合文件仍是已水合、
不再回源」才真正成立。

# v0.7.0 —— 离线可用与累计缓冲区

> 发布日期：2026-10-19
> 上一版：[v0.6.8](发布说明-v0.6.8.md)（对账扫描时间预算）
>
> **新功能版**：断网不再等于「本地改动等 10 秒后丢失」。离线时挂载点继续提供服务，
> 本地改动进持久化缓冲区，联网后按顺序统一同步。
> 数据格式有一处**向前兼容的升级**：`sync.db` schema v4 → v5（新增 `outbox` 表，
> 老库打开时自动补齐、不碰已有数据）。

**升级就是换二进制 + 重启 daemon**（`systemctl --user reload qxyncd` 可不断挂载点）。

## 一句话

以前断网约 10 秒（5 次指数退避）后，上传/删除作业会被当成「失败」删库 ——
用户以为「联网就会同步」，实际是**永远不会**：本地缓存文件还在，NAS 停在旧版；
删除则会在联网后「复活」。现在网络错误**不计次数、不丢作业**，离线操作（含
`mkdir` / `rename` / `touch`）进 outbox，联网后先回放结构操作、再解冻上传/删除、
最后补一轮对账。

## 一、离线时到底哪些事能做了

| 操作 | 以前（离线） | 现在（离线） |
| --- | --- | --- |
| 读已下载内容 | ✅ 正常 | ✅ 正常 |
| 读**未下载**区间 | 卡 20s 才 EIO | **立即** EIO（不再白等） |
| 改已水合文件 | 进队列，10 秒后作业被删 | ✅ 进持久化队列，等联网 |
| 新建文件 | ✅ 进队列（同样 10 秒后被删） | ✅ 进持久化队列 |
| 新建目录 | ❌ EIO | ✅ 本地立即可见 + 进 outbox |
| 改名 / 移动 | ❌ EIO | ✅ 本地立即可见 + 进 outbox |
| 删除 | 进队列（10 秒后被删，联网后「复活」） | ✅ 进持久化队列，联网后真删 |
| `touch` | 本地 mtime 改了，联网后被上传覆盖回去 | ✅ 进 outbox，并同步更新排队作业 |
| `ls` 看过的目录 | ✅ 吃本地快照 | ✅ 不变 |
| `qxync status` | 最长卡一分钟（3 个 20s connect timeout） | ✅ 立即返回，显示「离线」与缓冲区 |
| 脚本判断能不能联网 | ❌ | ✅ `getfattr -n user.qxync.offline` |

## 二、联网之后发生什么（顺序是正确性的一部分）

```text
每 3 秒短探活（不等 30s/600s 的轮询间隔）
  → 探活成功
  → 冻结上传/删除队列
  → 按 seq 回放 outbox（mkdir / rename / setmtime）
  → 解冻 + 唤醒队列
  → 补一轮对账
```

* **先回放再解冻**：否则上传会抢在「改名 / 建目录」之前落到旧路径上，远端与本地分叉；
* **回放幂等**：每条操作先 `stat`，「NAS 已经是目标状态」就只删行（daemon 崩在
  删行前也没事）；
* **改名冲突不覆盖**：源和目标都在时，先把 **NAS 上那份**改成冲突副本，再落地 ——
  两边数据都保住；
* **回放没清空就快速重试**：3 秒后重来（不等 30s/600s 的完整间隔）；
* **本地改名会让缓冲区跟着走**：离线建的目录再改名时回写 outbox 前缀；删除作业
  同样按改名 rekey（`a/x` → `b/x`），不会出现「删掉的文件联网后复活」；
* **网络错误不计重试次数**：回放遇到断网立刻停，剩余行原样保留，下一轮再来；
* **会话失效自动重登**：回放撞上 sid 过期（4/5）会立即重登、下一轮继续，不计次数；
  服务端未就绪（status=8，NAS 迁移/启动中）同样只等不计数。只有真正的业务错误
  才计数（5 次放弃并留痕）。

## 三、界面上能看到什么

* 首页：每个离线连接一条横幅 —— 「离线（已 3 分钟）本地改动已先攒着（5 项），
  联网后自动同步」；
* 状态页：连通性 / 已离线时长 / 最近错误 / 离线缓冲区分类计数
  （待上传、待删除、待建目录、待改名、待改 mtime）/ 是否正在回放；
* CLI：

```text
连通性    : 离线（已 42 秒）｜最近错误: 网络错误: 探活: error sending request …
离线缓冲  : 待上传 3｜待删除 1｜待建目录 2｜待改名 1｜待改 mtime 0
```

## 四、兼容性

* **没有协议改动**：服务端不感知离线（M14 的结论继续成立），不需要升级 NAS 侧。
* **`sync.db` v4 → v5**：只新增 `outbox` 表，`CREATE TABLE IF NOT EXISTS` 自动补齐；
  老库里的 baseline / 队列 / decisions / nodes 一行不动。
* **老 daemon + 新前端**：`status` 缺 `connectivity` / `offline` 字段时前端按「正常」
  处理（`serde(default)` + JS 侧判空），不会把缺字段误报成离线。
* **新 daemon + 老前端**：多出的字段被忽略，行为不变。

### 真机 FUSE 验收（2026-10-19 补做，已通过）

`/dev/fuse` 可用后，用**真 NAS + 真挂载 + TCP 中继断网**补跑了完整链路
（脚本：[`xtask/tests/m20-real-nas.sh`](../xtask/tests/m20-real-nas.sh)，57 项断言全过）：

```text
在线写 → 断网 → 离线 mkdir / 建二级目录 / 写文件
            → rename 文件 / rename 目录 / ls 新目录 / rm / touch / 读缓存 / 读未水合
            → daemon 重启（outbox 4 行不丢、attempts 仍 0）
            → 恢复网络 → 远端出现改名后的目录与文件、内容一致、旧名消失、
              删除生效、mtime 生效、缓冲区清零
```

验收过程中抓到并修复了两个只有真挂载才暴露的问题（详见
[M20 §4.3](M20-离线缓冲区.md)）：

* **离线建出来的目录「能建不能用」**：内核在 `mkdir`/`open(O_CREAT)` 前会先发 FUSE
  `LOOKUP`；新目录本地没有清单快照 → 「无快照 + 离线」回 EIO，`ls` 与往里写文件全失败。
  修复：离线 `mkdir` 给新目录放一份**空清单快照**；目录改名时快照跟着搬。
* **断网后挂载根目录建不了东西**（用户从没 `ls` 过根时）：挂载成功后主动**预热根清单**，
  且预热用 `seed_listing` 只在没有快照时灌入，避免「挂载时抓的旧清单」迟到落地把
  刚新建的文件从 `ls` 里抹掉（这个竞态也在真机复现并修掉）。

**仍存在的限制**：离线重启 daemon 时，挂载点要等网络恢复后才恢复（恢复挂载要先登录）；
缓冲区与队列不丢，联网后先回放再补挂载。

## 六、已知限制

1. 离线新建/改名的条目在同步落地前，**重新打开挂载点**看不到（节点表是进程内状态）；
   内容与操作在持久化队列里，不会丢。
2. 回放改名的冲突固定走「NAS 那份改名成冲突副本」，暂不读任务的 `conflict` 策略。
3. 任务级 purge 不清理 outbox（与上传/删除队列一样按连接共享）。
4. 未水合的区间离线仍然读不了（数据不在本地，任何客户端都变不出来）。

## 七、给升级后的你

* 断网时放心改文件：改动会攒着，联网自动同步；
* 如果看到「离线缓冲」一直不降，先看 `qxync status` 的「连通性 / 最近错误」，
  再看 `qxync journal`（「错误」页）里 `offline` 分类的记录；
* 需要脚本判断挂载点当前能不能联网：

```bash
getfattr -n user.qxync.offline -e text /path/to/mount/some-file
# user.qxync.offline="1"  → 已知离线
```

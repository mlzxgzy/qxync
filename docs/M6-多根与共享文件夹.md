# M6 —— 多根 / 共享文件夹

> 状态：**已实现并真机验收**（`xtask/tests/m6-matrix.sh` **29/29**，含多根真挂载那 8 项）。
>
> 一句话：Qsync 的同步范围不再只有家目录 —— `roots` 让一个挂载点覆盖多个远端根
> （`/home` + 共享文件夹），**单根行为一字未改**（M1–M5 的验收矩阵继续有效），
> 共享文件夹**默认只读**，因为真机实测普通账号往里写会被服务端拒绝。

---

## 1. 先纠正一个旧判断：共享文件夹不需要 `auth_data` AES

`docs/开发规划.md` §4.1 记着「共享文件夹的 `auth_data` AES 未还原，是硬缺口，首版只做 home」。
M6 动手前先用普通 `sid` 真机试了一遍（2026-10-01，用户 `test1`）：

| 操作 | 结果 |
|---|---|
| `get_list /Public` | ✅ 7 项（`@Recycle`、`迅雷`、`tailscale.txt`、`jellyfin`…） |
| `get_list /Multimedia` | ✅ 3 项 |
| `get_list /`、`/share` | ❌ `status:5`（路径不存在 / 无权限） |
| `stat /Public tailscale.txt` | ✅ `exist=true`、`privilege=670` |
| `get /Public tailscale.txt` | ✅ 172 字节，内容正确 |
| `get_list /Download`、`/Web`、`/homes`、`/test1` | ❌ `status:4/5` |
| **`put` → `/Public`** | ❌ **`status:20`（被拒绝：非 Qsync 同步文件夹没有写权限）**，远端未产生任何文件 |
| `qbox_get_syncing_folder_list` | ✅ 端点可用，但 `{"total":0,"folder":[]}` —— 该账号没在 Qsync 里配对任何文件夹 |

结论：

* **读**：账号有读权限的共享文件夹，用普通 `sid` 就能列 / stat / 下载，**不需要 AES**；
* **写**：只有被登记为 Qsync 同步文件夹的目录才写得进去（我们这台账号是空的 → 共享文件夹全部只读）；
* 顶层共享列表不能靠 `get_list /` 枚举（普通用户拿不到 `share_root`）→ 所以 **M6 让用户显式配置 `roots`**，
  同时把 NAS 侧登记的同步文件夹作为**提示信息**展示出来（`qsync roots`）。

## 2. 配置：`roots`

```json
// ~/.config/qsync/links/default.json
{
  "id": "default", "host": "nas.local", "port": 9834, "https": true, "insecure": true,
  "user": "test1", "home_root": "/home",
  "roots": ["/home", "/Public"]        // ★ M6；空/缺省 = 只用 home_root
}
```

* `LinkConfig::roots()` 负责归一化：去空白、补前导 `/`、去尾 `/`、去重；空输入退回家目录。
* 兼容：老配置没有 `roots` 字段照样能读（`#[serde(default)]`），行为与 M5 之前完全一致。

## 3. 挂载布局：单根直通 / 多根虚拟根

`crates/qxync-core/src/roots.rs`（纯函数 + 单测）：

```text
单根（Passthrough，M1–M5 行为）:
    mount ~/mnt --remote /home          ~/mnt/qxync-test/hello.txt → /home/qxync-test/hello.txt

多根（Multi，M6）:
    mount ~/mnt --remote /home --remote /Public
    ~/mnt/home/qxync-test/hello.txt     → /home/qxync-test/hello.txt
    ~/mnt/Public/tailscale.txt          → /Public/tailscale.txt
```

* **视图名**取根的 basename（`/home`→`home`、`/Public`→`Public`）；同名时用「父目录_名字」消歧
  （`/a/b` 与 `/c/b` → `b` / `c_b`），保证顶层目录名唯一。
* **只有挂载点这一层多了一次名字映射**：节点表、缓存文件名、baseline、pin、xattr、上传队列
  仍然全部以**远端路径**为键（M2a 的教训：不能用 ino 当键）。
* 单根仍然是直通（挂载点就是那个根）——这是硬要求，否则 M1–M5 的 68 项 FUSE 矩阵全废。

## 4. 只读规则与 FUSE 保护

| 根 | 可写 | 依据 |
|---|---|---|
| 家目录（`home_root`） | ✅（挂载带 `--rw` 时） | 主目录上下传只需 `sid`，M2b 已验收 |
| 其它根（共享文件夹） | ❌ 默认只读 | 实测 `put` 被服务端拒绝 `status:20`；该账号 `syncing_folder_list` 为空 |

FUSE 层（`crates/qxync-fuse/src/lib.rs`）：

* `QxyncFs::new()` 保持直通；新增 `QxyncFs::new_multi(client, Vec<RootSpec>, cache_dir)`。
  多根时根节点是**虚拟根**（`remote = ""`），每个根预插一个合成目录节点（`view_name` → `remote`）。
* `lookup_child` / `load_children` 在 `multi_root && ROOT` 时**只查节点表、不访问 NAS**
  （否则会拿空路径去 `stat`）。
* `ensure_writable(remote)`：非多根 → 放行（挂载级 `read_only` 已管）；多根时按「属于哪个根」
  判定，非家目录根 / 不属于任何根的路径（虚拟根下新建）→ `EROFS`。
  调用点：`create`、`mkdir`、`remove_entry`（提前到删除熔断之前，避免被 EROFS 挡下还吃掉熔断额度）、
  `rename`（新旧两端）、`write`、`setattr`（size/mtime）、`open`（带写意图）。
* 虚拟根自身不可增删：`rmdir ~/mnt/home`、`mkdir ~/mnt/NewDir` 一律 `EROFS`（它们是挂载视图本身）。
* `FsHandle` / `LocalView` 增加 `remote_roots()`（带默认实现，向后兼容旧实现者）。

## 5. 同步引擎与脱水

* **同步**：`build_views()` 把一个**多根挂载展开成多个「单根视图」**（同一个 handle / 挂载点，
  不同的 `remote_root`）→ M2c 的对账逻辑一行没改，天然覆盖每个根。
  事件路径映射 `map_event_path` 仍只认 `/home` 与 `/share/homes/<user>`，所以共享文件夹的变更
  **走对账主路径**（这正是 M2c 的设计：事件是快路径、对账是主路径）。
* **脱水**：候选按根展开（`layout()` 再算一遍得到 `view_name`），并按根过滤候选，
  避免同一个文件被每个根算一遍；mmap 保护 `mmap_remotes()` 增加 `view_prefix` 参数
  （多根时挂载点里多一层目录名），映射错了会让 mmap 判定失守 → 违反脱水铁则。

```bash

xtask/tests/m6-matrix.sh --no-nas     # 只跑单测
qsync roots [--json]                  # 远端根一览

```

矩阵覆盖（29 项，全绿）：

1. **真机事实**：`/Public` 能列出（7 项）、能下载（172 字节）、**上传被拒**（负向对照）、
   不存在的根被拒；
2. **roots 配置与判定**：写一份 `roots:["/home","/Public"]` 的 link → 起 daemon → `qsync roots --json`
   断言 `configured`/`home_root`/`/home` 可写可读 / `/Public` 只读可读 / 视图名 `Public` / `note` 有内容；
   人读输出里能看到两个根；
3. **单测**：`qxync-core --lib roots` 7 项、`qxync-fuse` 23 项（含 4 项多根映射/只读/单根回归）、
   `qxync-client` 15 项（含 `syncing_folders` 解析）；
4. **FUSE 多根真挂载**（8 项，实测通过）：`mount ~/mnt --remote /home --remote /Public` →
   顶层出现 `home` 与 `Public` 两个目录；`Public/tailscale.txt` 按需水合 172 字节（内容正确）；
   `home/qxync-test/hello.txt` 按需水合；**向共享根写被 `EROFS` 挡住**（内核报「只读文件系统」）；
   向家目录根写成功（走 M2b 上传队列）；共享根上的文件可 `dehydrate --path`；卸载干净。

## 7. 已知限制

* **可写性只能按「是不是家目录」判断**：`SyncingFolderInfo.permission` 的位含义还没有还原，
  所以即使某个共享文件夹在 NAS 上被登记为可写，我们也一律按只读处理（保守但不丢数据）。
  将来解出权限位后，把 `layout()` 的 `writable_root` 换成「按根判定」即可。
* **共享文件夹的变更事件不参与快路径**：`map_event_path` 只映射 `/home` 与
  `/share/homes/<user>`，共享根的事件会被跳过（`events_skipped` 计数），靠对账兜底。
* `qsync roots` 的「可读性探测」用的是完整 `list()`（根目录通常很小）；大目录会很慢，
  后续可以换成 `get_list&limit=1`。
* 多根布局下 `--direct mount`（不经过 daemon）不支持多根，会明确报错要求用 daemon。

## 8. 踩到的坑

1. **顶层共享列表不能枚举**：`get_list /` 对普通用户是 `status:5`，`/Web`、`/homes` 也一样 →
   根必须由用户配置，不能自动发现（NAS 的 `syncing_folder_list` 只报它在 Qsync 里配对过的目录）。
2. **「端点存在」不等于「能用」**：`qbox_get_syncing_folder_list` 返回 200 但 `total:0` ——
   这在正常不过，别把它当错误（空列表 = 没配对，不是失败）。
3. **共享文件夹「能读不能写」**：读走 `sid` 就行，写必须是 Qsync 同步文件夹；错误码是含糊的
   `status:20`，所以我们在客户端就把非家目录根标成只读，写操作回 `EROFS` —— 让用户看到
   「只读文件系统」比看到「服务端 status 20」有用得多。
4. **多根不能破坏单根**：所有新逻辑都以 `multi_root` 为开关，单根走的还是 `new()` 那条路；
   `roots.rs` 里专门有一条「单根必须还是 Passthrough」的断言守着这条线。
5. **脱水候选与 mmap 映射要按根来**：否则同一个文件被多个根各算一遍（`freed_bytes` 翻倍），
   而 mmap 映射错了会让安全检查失守 —— 这两处都按 `view_prefix` 显式处理。

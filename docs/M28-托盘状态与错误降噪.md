# M28 — 托盘状态点与错误降噪

> 状态：已实现（2026-10-21）
> 关联：M8.4（托盘本体）、M20（离线缓冲区/连通性）、NetGuard（断网先探活再报错）

## 1. 要解决的问题（用户原话）

> 现在如果突然断网，或者网络波动，会报错……这种报错就不要提示了。
> 普通错误尽量就少点。连接状态能不能反馈在 tray 的图标上：
> 网络正常来个绿色，网络不正常红色，有问题黄色？同步有冲突可以弹个窗。

上一轮 NetGuard 已把「一次断网 = 一屏错误」收敛成一条；这一轮把剩下的「一条」
也从弹窗/错误列表里拿走，改由**托盘颜色**表达 —— 同一件事只说一遍。

## 2. 错误降噪：网络错误降级为 warn

| 层 | 改动 |
|---|---|
| `SyncReport` | 新增 `error_is_network: Vec<bool>`，与 `errors` **逐条对齐**（`push_error` 统一落点，含 20 条截断同步） |
| daemon journal | 网络类错误写 `kind="network", status="warn"`；普通错误照旧 `error` |
| `journal_list` | level 过滤补 `warn` 档；`journal_counts` 天然含 warn（GROUP BY status） |
| GUI 错误列表 | `level=error` 查询天然不含网络错误；journal 页新增「警告（网络）」筛选项 |
| GUI 桌面通知 | `checkErrorsForNotify` 跳过 `isNetworkErrorEntry`（老 daemon 文案兜底：「网络不可用」/「网络错误」开头） |
| GUI 首页/任务卡 | 离线横幅显示时不再叠 `last_error` 红条/卡片 ⚠️；离线时任务卡显示「网络断开 —— 本地改动先攒着」 |

**判据只有记错误那一刻知道**（`CoreError::is_offline`），所以走结构化标记而不是
事后从文本猜 —— 消息措辞会变，`is_offline` 不会。

## 3. 托盘三色状态点

图标 = 原 32x32 + 右下角状态点（绿/红/黄，带描边），三个变体编译期
`include_bytes!`，品牌形状不动。

| 颜色 | 判据（聚合所有「daemon 在跑」的连接，红 > 黄 > 绿） |
|---|---|
| 🔴 红 | `connectivity.known && !online`（探活确认网络断） |
| 🟡 黄 | 网络通着但有 `last_error`（非网络）或 `delete_block_reason` |
| 🟢 绿 | 全部正常 |
| 原图（无点） | 没有任何 daemon 在跑 —— 用户自己没配任务不是故障 |

链路：前端 `updateTrayStatus()`（2s 轮询后聚合）→ IPC `tray_set_status` →
`tray::set_status`（**仅状态变化时**动 SNI 图标，不刷 D-Bus）→ tooltip 同步更新。

老 daemon 缺 `connectivity` 按「正常」处理（缺字段 ≠ 离线，与 M20 同一原则）。

## 4. 冲突弹窗

`checkConflictsForNotify`（与错误检查同一个 6s tick，去重键独立）：
发现新的 `kind=conflict` 且 detail 以「双方都改」开头的条目 → 桌面通知
「qxync 发现同步冲突（连接X）—— 打开主窗口处理」。队列自动清理不算新冲突，不弹。
尊重「桌面通知」设置；Linux 通知点击行为不可靠，不做点击跳转。

## 6. 取舍记录

- **网络错误从错误列表完全消失**（降 warn，journal 全量页可查）——「不要提示」
  理解为弹窗和错误列表都不要；诊断信息仍在 `status.connectivity.last_error`。
- **黄色不含「有待裁决冲突」** —— 冲突靠弹窗提醒；图标判据只用 status 已有字段。
- **daemon 没跑 = 原图标** —— 不亮黄，那是用户自己的选择。
- **Rust 侧只在状态变化时动图标** —— SNI 换图标是 D-Bus 往返，2s 轮询无脑重设
  会刷总线。

# M41 · 日志降噪（同样的诊断信息，体积砍掉约九成）

> 状态：**已发布（v0.7.14，2026-10-28）**；§4 的数字为真机日志只读重放实测
> 前置：[M39 日志轮转与保留](M39-日志轮转与保留.md)（管住了「日志文件多大、留几天」，
> 没管「写进去的内容有多吵」）

## 0. 结论先行

M39 之后日志文件不会再长成 5 GB，但**每天写进去的内容**仍然大头是重复刷屏：

| 日期 | 日志文件 | 其中最大的重复类 |
|---|---:|---|
| 10-25 | **11.19 MB / 5.66 万行** | `创建缓存文件失败 … Too many open files` **48 983 行 / 10.33 MB**（每条一个路径；fd 泄漏是另一个问题） |
| 10-26 | **4.46 MB / 1.90 万行** | 逐目录 `对账列举失败` 3 677 行 / 862 KB、断网时 `上传因网络不可用暂停` 941 行 / 358 KB、逐文件 `已上传` 1 022 行 / 163 KB |
| 10-27 | **0.70 MB / 0.24 万行** | 逐目录 `对账列举失败` 1 260 行 / 295 KB、`轮询有异常` 33 条 × 1.8 KB（把已经打过的 errors 数组整串再抄一遍） |

一句话：**信息量是一句话，体积是几 MB。** M41 只在**源头**解决这件事，不动保留策略：

1. **同签名重复** → 首次 + 每窗口一条（带「另省略 N 条」后缀），逐条明细仍写 `debug!`；
2. **状态型日志**（轮询异常 / 会话失效 / 上传暂停 / 回放中断）→ 改成**状态迁移式**：
   只有「变坏」「变好」「变了」那一刻写一条，持续期间静默；
3. **每轮一行的空转 INFO**（`同步轮询: …`）→ 有实际动作才写 + 10 分钟心跳；
4. **抄数组 / 抄全量名字** → 改成「共 N 条；首条「截断」」，完整内容留给 `debug`。

效果（同一批真机日志按新规则离线重放，§4）：三天 **16.35 MB → 0.58 MB（-96.5%）**，
单日最好 -99%、最差 -87%；默认 `INFO` 级别下**运维真正需要的信息一条不少**
（首次、变化、恢复、计数都在），逐条明细在 `RUST_LOG=debug` 时一条不缺。

## 2. 为什么砍源头，而不是把日志级别调低

* **级别调低会把「第一次」也藏掉**：把 `已上传` 改成 debug 是省事，但以后排查
  「这个文件到底传上去没有」就少了一条线索；而这里压掉的是**第 2..N 次重复**。
* **保留策略不解决写入量**：`log_max_total_mb=256` 只是把「几天前的重复」删掉，
  当天的盘写入与 journal 事件量不变；M39 已经证明「只切段不减肥」仍然一天几 MB。
* **告警要按事件记，不按状态记**：断网 10 分钟不是「600 条 WARN」，是「进入离线」
  「恢复在线」两个事件；M2c 的删除熔断告警已经这么做了（`delete_block_changed`），
  M41 把这套口径推广到轮询异常 / 会话失效 / 上传暂停 / 回放中断。
* **诊断价值 = 签名 + 计数 + 首例**。`postgres` 风格的「重复 N 次」比 5 万份同一句
  更有用；完整逐条仍可在 `RUST_LOG=debug` 拿到。

## 3. 设计

### 3.1 `qxync_core::noise`（新模块，daemon / GUI / fuse 共用）

```rust
// 时间窗限流：同一 (site, signature) 每 window 最多放行一条
pub fn dedupe(site: &str, signature: &str) -> Admission;          // 窗口 60s
pub fn dedupe_in(site: &str, signature: &str, window: Duration) -> Admission;
pub fn every(site: &str, period: Duration) -> Admission;          // 心跳（首次立即放行）
pub fn reset(site: &str, signature: &str);                        // 故障恢复后让下一条立刻放行
pub fn truncate(s: &str, max_chars: usize) -> String;             // 按 char 边界截断
pub fn summarize_errors(errs: &[String], max_chars: usize) -> String; // 「共 N 条；首条「…」」
// Admission { emit: bool, suppressed: u64 }：本次是否输出 + 上个窗口被压掉的条数
```

语义（刻意简单，8 条单测钉住）：

| 情况 | 结果 |
|---|---|
| 该签名第一次 | 放行（`suppressed = 0`） |
| 窗口内再出现 | 压掉，内部计数 +1（调用方写 `debug!` 留全量） |
| 窗口到期后的第一次 | 放行，`suppressed = 上个窗口压掉的条数`（写进消息，如「过去一个窗口内另省略 128 条同类」） |
| `reset` 后 | 下一次立刻放行（「故障恢复后再次发生」不能被窗口吞掉） |

边界：

* **签名里绝不允许出现路径/数字/序号** —— 那样每条都是新键，等于没限流；
  路径与具体值只出现在**放行的那一条**里；
* 状态有界（最多 512 个签名，超了淘汰「窗口开始最早」的），极端刷屏不会吃内存；
* 全进程一把短锁，锁内只有 `HashMap` 操作、不碰 IO；**锁中毒照样继续**（日志路径不能停摆）；
* 窗口用单调时钟 `Instant`，系统时间跳变不影响；
* 进程内共享（daemon / GUI 各一份，本来就各写各的文件）。

### 3.3 状态迁移式（不用时间窗的四个点）

时间窗对「每轮一行」的日志基本无效：真机轮询间隔约 **45s**，而 60s 窗口几乎每轮都跨
窗口 —— 重放估算 60s 窗口只能把 941 行「上传暂停」压到约 749 行（-19%）。所以这几处
改成**门闩（latch）**，「日志记事件，不记状态」（项目里已有先例：M2c 的
`delete_block_changed` 只在熔断签名变化时 WARN）：

| 门闩 | 站点 | 语义 | 复位 / 重新武装 |
|---|---|---|---|
| `AnomalyLatch`（sync.rs:1518） | 轮询有异常 | 异常签名变化（或网络失败/熔断签名变化）→ 一条 WARN（摘要）；同签名持续 → `debug!` 全文 | **无异常的一轮自动清状态** → 复发立刻再报 |
| `AuthLatch`（sync.rs:1554） | 轮询遇会话失效 | 仅「正常→失效」迁移一条 WARN（摘要）；持续失效 `debug!` | 重登成功 / 恢复在线；凭据真坏时每轮仍会再报（有意不吞） |
| `ReplayInterruptLatch`（sync.rs:1594） | outbox 回放中断（会话/网络/未就绪） | 每次打断一条（首个受阻 kind+path+恢复方式）；同一原因持续重试 `debug!` | 回放清空/成功（daemon `replay_interrupt_reset`） |
| `OfflineLatch`（fuse upload.rs:89） | 上传因网络不可用暂停 | 一次断网一条 WARN（示例路径）；断网期间每次 `debug!` | 任一次上传成功（网络确实通了） |

「不吞复发」是这四个门闩共同的不变量：**恢复后状态清空，下一次故障一定会再报一条**；
被压掉的持续期明细全部写 `debug!`，`RUST_LOG=debug` 时一条不少。

### 3.4 明确不动的边界

* **用户可见的错误语义不变**：`SyncReport.errors` 仍是「本轮错误清单」（上限 20 条），
  IPC / GUI 错误列表 / journal 的内容与条数都不受影响；M41 只把**每轮 WARN 的样本**
  限到 3 条 + 1 条汇总，完整清单仍在 `errors` 里（GUI 照常显示）。
* **fd 泄漏（EMFILE 根因）没有修**：M41 只是让它在日志里不再刷屏；M39 的轮转/保留
  保证它刷不爆盘。根因仍单列待查。
* **不做**：全局日志级别调整、随机采样（会丢首次）、GUI 设置页/`qxync log` 输出改动、
  保留策略默认值改动（用户明确只要「源头降噪」）。
* **不做**：把 `debug` 级日志写进文件（默认 `INFO` 过滤在 subscriber 层，写路径看不到）；
  逐条明细在 `RUST_LOG=debug` 或 `--log-level debug` 时照旧写盘。

## 4. 体量重放（验收数字）

方法：把**真机历史日志**当作输入，按 §3 的新规则离线重算一遍输出（脚本
[`xtask/probe/m41_log_volume.py`](../xtask/probe/m41_log_volume.py)）。

```text
$ python3 xtask/probe/m41_log_volume.py \
    ~/.local/state/qxync/log/qxyncd.log.2026-10-25 \
    ~/.local/state/qxync/log/qxyncd.log.2026-10-26 \
    ~/.local/state/qxync/log/qxyncd.log.2026-10-27
```

### 5.2 体量重放

见 §4：同一批真机日志三天 **16.35 MB → 0.58 MB（-96%）**，单日 -87% ~ -99%。
脚本可重跑：

```bash
python3 xtask/probe/m41_log_volume.py            # 默认重放 ~/.local/state/qxync/log/qxyncd.log.*
```

### 5.3 没验的 / 如实记

* **真机新二进制没有跑**：降噪要在重装 / 重启 daemon 后才生效；本次验证是「真机历史
  日志重放 + 635 条测试 + 隔离 e2e」，不是「新二进制在真机跑一整天」。
* **GUI 真窗口 / `gui-matrix.sh` 未重跑**：改动不涉及 IPC 形状（`SyncReport.errors` 只
  多一条同形状摘要），既有单测覆盖 errors 语义；整套 GUI 矩阵会起停多个 daemon，本版
  没重跑。
* **`RUST_LOG=debug` 的逐条量未单独测**：估算只算默认 `INFO` 落盘；debug 时等于回到
  旧量级（这是设计：明细不丢，只是默认不写盘）。
* **fd 泄漏根因仍未定位**（M39 起就单列待查）：M41 只保证它不再刷屏；重放里
  「创建缓存文件失败」从 56 001 行/10.9 MB 降到 7 行/1.6 KB，但 fd 泄漏本身依旧存在。
  另外 `accept 失败`（M39 那次 5.17 GB 洪水的来源）也按 **errno 60s 限流**：
  即使 fd 再耗尽，最坏 1 条/分钟（≈ 1.5 MB/天），不再可能复现「一天 5 GB」。

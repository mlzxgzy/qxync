## 一句话

从这个版本起，Debian 与 Ubuntu 用户只需要**一个** `qxync_<版本>-1_amd64.deb`：Debian 12 /
13、Ubuntu 22.04 / 24.04 / 26.04 都能装、都能跑（发布前在五个干净容器里逐个实装验证）。
README 也重写成给用户看的安装与使用说明，协议级踩坑笔记搬到 [`docs/协议要点.md`](协议要点.md)。

## 一、Debian / Ubuntu：两个包合成一个

### 1.1 之前的问题：用户得按发行版挑包

0.6.4 及以前，Release 里有两个包：

```text
qxync_<版本>-1~deb12_amd64.deb        # Debian 12
qxync_<版本>-1~ubuntu22.04_amd64.deb  # Ubuntu 22.04
```

它们其实是**同一份东西**。把两个包都解开、逐文件比对：

```bash
dpkg-deb -x qxync_0.6.4-1~deb12_amd64.deb old-deb12
dpkg-deb -x qxync_0.6.4-1~ubuntu22.04_amd64.deb old-ubuntu
diff -rq old-deb12 old-ubuntu
# Files .../usr/share/doc/qxync/changelog.Debian.gz differ   ← 唯一差异
```

* payload 共 16 个文件，除 `changelog.Debian.gz`（里面是版本串 / 发行版代号 / 构建时间）
  外 **15 个逐字节相同**；
* 三个二进制的 sha256 在两个包里完全一样，也与 Release 的 tar.gz 里一致；
* 两个包的 `Depends` 字符串**逐字相同**，`Installed-Size` 也一样（191907 KiB）。

原因是 `dpkg-shlibdeps` 在 Debian 12 与 Ubuntu 22.04 两个基线里算出的版本下限恰好一致 ——
维护两个几乎相同的包没有意义。

### 1.2 现在：一个包，一条安装命令

| 下载这个 | 适用发行版 |
|---|---|
| `qxync_<版本>-1_amd64.deb` | Debian 12 / 13、Ubuntu 22.04 / 24.04 / 26.04 |

```bash
sudo apt install ./qxync_<版本>-1_amd64.deb
systemctl --user enable --now qxyncd      # 装完直接启用常驻同步
```

包里的东西与 Release 产物同源：**同一份 tar.gz 的三个二进制** + 桌面项 + 4 张图标 +
两个 systemd user 单元 + 文档，在 `ubuntu:22.04` 容器里重打包（**不重新编译**）。
`Depends` 是 `dpkg-shlibdeps` 对三个二进制实测后得到的 10 项，加上手工补的 `fuse3`
（挂载要调 `fusermount3`，而二进制并不链接 `libfuse`，自动工具看不出来），共 11 项，
全部是 Debian / Ubuntu 官方仓库里的标准包：

```text
libc6 (>= 2.34), libcairo2, libdbus-1-3, libgcc-s1, libgdk-pixbuf-2.0-0,
libglib2.0-0, libgtk-3-0, libjavascriptcoregtk-4.1-0, libsoup-3.0-0,
libwebkit2gtk-4.1-0, fuse3
```

`apt install ./<文件>.deb` 会从你配置的 apt 源自动装齐依赖；习惯 `dpkg -i` 的话，装完补一句
`sudo apt-get -f install`。国内清华、阿里等镜像源都有这些包 —— 我们的打包与 CI 实装验证
本身就是用清华源跑的。

### 1.3 从旧包升级

以前装过 `~deb12` / `~ubuntu22.04` 的，直接装新包即可，**不需要先卸载**：按 dpkg 版本序
`<版本>-1` 大于 `<旧版本>-1~deb12`（`~` 排在空串之前），apt 会正常替换并升级。想先确认：

```bash
dpkg --compare-versions <版本>-1 gt <旧版本>-1~deb12 && echo newer
```

## 三、发版流水线

* Release 资产 **6 → 7 个**：多了 `qxync_<版本>-1_amd64.deb`，并且它进 `SHA256SUMS`。
* 顺序：构建三个二进制 → 打 tar.gz / 裸二进制 → 打 Arch 包并校验内容 → **打 `.deb`** →
  **五个发行版干净容器实装校验** → `SHA256SUMS` → 发布。任一断言失败就中断，不发半成品。
* 打包与实装都在容器里跑 `xtask/release/apt-mirror.sh`，把 apt 源换成国内镜像（默认清华，
  可用 `QXNYC_APT_MIRROR` 换；CI 里是 `release.yml` 顶部的 `APT_MIRROR`），
  否则容器里 `apt-get update` 常常慢到超时。

## 五、已知边界（如实写）

* **只出 amd64**。要 aarch64 需要另外的 CI 平台与二进制代际，不在本版范围。
* **不进 Debian / Ubuntu 官方仓库，也没有自己的 APT 源 / 签名**：从 Release 下载 `.deb`
  后 `apt install ./<文件>`。包本身是标准的，但官方收录要走它们的流程。
* **更老的发行版装不了**：二进制要求 **glibc ≥ 2.34**，所以 Debian 11 / Ubuntu 20.04
  这类 glibc 2.31 的系统跑不起来（与 tar.gz 产物一致）。
* **单包成立的前提**是新发行版继续为旧包名提供 `Provides`（例如 `libgtk-3-0t64`
  `Provides: libgtk-3-0`）。哪天真出现依赖分叉或某个发行版不再提供旧名，
  就按 [`packaging/debian/README.md`](../packaging/debian/README.md) 里的判据拆回两个包 ——
  那里写清了「什么情况下才拆」。
* **装完约 190 MB**：与 tar.gz / Arch 包一样**有意不 strip**（release profile 带
  `line-tables-only` 调试信息，用户报 bug 时回溯可读）。
* **重复构建的 `.deb` sha256 会变**：`changelog.Debian.gz` 里带构建时间。要可复现就设
  `SOURCE_DATE_EPOCH`（与合并前一样）。
* **AUR 包的校验和仍是占位值**：`qxync-bin` 的 `sha256sums` 要等 Release 发出来之后
  在 `packaging/arch/` 下 `updpkgsums` 再推 AUR，这是既有流程，本版没有变。

## 六、升级须知

* **0.6.4 → 0.6.5 二进制行为不变**：没有新的同步逻辑、没有数据格式 / 配置 / CLI 变更；
  升级只是为了拿新的安装包与文档（不升级也不影响使用）。
* **`.deb` 用户**：`sudo apt install ./qxync_0.6.5-1_amd64.deb`，旧 `~deb12` / `~ubuntu22.04`
  包会被按版本序正常替换；升级后重启 `qxyncd`（新二进制不会替换正在跑的旧进程）。
* **Arch 包 / tar.gz 用户**：换二进制后重启 daemon：`systemctl --user restart qxyncd`。
* **回退**：装回 0.6.4 的包或二进制即可；`sync.db` schema 没有变化，回退不需要迁移。

> 发布日期：2026-10-21
> 上一版：[v0.7.7](发布说明-v0.7.7.md)（修复 v0.7.6 daemon 启动即 panic）
>
> 这一版的两个改动都是用户原话直接落成的：
>
> 1. **「第一次同步应该全部同步一遍吧，同步后有缓存就恢复原来的同步频率，太久没同步也按没同步过来算」**
> 2. **「咋还在报网络错误；本地路径和远程路径都不要显示了，就显示哪一路同步时网络失败，然后放到缓冲区去等在线」**

## 一句话

```text
升级后第一次启动：
  → 一轮列完整棵树（你这台 5000 个目录约 8~9 分钟）
  → 期间 status / GUI 显示「全量同步：进行中（首次）」
  → 完成后自动恢复你设置的常规轮询间隔
之后：
  → 只有「断网/休眠超过 1 小时」或「上次没列完」，才会再全量一次
  → 平时仍是常规轮转
```

## 一、首次同步 / 太久没同步 → 一轮全量列举

### 为什么必须改

这个 NAS 账号上，**变更发现的主路径不是增量事件，而是「列目录 + baseline 差集」**：

- `qbox_get_sync_log` 在真机上恒返回 `-17`（区间内没有事件）；
- 删除事件的 `filepath` 实测为空 —— 删除只能靠对账发现。

旧实现把**第一次同步**也塞进常规轮转窗口：5000 个目录 × 每轮约 171 个 ≈ **29 轮**
（600s 间隔下约 24 分钟），而且每一轮里没轮到的条目都显示「本轮暂不判定」——
用户看到的是「永远同步不完」，远端删除也要等一整圈才被发现。

### 现在怎么跑

按挂载点记状态，三种情况走**一轮全量**（BFS，每个目录只列一次）：

| 情况 | 判据 | 行为 |
|---|---|---|
| **首次同步** | 没有 `reconcile_full_done:<挂载点>` 完成标记 | 一轮列完整棵树；不受轮转游标、常规单轮预算、2000 目录硬顶截断 |
| **太久没同步** | 距上次**完整跑完**一轮 ≥ 1 小时 | 按首次同步处理（断网/休眠期间不会把「上次成功」拨到现在） |
| **上次没列完** | 崩溃 / 断网 / 预算用完留下 pending 标记 | 下轮继续全量；预算用完时 **2 秒**后就继续，不等常规间隔 |

- 完成标记在**删除判定之前**落盘：删除熔断挡住时，不会每轮重扫整棵树。
- 完成后自动**恢复常规轮转与你设置的轮询间隔**（不需要重装/重配）。
- 数据安全不变：列举失败的目录仍然**不判定**、不按缺失删本地。

### 状态可见

```text
qxync status / qxync sync：
  全量同步：进行中（首次 / 太久没同步）
  上次成功同步 N 前
GUI 同步摘要与诊断页同样显示。
```

### 可调开关

| 环境变量 | 默认 | 含义 |
|---|---|---|
| `QXNYC_FULL_SCAN_BUDGET_SECS` | `1800` | 一次全量的时间预算，`0` = 不限 |
| `QXNYC_FULL_SYNC_AFTER_SECS` | `3600` | 「太久没同步」阈值，`0` = 不因超时触发 |
| `QXNYC_FULL_SYNC` | `1` | `0` = 退回旧行为（排障对比用） |

### 真机实测（只读，未改动任何远端数据）

```text
90 秒预算：列目录 982（新发现 1716）、baseline 6358、0 错误
→ 约 10.9 目录/秒（92ms/目录）
→ 该账号 5362 个目录整棵树一轮约 8~9 分钟
```

## 二、网络失败：闪断由重试吸收，真断网按「已缓冲，等联网」

真机那一次不是「网络断了」，而是**一条请求被对端丢了**（keep-alive 竞态：NAS 回收空闲连接，
客户端复用了那条刚被关掉的连接）。旧实现把一次闪断记成「同步失败」，并且
`reqwest` 的错误文本自带完整 URL（含 `sid=` 与 URL-encoded 远端路径），叠加对账层自己拼的
路径，一条消息里出现两遍远端路径。

| 情形 | 现在的行为 |
|---|---|
| 一次闪断（对端提前关连接 / 反代 502/503/504） | 幂等 GET **最多 3 次尝试**（200ms → 600ms 退避）吸收，**用户看不到任何东西** |
| 真断网 / 重试用尽 | 只留一条「**已缓冲，等联网**」说明；未列到的目录下轮自动重试，不判定、不删本地 |
| 「最近错误」红字 | 只留给**非网络**错误（业务 status / 会话 / 本地 IO） |
| 更新中心 journal | 同一次断网只记**一条** warn，恢复时补一条「网络已恢复：同步继续」 |
| 文案 | 不含本地路径、远端路径、URL、sid；只说「哪一路同步 + 第几个目录」 |

重试**只**针对「对端提前关连接 / 协议中断 / 502/503/504」；连接超时、连接拒绝、DNS 失败
不重试 —— 那些是离线判据，重试只会把 20s 的 connect timeout 拖成 60s。

真断网时的文案：

```text
说明（<nas>）：同步「qsync」对账列举失败（第 1/4987 个目录，已列 0 个）:
网络错误: get_list: 请求发送失败：Connection reset by peer (os error 104)；
已缓冲本轮进度，网络恢复后自动继续
```

## 四、升级须知

1. 下载本版 Release 资产（tar.gz / Arch 包 / `.deb`），或源码 `cargo build --release`；
   **`qxyncd` 换了，必须重启 daemon**：
   ```bash
   qxync daemon stop
   qxync daemon start
   ```
2. **升级后第一次启动会跑一次全量列举**（你这台约 8~9 分钟），期间 `status` / GUI 会显示
   「全量同步：进行中（首次）」。这是预期行为，不是卡住。
3. **全量同步只建缓存**（完整目录清单 + baseline），**不下载文件内容** ——
   `space_saving` / `pagecache` 模式下文件内容仍按需水合，不会占满磁盘。
4. 「太久没同步」也会触发一次全量：例如笔记本离线超过 1 小时后重新上线，
   第一轮会多花一次全量时间。

## 五、已知边界（如实记）

- 本版**没有改变**稳态对账的轮转窗口（15s 时间预算 / 每轮 2000 目录硬顶）——
  5000 目录在常规轮转下约 24 分钟覆盖一遍。若希望「有缓存后每轮也全量」，
  需要把轮询间隔提到 ≥ 全量耗时，那是另一个取舍，留待后续。
- 全量与网络降噪的验证是**单测 + 真机只读冒烟**；升级后 daemon 重启的首轮全量，
  由用户在本机执行（本环境不在用户真机上重启 daemon）。
- GUI 部分只有 crate 单测与编译验证，没有真实桌面环境下的活体验证。
- `cargo clippy` 在发版本环境未安装，未运行（CI 的 `cargo test` / `fmt` / 版本守卫都过）。

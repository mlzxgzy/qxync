# M18 任务默认路径：id / 本地文件夹 / 水合缓存按「连接 + id」派生

> 起因：用户反馈「**现在不同任务的任务 id 和默认文件夹地址、还有水合目录都默认一样，
> 是不是可以根据用户和 id 来定制路径，否则不友好**」。
>
> 结论：新建任务的三个默认值全部改成**按「连接 + NAS 文件夹」派生**，天然唯一；
> 已经保存的任务路径**一个都不动**。任务文件格式没有新增任何字段，回退旧版本不受影响。

---

## 1. 旧默认值为什么会撞车

旧版「＋ 添加配对文件夹」表单的初值固定是这三样：

| 字段 | 旧默认值 | 后果 |
|---|---|---|
| 任务 id | `default` | 任务登记是 `tasks/<id>.json`，**id 是全局唯一文件名**。第二条任务不改 id：同连接 = **静默覆盖**第一条；跨连接 = 后端报「任务 id「default」已经属于连接「X」」 |
| 本地文件夹（挂载点） | `~/qxync-mnt` | 同一个本地路径只能给一条任务（`destination_conflicts_with` 拦重复与嵌套），第二条任务一提交就被拒 |
| 水合缓存目录 | 空 = 按连接共享 | 不是错误（缓存键含完整远端路径，不会串），但界面上「看着都一样」，也无法按任务单独清理 |

所以「建第二条任务」的真实操作是：**手改三处**。这就是「不友好」的来源。

（顺带修掉一个真实风险：旧版同连接下 id 撞车时 `tasks save` 会**静默覆盖**，
而挂载表里可能还挂着旧任务的根 —— 记录与挂载对不上，且界面上看不出来。
现在新建任务提交前会先做 id 查重，不再静默覆盖。）

## 2. 新规则

| 字段 | 新默认值 | 例子（连接 `default`、NAS 选 `/home`） |
|---|---|---|
| 任务 id | NAS 文件夹**最后一段**，压成 `[a-z0-9._-]`；与已有任务重名时加 `-2` / `-3` | `home`；再给 `/home` 建第二条 → `home-2` |
| 本地文件夹 | `<HOME>/qxync/<连接 id>/<任务 id>` | `/home/tester/qxync/default/home` |
| 水合缓存目录 | `<data_dir>/cache/tasks/<连接 id>/<任务 id>`（**父目录**） | `/home/tester/.local/share/qxync/cache/tasks/default/home` |

补充：

* **连接 id** 是 `links/<id>.json` 的 id，就是 GUI 里徽标 `id · user@host:port` 的前半段
  （`default` / `nas2`…）。多 NAS 时路径一眼能看出是谁的哪条任务。
* 缓存的真实落盘还会**再拼一层「连接命名空间」**（`config::link_namespace`：
  `default` → NAS 主机名；其它 → `#<id>@<主机名>`）——这是 M16 定的隔离规则，
  「显式 `cache_dir` 是父目录」的既有语义没有改。所以上面例子实际缓存文件在
  `…/cache/tasks/default/home/<NAS 主机名>/` 下。
* id 的字符集与后端 `Task::is_valid_id` 完全一致：`A-Za-z0-9 . _ -`，1~64 字符，
  不能是 `.` / `..`。中文等非 ASCII 目录名会被压成 `task`（可手改）。

## 3. 表单行为

1. 表单顺序调整为 **NAS 连接 → NAS 文件夹 → 任务 id → 本地文件夹 → 水合缓存**：
   先选 NAS 文件夹，因为 id 和两条路径都由它派生。
2. 换 NAS 文件夹 → 自动改 id（取文件夹名，重名加后缀）→ 两条路径跟着 id 走。
3. 换 NAS 连接 → 路径里的连接段跟着变。
4. **用户手改过的字段不再被自动覆盖**：
   * 改 id → 两条路径继续跟着 id 走（它们仍是「自动」的）；
   * 改本地文件夹 / 缓存目录 → 之后换 NAS 文件夹也不动它；
   * 想恢复 → 点「重置为默认路径」（三处重新交回自动派生）。
5. 编辑**已有**任务时不做任何派生：显示磁盘上的原值。
6. 提交前校验（都是人话，不发请求）：
   * id 不能为空、必须是合法 id；
   * 新建任务不能用一个**已被别的任务占用**的 id；
   * 本地文件夹必须是绝对路径。
   后端原有的「本地文件夹重复 / 嵌套」「NAS 文件夹重复（只提示）」「跨连接 id 覆盖」
   检查一条没删，继续兜底。

## 4. 为什么这样取舍

* **id 从 NAS 文件夹名派生，而不是用序号**：可读、可猜（`home` / `public`），而且
  同一条任务换台机器重建时得到同一个 id。序号（`task-1`、`task-2`）唯一但毫无信息量。
* **路径带连接 id**：id 本身已经全局唯一，理论上 `~/qxync/<id>` 就够；但多 NAS 场景下
  `~/qxync/default/home` 和 `~/qxync/nas2/home` 比 `~/qxync/home`、`~/qxync/home-2`
  更能说明「这是哪个账号的」。代价是单连接用户的路径多一层 `default/`。
* **水合缓存按任务隔离**：能按任务单独清理 / 单独设限额（释放空间页按挂载点统计）；
  代价是两条任务同步**相互重叠**的远端目录时缓存各存一份 —— 缓存是可再生的，
  且这种重叠本来就会收到「NAS 文件夹重复」的警告。
* **不动已有任务、不迁移目录**：默认值只在「新建」时生效。改已保存任务的路径等于
  替用户搬（或重新水合）整个目录，风险远大于收益。老任务打开时显示原值，原样保存。
* **任务文件格式没变**：没有新增 JSON 字段，只有 GUI 的初值变了。所以新旧版本混跑
  （包括回退）都没有兼容问题。
* **CLI 没跟着改**：`qxync task add` 的 `--id` / `--mountpoint` 仍是显式参数（脚本可控、
  可复现）。GUI 的默认值是「少填三格」，CLI 的默认值应当是「别让脚本猜」——
  两者目标不同，有意不一致。

## 6. 未做 / 边界

* CLI `task add` 没套用同一套默认（见 §4）。
* 默认值**只影响新任务**；老任务（比如已有 `/home/tester/qxync-mnt`）不会自动搬到新规则下。
* 「唯一化」依据的是 GUI 当前已知的任务列表；如果磁盘上有 GUI 还没加载到的任务
  （例如某连接的 link 文件被删、其任务又没被任何 daemon 列出），提交时后端仍会拒，
  **不会静默覆盖**。
* 挂载点目录不存在时由 daemon `create_dir_all` 递归创建（既有行为，M18 没改）。
* 直接挂载（诊断 → 挂载，不走任务登记）的默认挂载点仍是 `~/qxync-mnt`——
  那里没有「任务 id」可言，保持原样。

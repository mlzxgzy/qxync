## 新增

### 1. 完整英文界面

以前的 `en` 文案表只覆盖两步验证相关的几条，其余界面整条回落到中文 ——「语言」下拉其实是个摆设。现在：

- `en` 表与 `zh-CN` 表**同键数（全量镜像）**；
- 界面上**全部用户可见文案**——页面/分区名、状态、空态/加载态/错误态、按钮、徽章、确认框、
  提示条、表格列头、`title` 提示、`placeholder` 与 `aria-label` 属性，甚至 `<code>` 里的示例
  token——都走 i18n 层；
- JS 动态拼的文案（状态、报错、确认框、日志面板里的操作日志、计数）也都进了文案表；
- 安全约定不变：仍然只用 `textContent` 写文本，GUI 里没有 `innerHTML`。

没有引入 i18n 框架，也没有新增依赖；文案表就是普通的 JS 对象。

### 2. 语言设置真正生效

**设置 → 个人 → 语言** 三选一：

| 选项 | 行为 |
|---|---|
| 跟随系统 | `zh*` → 简体中文，`en*` → English，其它回落简体中文 |
| English | 始终英文 |
| 简体中文（zh-CN） | 始终简体中文 |

偏好存在 daemon 的 `settings.language`（CLI 与 GUI 共用同一份；`qxync settings --set language=en` 也能改）。
GUI 启动时先按本机上次的偏好渲染第一帧（英文用户不会先闪一帧中文），settings 回来后以 daemon 为准；
两者不一致就整页刷新一次。`<html lang>` 跟着切换，读屏与拼写检查不会错。

上面还加了一道静态守卫：`ui_spec`（Rust 单测）会在「英文表没覆盖全部中文键 / 英文值里出现中文 /
HTML 或 JS 用到的键在任一张表里缺失 / 语言 wiring 断了」时直接失败 —— 英文界面不会偷偷退回
「只是摆设」。另有无头浏览器验收 `xtask/tests/gui-i18n.sh`：用真界面中英各渲染一次，
断言英文模式没有中文文本、没有全角标点。

### 3. Release 正文英文优先

发版流水线取 GitHub Release 正文的顺序改为：

```text
docs/发布说明-<tag>.en.md   ← 英文（首选）
docs/发布说明-<tag>.md      ← 中文（英文缺失时兜底）
GitHub 自动生成的 Notes      ← 两个文件都没有时
```

中文稿继续留在仓库里。规则见发版清单 §3.4。

## 已知边界

- **底层文案仍是中文**：GUI 的诊断日志、以及 daemon / CLI 的输出仍是中文。英文界面下，
  越接近底层的报错（daemon 错误、daemon 侧日志）越可能看到中文；这部分留待后续版本。
- 语言切换在「保存的设置与启动时渲染的语言不一致」时会整页刷新一次 —— 这是有意的
  （避免出现半中半英的中间态）。

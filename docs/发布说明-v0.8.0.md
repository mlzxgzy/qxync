# v0.8.0 —— 本地文件搜索（不挂载、不联网，0.1 秒搜 NAS 同步树）

> 发布日期：2026-10-28
> 上一版：[v0.7.14](发布说明-v0.7.14.md)（日志降噪）
>
> **功能版**：新增 `qxync find` 命令与 GUI「搜索同步文件」。两者都**只读**同步状态库
> （`baseline` + `nodes.local_only`），**不挂载、不联网、daemon 不在跑也能搜**。
> 数据格式 / IPC / daemon / FUSE **零改动**；升级只需换二进制，不需要迁移任何文件。
> 真实库（28 136 个文件 + 5 891 个目录）实测 `qxync find 防火墙` 约 **0.1 秒**。

## 一句话

```text
升级后：
  → qxync find 防火墙           子串搜（默认大小写不敏感），约 0.1 秒
  → qxync find '*.pdf' --glob   通配符；模式里没有 / 时只匹配文件名
  → qxync find --under <目录>   只搜某个子树（NAS 路径、挂载点路径都行）
  → qxync find … --local        直接输出挂载点里的本地路径，复制就能打开
  → qxync find … --json         脚本用（path / local_path / size / mtime / origin / task_id）
  → GUI 文件页 →「搜索同步文件」：关键词回车 → 定位 / 打开 / 复制路径
  → 全程不挂载、不联网、daemon 不在也能用；数据最多滞后一轮轮询（上传成功立即落盘）
```

## 一、起因：状态库里本来就有一份「目录数据库」

用户原话：

> 「有目录数据库的话是不是可以快速搜索仓库内的文件啊」

能。qxync 的同步状态库 `sync.db` 里有两张表天然就是目录清单：

| 表 | 内容 | 规模（本机真实库） |
|---|---|---|
| `baseline` | 上次同步成功时的**远端**路径 + 签名（`present` / `is_dir` / `size` / `mtime`） | **34 020 行 = 28 136 文件 + 5 891 目录** |
| `nodes.local_only` | 本地新建、**还没上传成功**的路径 | 3 条 |

它是同步逻辑自己的权威缓存：本地文件、大小、修改时间全在。所以**不需要挂载、
不需要联网、不需要 daemon 在跑** —— 只读打开就能当「目录数据库」用。

顺带说明为什么**没有**复用系统级目录库：`plocate` 的索引实测覆盖不到 `/home/kami`；
Baloo 在本机没装，而且 qxync 文档本来就要求把挂载点排除出 Baloo（内容索引 = 读内容 =
全量水合，天生冲突）；现扫挂载点则要挂载 + daemon，断网根本不可用。

## 二、`qxync find` 怎么用

```bash
qxync find 防火墙                      # 子串，默认大小写不敏感
qxync find '*.pdf' --glob              # 通配符
qxync find 报告 --case-sensitive       # 区分大小写
qxync find --under /home/.Qsync/2026/29-四川赛 --type f --sort mtime
qxync find --under /home/kami/qxync/default/qsync/2026/29-四川赛   # 本地路径也行
qxync find 试题 --min-size 10M --long
qxync find 防火墙 --limit 5 --local    # 只出前 5 条，打印挂载点本地路径
qxync find 防火墙 --limit 0 --json     # 全量 + JSON（脚本用）
```

| 选项 | 语义 |
|---|---|
| `--glob` | 通配符模式（`*`、`?`）；**模式里没有 `/` 时只匹配文件名**，有 `/` 时按整路径匹配且 `*` 可跨 `/` |
| `--case-sensitive` | 区分大小写（默认不区分，Unicode 大小写折叠） |
| `--under <路径>` | 限定子树；**NAS 远端路径或挂载点本地路径都行**（自动换算） |
| `--type f\|d` | 只要文件 / 只要目录 |
| `--min-size` / `--max-size` | 大小过滤，支持 `K` / `M` / `G`（如 `--min-size 10M`） |
| `--sort path\|size\|mtime` | 排序：路径 / 大小（大的在前）/ 修改时间（新的在前） |
| `--local` | 把命中换算成挂载点里的本地路径 |
| `--json` | 每行一个 JSON 对象：`path` / `local_path` / `size` / `mtime_text` / `origin` / `task_id` |
| `--limit N` | 最多 N 条；**`0` = 全量**；截断提示走 stderr，不污染管道 |
| `--link <名字>` | 多连接时选连接（默认 `default`） |

`find` 的别名是 `search`，两者等价。它是纯本地命令（和 `verify` 一样路由前短路），
传 `--via-daemon` 会被明确拒绝。

## 三、为什么这么快、为什么离线可用

* **数据源是本地 SQLite**：`Store::open_readonly` 只读打开，不建库、不写任何行；
  匹配用 `qxync_core::search` 的纯函数，装载走 `baseline` + `nodes.local_only`。
* **一个路径出现两次时以远端签名为准**（`present=1` 优先于 `local_only`），
  墓碑行（`present=0`，远端已删）不返回。
* **实测（本机真实库，34 020 行）**：`qxync find 防火墙 --limit 5` **97 ms**
  （含进程启动）/ **49 条命中**，第一条就是
  `/home/.Qsync/0.1+X/5.课件/1+X防火墙安全配置-外发.pdf`。
* **新鲜度**：最多滞后一轮轮询（默认 30 秒）；上传成功会立即把新签名落盘。
  所以「刚建、还没上传」的文件也能搜到（来源标为「本地新建」）。

## 四、GUI 也能搜

文件页顶部新增「搜索同步文件」卡片：

* **关键词**（回车即搜）/ **通配符** / **限定目录**（NAS 路径或挂载点路径都行）/
  **类型** / **排序** / **最多条数**（50 / 100 / 500 / 全部）；
* 结果表每行带**来源徽标**（已同步 / 本地新建）与三个动作：
  **定位**（在下面的「NAS 上的目录」里打开父目录）、**打开**（映射到挂载点本地路径，
  默认程序打开）、**复制路径**；
* 四态明确（未搜 / 加载中 / 空 / 错误）；截断时提示改成「全部」；
* 切连接自动清空结果并丢弃过期响应，不会显示上一个连接的命中；
* 匹配 / 过滤 / 排序**全部复用** `qxync_core::search`，与 CLI 同一套语义
  （前端不重算，避免两处各写一份后只在一边修对）；
* 同样只读状态库，**不挂载、不联网、daemon 不在也能搜**。

真窗口实测（`DISPLAY=:0`，真实 34 020 行状态库）：输入「防火墙」回车 →
**命中 49 条**，与 CLI 完全一致；映射出的本地路径 `exists_on_disk=true`。

## 五、能搜什么、不能搜什么

| 能 | 不能（本版明确不做） |
|---|---|
| 路径 / 文件名子串、通配符 | **文件内容**（状态库只存签名，不存内容；内容搜索要另建 FTS 索引） |
| 大小、类型（文件 / 目录）、修改时间排序 | 「文件是否已水合 / 离线可读」（`--cached`，读 `.qxstate` 位图，后续再做） |
| 远端子树（`--under`） | 跨连接 / 跨站点一次搜（一次搜一个连接的状态库） |
| 刚建但还没上传的本地文件 | 搜索期间 DAO 之外的写入（只读快照语义，最多滞后一轮） |

边界与实现细节见 [`M42-本地文件搜索.md`](M42-本地文件搜索.md)（§1 数据源、§6 为什么不复用
系统目录库、§8 GUI、§9 后续）。

## 七、升级

```bash
# 1) 换二进制（qxync / qxyncd / qxync-gui 一起换，保持版本一致）
sudo install -m755 target/release/qxync target/release/qxyncd target/release/qxync-gui /usr/bin/

# 2) GUI 需要重启才会出现「搜索同步文件」卡片
#    （qxync find 是独立命令，装完即可用；daemon 不需要重启也能搜）

# 3) （可选）重启 daemon —— 本版没有 daemon 行为变化，只为版本一致
systemctl --user restart qxyncd
```

升级须知：

* **不需要迁移任何文件**：无数据格式变更、无 IPC 变更、无配置变更；`sync.db` /
  缓存 / link 文件原样可用，老状态库（M5 / M36 起）直接能搜。
* **搜索是纯本地行为**：`qxync find` 与 GUI 搜索都不经过 daemon、不触发挂载。
* **旧版二进制没有 `find`**：`qxync --version` 仍是 0.7.x 的话，是 PATH 上的旧二进制。

## 已知限制（如实记）

* **内容搜索未做**：只能搜路径/文件名，搜不到文件内容（这是独立里程碑）。
* **没有「已水合」筛选**：断网时哪些文件真的能打开，目前搜不出来（`--cached` 后续）。
* **`--under` 未走 SQL 预筛**：3.4 万条规模没必要，等 20 万条以上再做。
* **`cargo clippy` 未运行**：发版环境未安装 `cargo-clippy`（与 v0.7.12~v0.7.14 相同）。
* **GUI 的「定位」未做真实 NAS 目录验收**：本机 daemon 未登录，只验证了它触发目录浏览
  导航（并如实写进操作日志），没有看到真实的 NAS 目录列表。
* **没有在 daemon 跑着 + 挂载中的现场做并发压测**：只做了只读冒烟与一条
  「写连接持有（WAL）时只读搜索可用」的集成测试。
* **不做**：跨连接统一搜索、边打字边搜（增量搜索）、给结果加预览。

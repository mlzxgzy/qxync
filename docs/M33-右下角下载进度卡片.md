# M33：右下角下载进度卡片

> 起因：用户反馈「下载大文件（大于 3 秒下载时间的文件），右下角并没有弹出下载进度
> 提示框」。排查结论：**M26 的进度链路本身是通的**（daemon 推进度行 → GUI Rust
> `emit` → 前端监听），但**展示挂点选错了**——进度写在文件页工具栏的「进行中…」
> 徽标（`#files-busy`）上：字号小、位置不显眼、切到别的页就看不见，真机上等于
> 「没有进度提示」。本里程碑把挂点改成**窗口右下角的浮动卡片**。

## 1. 现象与取证

| 检查 | 结果 |
|---|---|
| 进度链路（代码走查） | JS `ipcForWithProgress` → Rust `ipc_call_with_progress`（信封 `progress:true` 由 Rust 侧 `with_progress` 补上）→ daemon `get` 期间 10 Hz 推进度行 → `app.emit("progress://download")` → 前端 `tauri.event.listen` —— 每一环都有单测/既有验证 |
| `get` 超时 | long-running → 600s 总闸，**每条进度行重置计时**（有进度流动就不会被掐死） |
| 展示挂点（M26 原设计） | `makeDownloadProgress($('files-busy'))` —— 工具栏小徽标，`withBusy` 显示「进行中…」、进度行覆写其 `textContent` |
| 用户感知 | 「右下角没有弹出下载进度提示框」——徽标在文件页工具栏中部，既不在右下角、也不弹框 |

结论：功能在、位置错。M26 当时的取舍（「不弹窗挡操作」）方向没错，但徽标这个挂点
**可见性太差**：下载中用户切到别的页（任务/设置/诊断）就什么都看不到。

## 2. 方案：右下角浮动卡片（`#dl-toasts`）

```
┌────────────────────────────────────┐
│ big.bin                            │  ← 文件名（mono + 省略号，title 全名）
│ ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░ │  ← 进度条（accent；未知总量走 indeterminate 滑动）
│ ⬇ 61.2% · 2.4 MiB/4.0 MiB · 798 KiB/s · 剩余 2s │  ← 统计行
└────────────────────────────────────┘
```

设计要点（每条都对着 M26 的原始约束）：

| 约束 | 实现 |
|---|---|
| 不挡操作 | 容器 `pointer-events: none`，**只有卡片本身**恢复 `auto`（点击 = 立即关闭）；右下角这块区域照常点得到下面的页面 |
| 任何页面可见 | `position: fixed; right: 16px; bottom: 16px; z-index: 70`，页面怎么切都在 |
| 快下载零打扰 | 3 秒静默期**内不建卡片**（时序规则与 CLI `progress.rs` 一字不变）；快下载从头到尾无痕 |
| 多笔并发 | 每笔下载一张卡片，纵向堆叠（`column`） |
| 结束态 | 成功 → 进度条变绿 + 「✅ 下载完成 · N」，2.5s 后自动移除；失败 → 变红 + 错误摘要（完整错误在 `title`），6s 后移除；点击立即关 |
| 未知总量 | 服务端 chunked 无 `Content-Length` 时进度条挂 `indet` 类走滑动动画，统计行只报已下载/速度 |
| 旧页面降级 | 容器 `#dl-toasts` 不存在（旧 index.html）→ `buildDlCard` 返回 null，静默退回无进度（不炸） |

徽标 `#files-busy` 保留为通用「进行中…」指示（`withBusy` 原有行为），**不再覆写进度文本**
——进度只有卡片一个真相源，避免两处显示不同步。弹窗提示语同步改为
「超过 3 秒在右下角显示下载进度」。

`tauri.event.listen('progress://download')` 通道进前端——前端代码分不清桩和真后端。

## 5. 已知边界

- **daemon 挂起死亡（独立问题，未在本里程碑修）**：真机取证发现 12:49:38 系统挂起 →
  13:22:29 恢复后 daemon 无声死亡（socket 拒连、日志停在挂起前、无退出记录，挂载点
  13:23:12 被 systemd 记为 Deactivated）。GUI 只显示「未运行」、不会自动拉起。
  复现路径与修复方向（挂起/恢复看护）待单独排查——见 §6。
- 卡片只在「下载到本地」（`get`）路径出现；挂载点里 `cp` 触发的水合走 FUSE read，
  不经过这条 IPC 通道（那是 Dolphin 自己的复制进度条的范围）。
